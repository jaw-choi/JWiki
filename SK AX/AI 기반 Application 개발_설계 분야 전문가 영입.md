### [예상] 1. 낯선 환경에서 스스로 목표를 세우고 성과를 낸 경험
*(592자 / 제한 600자)*

미국 스타트업 A Round Entertainment에서 원격 소프트웨어 엔지니어 인턴으로 일하며 데이팅 앱 JOOPI 개발에 참여했습니다. 시차가 있는 해외 팀, 처음 실무로 다루는 React Native, 이미 App Store에 출시되어 실제 사용자가 쓰는 서비스라는 점이 모두 낯선 조건이었습니다. 저는 프로필 편집 기능을 맡아, 사용자가 사진을 올리고 순서를 바꾸면 그 결과가 앱 전체에 바로 반영되도록 만드는 것을 목표로 삼았습니다. 출시된 앱이라 작은 실수도 곧 사용자 불편으로 이어진다는 부담이 있었고, 실시간 데이터 구조를 이해하는 데 처음에는 시간이 걸렸습니다. 저는 Firebase 실시간 동기화 방식을 먼저 공부하고, 이미지 업로드와 순서 변경, 저장을 하나의 흐름으로 정리해 구현했습니다. 그 결과 프로필 편집, 이미지 업로드와 순서 변경, 실시간 동기화 기능을 완성해 서비스에 반영했고, 이 내용은 이력서와 포트폴리오에 정리되어 있습니다. 낯선 기술도 구조부터 이해하면 빠르게 실무에 쓸 수 있다는 자신감을 얻었습니다. React와 Python, LangChain 기반 사내 AI 서비스 개발에서도 이 방식으로 빠르게 기여하겠습니다.

> [확인 필요] 실시간 데이터 구조 이해에 시간이 걸렸다는 부분과 목표 설정 표현이 실제와 같은지 확인해 주세요.

### [예상] 2. 다른 사람의 의견이나 반대로 방향을 바꾸었거나 실패한 경험
*(545자 / 제한 600자)*

SeSAC 팀 프로젝트 AI 비서에서 에이전트와 음성 기능을 맡았습니다. 처음에는 19개 도구 선택을 모두 LLM에 맡기는 방향으로 진행했지만, 응답이 느리고 토큰 비용이 크다는 문제가 팀 안에서 제기됐습니다. 저는 LLM이 더 정확하다는 생각에 이 방향을 고집하고 싶었지만, 먼저 69개 평가 문장을 만들어 같은 기준으로 비교해 보기로 했습니다. 측정해 보니 규칙 기반은 78%, LLM 단독은 88%였고, 두 방식이 틀리는 문장의 유형이 서로 달랐습니다. 그래서 LLM 단독이라는 처음 계획을 내려놓고, 명확한 명령은 규칙으로 바로 처리하고 모호한 요청만 LLM으로 넘기는 하이브리드 라우팅으로 방향을 바꿨습니다. 이 과정에서 이미 만들어 둔 프롬프트 일부를 다시 설계해야 했지만, 최종적으로 정확도 91%를 달성하고 LLM 단독 대비 처리 시간과 토큰을 약 60% 줄였습니다. 의견이 갈릴 때는 주장보다 측정 기준을 먼저 세우는 것이 방향 전환을 빠르게 만든다는 것을 배웠습니다. AX ERP전략팀의 LangGraph 워크플로우 설계에서도 같은 원칙으로 판단하겠습니다.

> [확인 필요] 팀 안에서 속도와 비용 문제가 제기된 과정, 처음 계획을 고집하고 싶었다는 감정, 프롬프트 일부를 다시 설계한 부분이 실제와 같은지 확인해 주세요.

### [예상] 3. AI 도구를 활용해 업무나 과제의 효율을 높인 경험
*(543자 / 제한 600자)*

AI 도구를 단순 검색이 아니라 작업 절차의 일부로 쓰려고 노력합니다. 넥슨 계열 채용의 AI 코딩 테스트를 준비할 때 Claude와 ChatGPT를 함께 사용했습니다. 먼저 문제 유형을 정리하게 하고, 제가 직접 작성한 풀이를 두 도구에 각각 검토받아 서로 다른 지적이 나온 부분만 다시 확인했습니다. AI가 제시한 코드는 그대로 쓰지 않고 테스트 입력을 직접 만들어 돌려 본 뒤에만 채택했고, 틀린 제안은 왜 틀렸는지 메모로 남겼습니다. 이 방식으로 혼자 풀 때보다 오답 원인을 훨씬 빨리 찾을 수 있었고, 준비 과정은 개인 위키에 문서로 정리해 두었습니다. 팀 프로젝트 AI 비서에서도 LLM을 무조건 믿지 않고 평가 문장으로 결과를 검증하는 습관을 그대로 적용했습니다. 저에게 AI 활용의 핵심은 빠르게 초안을 얻고, 사람이 검증 기준을 쥐는 것입니다. 입사 후에도 코딩 에이전트와 LLM 도구를 개발, 검증, 문서화에 적극 활용하되, 결과를 확인하는 기준은 제가 책임지겠습니다. Cursor 같은 코딩 에이전트를 활용한 빠른 PoC에서도 이 기준을 지키겠습니다.

> [확인 필요] 넥슨 계열 AI 코딩 테스트 준비에서 Claude와 ChatGPT를 함께 쓴 방식(풀이 교차 검토, 테스트 입력으로 검증, 메모 정리)은 C:\JWiki 의 준비 문서 이름을 근거로 추정한 내용입니다. 실제 사용 방식으로 고쳐 주세요.
