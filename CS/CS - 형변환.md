Type-conversion, type-casting
객체끼리 불가능, 포인터끼리 가능
	[const_cast] - const 속성을 제거하는 기능
	[static_cast] - B* b - static_cast<B*>(a); 가능 but UB가능성 -> down casting 시 type 확정 후 사용,그렇지 않아도 가능은하지만 객체 범위 벗어난 영역에 메모리 덮는 문제 발생 가능
		- 관련없으면 안됨(상속관계만)
		- 런타임에 타입검사 x,(RTTI안함) 하지만 빠름
		- 레퍼런스 끼리도 가능
		- 기본 타입 변환(정수↔실수 등)과, 상속 관계에서 “연관된 타입” 사이 변환을 허용.
	[reinterpret_cast] - 흔히 void\*타입을 다룰때, void\*로 형변환 한것을 되돌릴 때 등 더 위험함,이것보다 static_cast가 더 잘 쓰임
				- 상속계층에서 서로 관련없는 레퍼런스끼리 변환가능(안정성 떨어짐)
				- 포인터에 타입이 제공되는이유: 얼마나 제공되는지 알기 위해
				- 강력하지만 잘 쓰면 좋음- 포인터 비트 패턴을 “강제로 다른 타입처럼” 해석.
		        - 연관성 검사도 거의 없고 매우 위험하지만, void* ↔ 특정 타입 포인터 같은 저수준 인터페이스에서 어쩔 수 없이 등장.
		        - 
	[[dynamic_cast]] - 같은 상속 계층에 속한 타입끼리 , 런타임에 타입검사
				- 업캐스팅된 포인터에 대해서 다시 다운캐스팅할때 성공 
				- 포인터에 대해서는 실패시(타입이 다를 시) nullptr 반환
				- 레퍼런스에 대해서는 std::bad_cast예외 발생 => 레퍼런스 다이나믹캐스팅은 느려서 잘 안씀
				- dynamic_cast 를 쓰려면 vtable이 필요하다 즉, 가상함수가 필요함
				- ==포인터 타입의 형변환을 할 때는 “다운 캐스팅”에 항상 주의==
				- 예전엔 RTTI 문자열 비교->느림
				- 요즘엔 컴파일러/플랫폼에 따라 다름->빨라졌음
			    - 상속 계층에서 런타임 타입 검사(RTTI) 기반 안전한 다운캐스팅.
			    - 동작 조건: 대상 타입이 다형적(polymorphic)이어야 함(보통 가상 함수가 최소 1개 필요 → vtable/RTTI 활용).

3. 왜 엔진 업계에서 dynamic_cast를 꺼리는가, 그 대신은?
    

- 순정 C++에서는 dynamic_cast가 RTTI/가상 테이블 기반 런타임 검사라 비용 우려가 있고, RTTI 자체를 꺼버리는 빌드도 존재합니다.
    
- 언리얼은 C++ RTTI 대신 자체 리플렉션/타입 시스템(UObject 계층, UCLASS/GENERATED_BODY 등)으로 타입 정보를 “미리 심어둔 다음” Cast<T> 같은 API로 체크+변환을 합니다.
    
- 정리하면:
    
    - 표준 C++: RTTI를 켜고 dynamic_cast/typeid로 런타임 타입 검사.
        
    - 언리얼: 엔진이 빌드/코드생성 단계에서 메타데이터를 박아 넣고, 자체 시스템으로 타입 검사 + 캐스트를 구현.
