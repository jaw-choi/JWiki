# 2026-10-14 수업 핵심 정리 — 전이학습과 PyTorch 신경망

## 1. 사전학습 모델과 전이학습

- **문제:** 이미지를 분류하거나 사람 영역을 구분하려고 거대한 신경망을 처음부터 학습시키면 데이터·연산 비용이 큽니다.
- **개념:** `torchvision`에서 AlexNet·ResNet·MobileNet 등 **사전학습 모델과 가중치(weight)** 를 불러와 곧바로 추론하거나 내 데이터에 맞춰 일부 층을 재학습할 수 있습니다. 가중치 W와 편향 b는 학습으로 조정되는 수치입니다.
- **동작:** 기존 ImageNet 분류 모델의 출력은 보통 1,000개 클래스에 대응합니다. 없는 클래스를 분류하려면 마지막 분류층을 교체하고 필요에 따라 미세조정(Fine-tuning)합니다.
- **실습:** 모델을 출력해 층 구조를 살펴보고, 사전학습 가중치와 분류 클래스 목록을 확인했습니다.

→ 왜 배우나·현업 활용: 기존 모델을 재사용하는 구조를 이해하여, 소량의 게임 이미지로 새로운 분류 기능을 빠르게 개발하기 위해 배웁니다.

## 2. 이미지 전처리가 예측 결과를 바꾸는 이유

- **문제:** 모델 학습 시 사용한 입력 규칙과 실제 이미지의 규칙이 달라지면 결과가 흔들립니다.
- **흐름:** 이미지 읽기(PIL) → 크기 조정(예시 `Resize(256)`) → 중앙 자르기(`CenterCrop(224)`) → 텐서 변환(`ToTensor()`) → 평균·표준편차 정규화(`Normalize`) → 배치 차원 추가(`unsqueeze(0)`) → 추론.
- `ToTensor()`는 일반적인 RGB 이미지를 `[H, W, C]`에서 `[C, H, W]` 형태로 바꾸고 픽셀값을 보통 0~1로 변환합니다. `unsqueeze(0)`를 거치면 한 장도 `[1, 3, 224, 224]` 형태가 됩니다.
- **실습:** 크롭 크기를 변경하면 예측 클래스가 달라질 수 있고, `ToTensor()`를 제거하면 입력 타입 오류가 발생하며, `Normalize`를 빼면 오류 없이도 예측 품질이 달라질 수 있음을 비교했습니다.
- **보충 설명:** 전처리 수치는 모델의 실제 가중치에 연결된 공식 transforms에 맞추는 것이 안전합니다. `model.eval()`은 평가 모드, `torch.no_grad()`는 추론 중 기울기 계산 방지입니다.

→ 왜 배우나·현업 활용: 입력 텐서의 형식과 학습 조건을 이해하여, 배포 모델이 정상 작동해도 예측이 틀리는 장애를 진단하기 위해 배웁니다.

## 3. 모델 출력과 활성화 함수

- 모델 출력의 1,000개 숫자는 보통 **로짓(logits)** 이며, 그대로 확률은 아닙니다. 가장 큰 값의 위치를 `argmax`로 찾으면 예측 클래스 인덱스를 얻습니다. `Softmax`를 사용하면 전체 합이 1인 클래스별 값을 만들 수 있습니다.
- **이진분류**(합격/불합격): 출력 1개 + `Sigmoid`로 0~1 범위 출력. **단일 정답 다중분류**(개/고양이/새): 클래스 수만큼 출력 + `Softmax`. **연속값 회귀**(가격·온도): 출력층에 보통 별도의 활성화 함수를 두지 않습니다.
- **은닉층:** 중간의 `Linear` 층이 특징을 조합하며 `ReLU` 등 비선형 활성화 함수가 복잡한 관계를 학습하도록 돕습니다.
- **보충 설명:** `Softmax` 자체는 최댓값을 *선택*하지 않습니다. 최댓값 인덱스는 `argmax`가 선택합니다. PyTorch의 `CrossEntropyLoss`는 로짓을 직접 입력받으므로 보통 모델에 Softmax를 미리 붙이지 않습니다. `BCEWithLogitsLoss`도 마찬가지로 Sigmoid를 내부 처리합니다.

→ 왜 배우나·현업 활용: 출력층과 손실함수의 관계를 이해하여, 분류·확률 예측·수치 예측 모델의 마지막 층을 올바르게 구성하기 위해 배웁니다.

## 4. 신경망 학습 과정과 핵심 튜닝값

1. **순전파:** 입력 X에 W·b를 적용하고 활성화 함수를 통과시켜 예측값을 계산합니다.
2. **손실 계산:** 정답 Y와 예측값의 차이를 손실함수로 계산합니다.
3. **역전파:** 손실을 각 파라미터로 미분해 기울기를 계산합니다.
4. **옵티마이저 갱신:** SGD·Adam 등이 학습률(LR)에 맞춰 W·b를 업데이트합니다.
5. **반복:** 데이터를 일정 개수씩 묶은 **배치**로 학습하고, 전체 학습 데이터를 한 번 사용하면 **에폭(epoch)** 1회입니다.

**우선 알아둘 하이퍼파라미터:**
- **학습률(LR):** 한 번에 가중치를 얼마나 크게 수정할지. 지나치게 크면 학습이 불안정하고 작으면 매우 느릴 수 있습니다.
- **배치 크기:** 한 번의 업데이트에 사용하는 데이터 수. 예를 들어 100개를 20개씩 나누면 일반적인 미니배치 학습에서 에폭당 5회 업데이트합니다.
- **에폭:** 학습 데이터를 몇 차례 반복할지.
- **은닉층 수·뉴런 수:** 모델 용량과 연산량에 영향.
- **Dropout·BatchNorm:** 과적합 완화 또는 학습 안정화를 위해 사용하는 기법(두 기능은 서로 다릅니다).

**보충 설명:** 미니배치 학습은 각 배치에서 파라미터를 순서대로 계속 갱신하며, 매 에폭마다 '가장 오차가 작은 배치의 W·b를 선택'하는 방식이 아닙니다. 에폭을 늘린다고 항상 손실이 감소하거나 최적해에 도달하는 것도 아닙니다.

→ 왜 배우나·현업 활용: 손실과 학습률의 관계를 이해하여, 학습이 발산하거나 너무 느린 모델의 원인을 점검하기 위해 배웁니다.

## 5. 검증·과적합·실습 확장

- **훈련/검증/테스트 데이터 분리:** 훈련 데이터로 W·b를 조정하고, 검증 데이터로 튜닝·체크포인트 선택을 하며, 테스트 데이터로 최종 일반화 성능을 평가합니다.
- **과적합:** 훈련 손실은 계속 줄지만 검증 손실은 증가하는 상황입니다. 검증 손실을 확인해 최적 모델을 저장하고 조기 종료(Early stopping)를 적용할 수 있습니다.
- **실습에서 다룬 구조:** `nn.Sequential`로 입력 3개 → 은닉층 4개 뉴런 → 은닉층 2개 뉴런 → 출력 1개 구성, 층별 weight·bias 확인, `torchinfo.summary`를 이용한 모델 구조·파라미터 확인.
- **영상 실습:** 사전학습된 세그멘테이션 모델과 OpenCV 웹캠을 연결해 **사람 영역만 남기고 나머지를 배경 이미지로 대체**하는 기능을 다뤘습니다. 웹캠 입력 크기와 처리 속도의 관계도 설명했습니다.
- **추가 아이디어(강의 제안):** 캡처 프레임 히스토그램, Streamlit 화면, GPT 이미지 질의응답, SQLite 로그 저장 → 이후 MySQL·FastAPI 확장. 모바일 배포를 위한 ONNX 등 변환도 언급되었습니다.

→ 왜 배우나·현업 활용: 일반화 성능과 추론 자원 제약을 이해하여, 실제 카메라 기반 AI 기능의 정확도·속도를 함께 개선하기 위해 배웁니다.


## 6. Hugging Face 세그멘테이션과 영역별 이미지 편집 [추가 녹취]

**문제·배경:** 사진 전체를 바꾸는 것이 아니라 머리카락·상의·배경처럼 원하는 부분만 바꾸려면 픽셀마다 해당 부분을 구별해야 합니다.

- **세그멘테이션(Segmentation):** 이미지의 각 픽셀에 분류값을 부여해 마스크(mask)를 만듭니다. 수업에서는 사전학습된 인물·의류 관련 모델을 불러와 여러 영역의 마스크를 얻고, 머리색만 RGB 값으로 변경하는 실습을 소개했습니다.
- **실습 흐름:** Hugging Face에서 모델 확인 → `transformers`의 프로세서와 사전학습 모델 로드 → 이미지 읽기 → 모델에 맞게 전처리 → 예측 마스크 생성 → 머리카락에 해당하는 픽셀만 선택 → 선택한 RGB 색상으로 변경해 화면에 표시.
- **단색 변경 vs 오버레이:** 단색 변경은 선택 픽셀을 지정 색으로 *대체*하고, 오버레이는 원본과 색상을 투명도로 *혼합*합니다. 질감 유지 여부가 다릅니다.
- **확장:** 옷 영역만 색상 변경, 배경 합성, 면적 계산, 사진·영상에서 객체 단위 편집. 각 모델의 라벨과 라이선스를 확인해야 하며, 실제 가상 피팅처럼 옷의 형태까지 자연스럽게 바꾸려면 별도의 생성·합성 기술이 필요할 수 있습니다.
- **보충 설명:** `transformers`는 Hugging Face 라이브러리이며 **PyTorch 자체의 하위 패키지는 아닙니다**. 다만 PyTorch 모델을 백엔드로 활용할 수 있습니다.

→ 왜 배우나·현업 활용: 픽셀 마스크의 의미를 이해하여, 게임 캐릭터 외형 변경이나 의류 시뮬레이터에서 선택 영역만 안전하게 편집하기 위해 배웁니다.

## 7. YOLO·OpenCV·LLM을 연결한 영상 분석 서비스 [추가 녹취]

**문제·배경:** AI 모델 하나가 객체를 감지하는 것과, 사용자가 실시간으로 조회하고 기록하는 서비스는 별개입니다.

- **강의 시연 구성:** 웹캠 → YOLO로 객체 검출 → 선택 객체 모자이크·블러 및 사람 감지 → 감지 결과에 대한 GPT 질의응답 → 세션·이벤트 로그를 로컬 DB에 기록 → 웹 화면에서 조회.
- **세그멘테이션과 객체 검출 차이:** 객체 검출은 주로 사각형 박스 단위로 위치를 찾고, 세그멘테이션은 픽셀 단위로 영역을 분리합니다. 정확한 배경 교체나 사람 윤곽별 모자이크는 후자가 유리합니다.
- **저장·조회:** 간단한 시제품은 SQLite의 `.db` 파일로 시작하고 필요하면 MySQL로 옮기는 흐름을 설명했습니다. 자연어 질문을 SQL로 변환하는 Text-to-SQL에서는 `message_json`과 `event_json`처럼 실제 컬럼 구조를 확인하지 않으면 잘못된 질의가 생성될 수 있습니다.
- **배포 고려:** 웹 카메라 권한은 일반적으로 HTTPS 같은 보안 컨텍스트에서 제공됩니다(`localhost`는 예외). 다중 사용자·카메라·대형 모델은 지연·메모리·서버 비용에 영향을 줍니다. 수업에는 ONNX와 온디바이스 추론으로 확장하는 방향도 나왔습니다.
- **주의:** 녹취의 시연 서비스가 실제로 어떤 환경에서 어느 FPS로 동작했는지, 전체 기능이 오류 없이 완료되었는지는 **확인 필요**입니다. GPT에는 모델이 실제로 검출한 객체·시간·로그만 근거 데이터로 전달해야 합니다.

→ 왜 배우나·현업 활용: 모델 추론과 웹·DB·LLM 사이의 데이터 흐름을 이해하여, 실시간 모니터링 서비스에서 잘못된 감지 결과나 로그 조회 오류를 추적하기 위해 배웁니다.

## 8. MCP·Few-shot과 AI 기능의 품질 검증 [추가 녹취]

**문제·배경:** API나 MCP 도구를 연결한 뒤에도 LLM이 사용자 표현을 잘못 해석하면 원하는 결과를 반환하지 못합니다.

- **수업 사례:** 화장품 추천 시스템에서 사용자가 요구한 '2만 원대'를 LLM이 잘못 해석해 가격 범위 파라미터(`min_price`, `max_price`)를 틀리게 전달하는 상황을 검토했습니다.
- **Few-shot prompting:** 올바른 입력·출력 예시를 프롬프트에 여러 개 제공해 '2만 원대', '3만 5천 원', 한글·숫자 혼합 표기 등을 일관되게 변환하도록 유도합니다. 범위를 어떻게 정의하는지는 **서비스 정책**으로 먼저 정해야 합니다.
- **평가 방법:** 표현 유형별 테스트 사례를 만들고 변경 전후 정확도와 실패 사례를 비교합니다. 수업에서 이를 A/B 테스트에 비유했지만, 엄밀한 A/B 테스트라면 사용자 또는 요청을 무작위로 두 버전에 배정해 지표를 비교합니다.
- **MCP(Model Context Protocol):** LLM이 외부 도구·데이터와 통신하도록 연결하는 표준입니다. Hugging Face 관련 MCP는 모델 검색·메타데이터 확인에 도움을 줄 수 있지만, **MCP 연결만으로 모델 추론이 자동 실행되는 것은 아닙니다**. 해당 서버가 제공하는 도구를 확인해야 합니다.
- **주의:** 'LLM은 영어 기반이라 한국어가 무조건 약하다'는 일반화는 모델마다 다릅니다. 수업에서 분석한 **구체적인 서비스와 테스트 데이터의 관찰**로 이해해야 합니다.

→ 왜 배우나·현업 활용: 도구 호출과 자연어 해석을 분리해서 평가하여, AI 상품 추천 챗봇에서 가격 조건을 잘못 적용하거나 고객 의도를 놓치는 오류를 개선하기 위해 배웁니다.

## 9. OLTP·OLAP, 배치 처리와 데이터 동기화 [추가 녹취]

|---|---|---|
| 주목적 | 주문·결제·재고처럼 빠르고 정확한 거래 처리 | 매출 추이·이상 탐지·집계 등 분석 |
| 특징 | 짧은 조회/갱신, 트랜잭션, 동시성 관리 | 대규모 스캔·조인·집계 |
| 예시 | MySQL 주문 테이블의 재고 감소 | 데이터 웨어하우스·Spark로 월별 판매량 분석 |

- **수업 사례:** 판매 종료 상태나 재고 정보가 서로 다른 시스템 사이에서 늦게 반영되면 판매 불가 상품을 주문받는 문제가 생깁니다. 주기적 배치만 사용하면 데이터 최신성에 시간 차이가 생길 수 있습니다.
- **연관 기술:** CDC(Change Data Capture)는 DB 변경 사항을 감지해 다른 시스템으로 전달하는 기법입니다. 로그·알림, 데이터 품질 점검, 재처리 경로가 필요합니다.
- **보충 설명:** OLAP이 항상 배치 방식이거나 실시간 분석이 불가능한 것은 아닙니다. Hive·Spark는 분석 처리 도구이고, HDFS는 데이터를 여러 노드에 분산 저장하는 파일 시스템입니다. S3와 같은 객체 저장소도 분석 데이터 저장에 활용됩니다. OpenSearch는 검색·분석 엔진이며 벡터 검색도 지원하지만 **벡터 DB 기능만 있는 제품은 아닙니다**.

→ 왜 배우나·현업 활용: 거래 DB와 분석 DB의 역할을 구분하여, 재고 조회 응답 지연이나 시스템 간 상품 상태 불일치가 발생했을 때 병목과 데이터 지연 지점을 파악하기 위해 배웁니다.

## 신입 면접 예상 질문과 답변

**Q1. 전이학습은 왜 하나요?**  
A. 이미 학습된 모델의 특징 추출 능력을 재사용해 초기 학습에 필요한 데이터와 비용을 줄이기 위해서입니다. 새 작업에 맞게 출력층을 교체하고, 필요하다면 일부 층만 추가로 학습합니다.

**Q2. `ToTensor`와 `Normalize`의 차이는 무엇인가요?**  
A. `ToTensor`는 이미지를 모델이 처리할 수 있는 텐서로 바꾸고 통상 픽셀 범위를 0~1로 변환합니다. `Normalize`는 지정한 평균과 표준편차를 이용해 각 채널 값을 조정하며, 사전학습 모델의 입력 조건과 일치시켜야 합니다.

**Q3. 학습률을 너무 크게 주면 어떻게 되나요?**  
A. 손실을 줄이는 방향으로 이동하는 폭이 커져 최적점 주변을 지나치거나 손실이 발산할 수 있습니다. 손실 그래프를 확인하며 LR을 낮추거나 스케줄러를 적용할 수 있습니다.

**Q4. Sigmoid와 Softmax는 언제 쓰나요?**  
A. Sigmoid는 독립적인 이진 판단이나 다중 레이블 분류에 적합하고, Softmax는 서로 배타적인 여러 클래스 중 하나를 예측할 때 주로 사용합니다. 실제 구현에서는 손실함수가 해당 변환을 내부 처리하는지 먼저 확인합니다.

**Q5. 훈련 정확도는 높은데 실제 영상에서 오분류가 많다면?**  
A. 먼저 학습·실서비스 전처리 차이와 데이터 분포 차이를 확인하겠습니다. 그 다음 검증 성능, 클래스별 오류, 과적합 여부를 점검하고 데이터 보강·모델 튜닝·추론 속도를 함께 평가하겠습니다.

### 녹취 표현 중 확인·정정이 필요한 부분

- '출력 1,000개 숫자 = 모두 확률'은 정확하지 않습니다. Softmax 이전 값은 일반적으로 로짓입니다.
- '배치마다 가장 좋은 가중치 선택', '에폭이 많을수록 오차 무조건 감소'는 일반적인 신경망 학습 규칙이 아닙니다.
- 'BatchNorm이 W·b를 정규화한다'는 설명은 부정확합니다. 보통 층의 활성값을 정규화하는 구조입니다.
- '과소적합 = 손실이 천천히 감소'도 일반적인 정의가 아닙니다. 과소적합은 데이터 패턴을 충분히 학습하지 못하는 상태입니다.
- 웹캠 세그멘테이션 코드의 정확한 모델 이름과 실측 처리 속도, 실습 완료 여부는 녹취만으로 **확인 필요**입니다.

**Q6. 객체 검출과 세그멘테이션의 차이는 무엇인가요?**  
A. 객체 검출은 주로 바운딩 박스로 위치와 클래스를 알려주고, 세그멘테이션은 픽셀 수준의 영역 마스크를 만듭니다. 따라서 특정 사람만 정밀하게 흐리게 하거나 머리카락만 색을 바꿀 때는 세그멘테이션이 유리합니다.

**Q7. 실시간 주문 처리와 매출 집계를 왜 분리하나요?**  
A. 주문 처리에는 빠른 응답과 트랜잭션 일관성이 중요하고, 매출 집계에는 많은 데이터를 한꺼번에 읽는 작업이 필요합니다. 두 처리를 분리하면 분석 작업이 주문 처리 성능을 저하시키는 위험을 줄일 수 있으며, 데이터 동기화 지연은 별도로 관리해야 합니다.

**Q8. MCP로 추천 도구를 만들었지만 가격 조건이 자주 틀리면 어떻게 하겠습니까?**  
A. 우선 사용자 표현을 가격 범위로 변환하는 정책과 테스트 케이스를 정의하겠습니다. 도구 스키마·설명·Few-shot 예시를 개선하고, 변경 전후의 조건 해석 정확도와 최종 검색 결과를 비교하겠습니다.
