## 1. 오늘 수업의 큰 흐름

오늘 수업은 단순히 Python 문법을 배우는 것이 아니라, **작은 함수를 등록·검증하고 → 재사용 가능한 구조로 모듈화하고 → FastAPI를 통해 외부에서 호출할 수 있게 만드는 과정**을 연결해서 이해하는 것이 핵심입니다.

즉,

`함수 작성 → Tool Registry 등록 → 클래스/상속으로 공통 기능 분리 → 모듈/패키지화 → FastAPI로 외부 공개 → ASGI 서버로 실행`

이라는 흐름입니다.

→ 왜 배우나·현업 활용: 함수 하나만 작성하는 수준을 넘어서, 실제 서비스에서 여러 기능을 안전하게 관리하고 API로 배포하기 위해 배웁니다.

## 2. Tool Registry: 여러 함수를 이름으로 관리하기

### 핵심 개념
`Tool Registry`는 여러 도구(함수/클래스)를 **이름으로 등록하고 찾아서 실행하는 관리소**입니다.

예를 들어 `add`, `hello` 같은 도구를 등록해 두면 호출하는 쪽에서는 내부 구현을 직접 찾지 않고 이름으로 사용할 수 있습니다.

Registry가 담당하는 핵심 기능은 다음과 같습니다.

- 도구 등록
- 중복 등록 검사
- 등록된 도구 목록 반환
- 이름으로 도구 검색
- 존재하지 않는 도구 호출 시 오류 처리

### 실행 흐름

```text
main.py
  ↓
ToolRegistry 생성
  ↓
add / hello 도구 등록
  ↓
등록된 도구 목록 확인
  ↓
registry.call("add", ...)
  ↓
해당 도구의 run() 실행
  ↓
결과 반환
```

함수는 정의만 되어 있다고 실행되는 것이 아니라 **호출되어야 실행**됩니다. 따라서 코드를 읽을 때는 위에서부터 읽기보다 `main`에서 실제로 어떤 함수가 호출되는지 따라가는 방식이 효과적입니다.

→ 왜 배우나·현업 활용: 플러그인, AI Agent Tool, 명령 처리 시스템처럼 기능이 많아졌을 때 기능을 이름으로 등록·호출하고 잘못된 호출을 통제하기 위해 배웁니다.

## 3. Base Tool과 상속: 공통 규칙을 한 곳에 모으기

각 도구마다 보통 다음 정보가 필요합니다.

- 이름(`name`)
- 설명(`description`)
- 입력 파라미터
- 실제 실행 함수(`run`)

이 공통 구조를 `BaseTool` 같은 부모 클래스에 정의하고, `AddTool`, `HelloTool` 등이 상속받도록 만들 수 있습니다.

```text
BaseTool
 ├─ AddTool
 └─ HelloTool
```

자식 클래스가 부모와 같은 이름의 메서드를 다시 정의하면 자식의 구현을 사용하는데, 이것이 **오버라이딩(override)** 입니다.

부모 클래스를 사용하는 핵심 이유는 여러 클래스에서 공통으로 필요한 동작을 한 번만 정의하기 위해서입니다. 공통 정책이 바뀌면 부모만 수정해도 하위 클래스에 동일한 규칙을 적용할 수 있습니다.

→ 왜 배우나·현업 활용: 여러 기능에서 반복되는 검증, 로깅, 호출 횟수 측정, 실행 시간 측정 같은 코드를 한 곳에서 관리하기 위해 배웁니다.

## 4. 모듈화: 한 파일에 전부 넣지 않기

수업에서 가장 강조된 개발 습관 중 하나는 **기능별로 파일을 분리하는 것**입니다.

예시 구조는 다음과 같습니다.

```text
project/
├─ main.py
├─ tool_core/
│  ├─ base.py
│  └─ registry.py
└─ tools/
   ├─ add.py
   └─ hello.py
```

핵심 기준은 다음과 같습니다.

- 여러 프로젝트에서 다시 쓸 수 있는 것 → 공통 모듈로 분리
- 현재 프로젝트에서만 쓰는 기능 → 개별 모듈로 분리
- 실행 흐름을 시작하는 코드 → `main.py`

Python에서 `.py` 파일 하나는 하나의 **모듈(module)** 로 사용할 수 있고, 여러 모듈을 묶어 패키지처럼 사용할 수 있습니다.

### `__init__.py`
패키지를 구성할 때 사용하는 파일입니다. 패키지 초기화나 외부에 노출할 항목을 정리하는 데 사용할 수 있습니다.

→ 왜 배우나·현업 활용: 코드가 커졌을 때 유지보수·협업·테스트가 가능한 구조로 만들고, 다른 프로젝트에서도 공통 코드를 재사용하기 위해 배웁니다.

## 5. 기능 명세서와 AI 문서화

코드를 작성한 뒤에는 코드만 남기는 것이 아니라 다음 내용을 문서화하는 것이 중요하다고 설명했습니다.

- 기능 이름
- 기능 설명
- 입력값과 타입
- 출력값
- 오류 조건
- 함수 간 호출 관계
- 폴더 구조

특히 AI를 사용할 때는 긴 코드를 통째로 설명시키는 것보다 **프로젝트 폴더 전체의 파일 관계, 함수 호출 관계, 다이어그램, 기능 명세**를 만들도록 요청하는 방식이 유용하다고 설명했습니다.

다만 회사 코드에는 보안 이슈가 있을 수 있으므로 외부 웹 서비스에 그대로 붙이는 것은 주의해야 합니다.

→ 왜 배우나·현업 활용: 인수인계, 코드 리뷰, QA, 신규 개발자 온보딩에서 다른 사람이 코드를 빠르게 이해하도록 하기 위해 배웁니다.

## 6. 전역 변수와 지역 변수

- **지역 변수**: 함수 내부에서 만들어지고 함수 실행이 끝나면 더 이상 사용할 수 없는 변수
- **전역 변수**: 여러 함수에서 공통으로 접근할 수 있도록 함수 밖에서 관리하는 변수

공통 상태를 무조건 전역 변수로 두기보다는 클래스의 인스턴스나 부모 클래스에 넣어 관리하는 방식도 사용할 수 있습니다.

→ 왜 배우나·현업 활용: 여러 함수가 공유해야 하는 상태와 함수 내부에서만 써야 하는 상태를 구분하여 예기치 않은 값 변경을 줄이기 위해 배웁니다.

## 7. 데코레이터와 부모 클래스의 차이

둘 다 반복되는 기능을 줄이는 데 사용되지만 목적이 다릅니다.

| 구분 | 데코레이터 | 부모 클래스/상속 |
|---|---|---|
| 주 목적 | 함수 실행 전후에 공통 기능 추가 | 여러 클래스의 공통 상태·동작 공유 |
| 예시 | 로그, 시간 측정, 권한 검사 | 공통 검증 규칙, 공통 속성 |
| 특징 | 기존 함수를 감싸서 기능 추가 | 부모의 기능을 자식이 물려받음 |

→ 왜 배우나·현업 활용: 반복 코드를 줄일 때 상황에 따라 함수 중심 구조와 객체 중심 구조 중 적절한 방법을 선택하기 위해 배웁니다.

## 8. 동기와 비동기

동기 방식은 하나의 작업이 끝나야 다음 작업을 진행합니다.

비동기 방식은 네트워크 요청이나 파일 처리처럼 기다리는 시간이 발생할 때, 그동안 다른 작업을 처리할 수 있도록 합니다.

Python에서는 `async`, `await` 같은 문법을 사용합니다.

→ 왜 배우나·현업 활용: API 서버에서 여러 사용자의 요청을 동시에 처리하거나 외부 서비스 응답을 기다리는 동안 서버 자원을 낭비하지 않기 위해 배웁니다.

## 9. FastAPI: Python 기능을 외부에서 호출할 수 있게 만들기

수업에서 FastAPI의 역할은 **Python 내부에서만 쓰던 함수를 브라우저나 다른 서버가 HTTP를 통해 호출할 수 있도록 연결하는 것**으로 설명했습니다.

```text
브라우저 / 다른 서버
        ↓ HTTP 요청
     FastAPI
        ↓
 Python 함수 / DB / AI 모델
        ↓
     결과 반환
```

예를 들어 다음 구조입니다.

```python
@app.get("/")
def root():
    return {"message": "OK"}
```

사용자가 `/` 경로로 GET 요청을 보내면 `root()` 함수가 실행되고 결과를 반환합니다.

FastAPI는 자체적으로 네트워크 포트를 열어 요청을 직접 처리하는 서버가 아니라, **웹 애플리케이션의 API 규칙과 동작을 정의하는 프레임워크**로 이해하는 것이 핵심입니다.

→ 왜 배우나·현업 활용: AI 모델, 데이터 처리 함수, DB 조회 결과를 웹이나 다른 서비스에서 사용할 수 있는 API로 제공하기 위해 배웁니다.

## 10. ASGI와 Uvicorn

> **확인 필요:** 녹취에서 `Unicorn`으로 인식된 부분이 많지만, FastAPI 실행 문맥상 **Uvicorn**을 설명한 것으로 보입니다.

FastAPI 애플리케이션을 실제로 실행하려면 네트워크 요청을 받아주는 **ASGI 서버**가 필요합니다.

대표적으로 Uvicorn을 사용합니다.

```bash
uvicorn main:app --reload
```

의미:

- `main` → `main.py`
- `app` → `FastAPI()`로 만든 객체
- `--reload` → 코드 변경 시 개발 서버 자동 재시작

### WSGI와 ASGI

- **WSGI**: 전통적인 Python 웹 서버 인터페이스, 동기 처리 중심
- **ASGI**: 비동기 처리를 지원하는 최신 인터페이스

수업에서는 Flask를 WSGI 기반, FastAPI를 ASGI 기반의 대표적인 흐름으로 설명했습니다.

→ 왜 배우나·현업 활용: FastAPI 애플리케이션을 실제 서버 프로세스로 실행하고 동시에 여러 요청을 처리하는 구조를 이해하기 위해 배웁니다.

## 11. Starlette와 FastAPI

수업에서는 FastAPI가 **Starlette 기반**으로 동작한다고 설명했습니다.

FastAPI는 Starlette의 웹 기능 위에 입력값 검증, 타입 힌트 활용, 자동 문서화 등의 기능을 추가해서 API 개발을 편하게 해줍니다.

따라서 미들웨어나 예외 처리 등 더 내부적인 동작을 확인할 때 Starlette 문서도 참고할 수 있습니다.

→ 왜 배우나·현업 활용: FastAPI 내부 구조를 이해하고, 기본 기능으로 해결되지 않는 미들웨어·예외 처리 문제를 분석하기 위해 배웁니다.

## 12. Jinja 템플릿: Python 데이터를 HTML에 넣기

HTML은 기본적으로 정적 문서이지만, 상품명·가격·사용자 이름처럼 Python에서 만든 값을 화면에 동적으로 표시하려면 템플릿 엔진을 사용할 수 있습니다.

수업에서는 **Jinja 템플릿**을 예로 들었습니다.

```text
Python 딕셔너리
      ↓
FastAPI
      ↓
Jinja Template
      ↓
HTML 화면
```

예를 들어 Python에서 상품 목록을 만들고 HTML에서 반복문으로 출력할 수 있습니다.

→ 왜 배우나·현업 활용: DB나 Python 코드에서 가져온 데이터를 웹 페이지에 동적으로 표시하기 위해 배웁니다.

## 13. 타입 힌트와 입력 검증

FastAPI를 사용하는 주요 이유 중 하나는 Python의 타입 힌트를 적극적으로 활용하여 입력 데이터를 검증할 수 있다는 점입니다.

예를 들어 숫자가 들어와야 하는 곳에 잘못된 값이 들어왔는지 미리 검사할 수 있습니다.

수업에서는 직접 검증 클래스를 만들 수도 있지만, Python/FastAPI에서 제공하는 검증 기능을 활용하는 것이 더 실용적이라고 설명했습니다.

→ 왜 배우나·현업 활용: 잘못된 API 요청이 프로그램 내부 로직까지 들어오기 전에 차단하여 장애와 데이터 오류를 줄이기 위해 배웁니다.

# 관련 현업 직무 추천

## 1. Backend / API 개발자
Python 비즈니스 로직과 DB를 FastAPI 같은 프레임워크로 연결하고, 여러 서비스가 사용할 API를 설계합니다. 오늘 배운 모듈화, 타입 검증, 비동기 처리, API 구조가 직접 연결됩니다. 추가로 SQL, 인증/인가, 테스트, Docker, 클라우드 배포 역량이 필요합니다.

## 2. AI Platform / MLOps 엔지니어
AI 모델이나 데이터 처리 코드를 API로 서비스화하고 배포·운영합니다. 모델 자체뿐 아니라 FastAPI, Docker, 네트워크, 모니터링을 함께 다루는 경우가 많습니다. 추가로 Linux, Docker/Kubernetes, CI/CD, 클라우드, 모델 서빙 구조를 익히면 좋습니다.

# 예상 면접 질문과 답변

### Q1. Tool Registry를 사용하는 이유는 무엇인가요?
여러 함수를 직접 조건문으로 연결하지 않고 이름으로 등록하고 조회할 수 있기 때문입니다. 기능이 늘어나도 등록 구조만 유지하면 확장하기 쉬우며, 존재하지 않는 도구나 중복 등록 같은 오류도 한곳에서 처리할 수 있습니다.

### Q2. 상속과 데코레이터는 언제 각각 사용하나요?
상속은 여러 클래스가 공통 상태나 동작을 공유해야 할 때 적합합니다. 데코레이터는 기존 함수의 실행 전후에 로그, 시간 측정, 권한 검사처럼 공통 기능을 추가할 때 적합합니다.

### Q3. FastAPI와 Uvicorn의 차이는 무엇인가요?
FastAPI는 어떤 경로에서 어떤 Python 함수를 실행할지 정의하는 웹 프레임워크입니다. Uvicorn은 그 FastAPI 애플리케이션을 실제로 실행하고 네트워크 요청을 받아주는 ASGI 서버입니다.

### Q4. 왜 코드를 여러 `.py` 파일로 분리하나요?
기능별 책임을 나누면 수정 범위가 명확해지고 테스트와 협업이 쉬워집니다. 또한 공통 기능을 독립 모듈로 분리하면 다른 프로젝트에서도 재사용할 수 있습니다.

### Q5. 비동기 처리가 필요한 대표적인 상황은 무엇인가요?
외부 API 호출, DB 요청, 파일 I/O처럼 CPU가 계산하지 않고 기다리는 시간이 많은 작업에서 유용합니다. 기다리는 동안 다른 요청을 처리할 수 있기 때문에 API 서버의 동시 처리 효율을 높일 수 있습니다.
