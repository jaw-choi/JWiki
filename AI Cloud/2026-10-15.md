## 1. 전체 학습 흐름: 모델을 학습하는 것에서 서비스를 만드는 것까지

**문제·배경.** 이미지 분류 모델의 테스트 정확도가 높더라도, 사용자가 휴대전화로 찍은 사진이나 직접 그린 그림을 입력하면 예상과 다른 결과가 나올 수 있습니다. 모델 구조만 알면 끝나는 것이 아니라 **입력 전처리 → 학습 → 평가 → 저장 → 불러오기 → 실제 입력 추론 → 배포 환경 검증**이 이어져야 합니다.

**[수업]** 먼저 OpenCV 이진화와 OCR 전처리를 살펴본 뒤 CNN(합성곱 신경망)의 구성요소, MNIST 손글씨 분류, 가중치 저장과 재사용, ResNet의 특징 맵 시각화 및 미세조정, 모바일 배포 시 양자화와 서비스 기획으로 확장했습니다. 강사가 강조한 결론은 **좋은 모델을 받아서 실제 환경에서 안정적으로 추론하게 만드는 역량**입니다.

→ 왜 배우나·현업 활용: 학습용 성능과 서비스 성능의 차이를 이해하여, 사진 업로드 API나 모바일 AI 기능에서 추론 실패의 원인을 단계별로 찾기 위해 배웁니다.

## 2. OCR 전처리: 이진화는 왜 필요한가

**[수업]** OCR(Optical Character Recognition, 광학 문자 인식)은 이미지 속 글자를 추출하는 기술입니다. 복잡한 배경·선·낮은 대비 때문에 글자 경계가 흐리면, OpenCV로 흑백 변환과 **이진화(binary thresholding)**를 적용하여 글자와 배경을 구분할 수 있습니다. 필요하면 밑줄이나 표의 선을 제거하거나 분리합니다.

**[보충]** 이진화는 각 픽셀을 기준값에 따라 검정(0) 또는 흰색(255)으로 바꾸는 것입니다. 조명이 균일하지 않으면 적응형 이진화가 유리할 수 있고, 색상 정보나 옅은 획이 중요한 원본에서는 이진화가 오히려 정보를 파괴할 수 있습니다. 원본과 전처리 결과를 둘 다 남겨 OCR 결과로 효과를 확인해야 합니다.

**Windows / VS Code 터미널, Python 예시:**

```python
import cv2

image = cv2.imread("input.jpg")
if image is None:
    raise FileNotFoundError("input.jpg를 확인하세요")
gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
_, binary = cv2.threshold(gray, 140, 255, cv2.THRESH_BINARY)
cv2.imwrite("binary.png", binary)
```

- 실행 위치: `input.jpg`가 있는 작업 폴더에서 `python ocr_binary.py` 실행.
- 목적·옵션: `cvtColor`는 컬러를 회색조로 바꾸고 `threshold(..., 140, 255, THRESH_BINARY)`는 밝기 140을 기준으로 픽셀을 0/255로 나눕니다. 임계값 140은 **예시**일 뿐, 이미지마다 조정해야 합니다.
- 예상 결과와 해석: `binary.png` 생성 여부와 글자 획의 보존 여부를 눈으로 확인합니다. 이 코드는 OCR 자체를 수행하지 않습니다. GUI 창이 없는 OpenCV 설치에서도 `imshow` 대신 파일 저장으로 확인할 수 있습니다.

→ 왜 배우나·현업 활용: 글자 인식 전처리의 역할을 이해하여, 영수증·문서 인식 서비스에서 배경선 때문에 글자가 잘못 읽히는 문제를 개선하기 위해 배웁니다.

## 3. CNN은 이미지에서 어떻게 특징을 찾는가

**[수업]** CNN(Convolutional Neural Network, 합성곱 신경망)은 필터(커널)를 이미지 위에서 이동시키며 픽셀값과 필터의 가중치를 연산해 **특징 맵(feature map)**을 만듭니다. 초기 층은 선·경계 같은 비교적 단순한 특징을, 깊은 층은 이들을 조합한 복잡한 특징을 표현하는 경향이 있습니다. 각 출력 채널은 하나의 필터 집합이 만든 특징 맵입니다.

- `in_channels`: 들어오는 특징 맵 채널 수. RGB 사진의 첫 입력은 일반적으로 3, 흑백 MNIST는 1입니다.
- `out_channels`: 만드는 출력 특징 맵 수. 예를 들어 3채널 입력을 8개의 필터 집합으로 처리하면 출력 채널은 8개입니다.
- `kernel_size=3`: 필터의 공간 크기가 3×3이라는 뜻입니다. RGB 입력에서는 **필터 하나가 3×3×3 깊이 전체에 걸쳐** 계산합니다.
- `stride=1`: 필터를 가로·세로 한 픽셀씩 이동합니다. 큰 값으로 설정하면 보통 출력 크기와 연산량이 줄지만 일부 세부 정보가 빠질 수 있습니다.
- `padding=1`: 입력 영상의 가장자리에 픽셀 한 줄을 추가합니다(기본적으로 0으로 채움). `3×3`, `stride=1`과 함께 쓰면 가로·세로 크기를 보존할 수 있습니다.

**출력 크기 계산 [보충]**

\[
H_{out}=\left\lfloor\frac{H_{in}+2P-K}{S}\right\rfloor+1
\]

폭도 같은 방식으로 계산합니다(일반적인 dilation=1 가정). 예를 들어 **4×4 이미지 + 3×3 필터 + stride 1 + padding 0 → 2×2**, 반대로 **padding 1 → 4×4**입니다. **28×28 MNIST에 padding 없이 3×3 합성곱 적용 → 26×26**가 됩니다. 녹취의 일부 크기 계산 표현은 음성 인식이 흐릿하여, 복습에서는 위 공식으로 검산하는 편이 정확합니다.

**[수업]** Max Pooling은 일정 영역의 최댓값만 남기며 크기를 줄이는 기법입니다. `2×2`, `stride=2`의 경우 적절한 크기에서 가로·세로가 대략 절반이 됩니다. ReLU는 음수 입력을 0으로 바꾸는 활성화 함수입니다. Batch Normalization은 미니배치 통계를 활용해 중간 값의 분포를 조정합니다.

**[확인 필요·정정]** 수업에서 “요즘 Max Pooling을 안 쓴다”라고 단정적으로 들리는 부분이 있지만, 현재도 많은 모델에서 사용합니다. 스트라이드 합성곱 등 다른 다운샘플링 방법도 있을 뿐입니다. 또한 배치 정규화에도 학습 가능한 scale/shift 파라미터가 있을 수 있으므로, '가중치는 합성곱에만 있다'는 설명은 정확한 일반 법칙이 아닙니다.

→ 왜 배우나·현업 활용: 커널·채널·스트라이드·패딩의 관계를 이해하여, CNN 구조 수정 시 텐서 크기 불일치나 메모리·연산량 증가 원인을 진단하기 위해 배웁니다.

## 4. Flatten, 완전연결층, 배치 차원

**[수업]** CNN에서 얻은 다차원 특징 맵을 분류에 사용하는 한 방법은 **Flatten(평탄화)**으로 한 줄로 펼쳐서 **Fully Connected Layer(완전연결층, `Linear`)**에 넣는 것입니다. 예를 들어 특징 맵 크기가 `8×26×26`이면 한 이미지당 5,408개의 값이 됩니다.

**[보충]** PyTorch 이미지 배치는 일반적으로 `[N, C, H, W]` 순서입니다. `N`은 이미지 개수, `C`는 채널, `H/W`는 높이/너비입니다. 한 장만 추론하더라도 `[1,1,28,28]`처럼 배치 차원이 필요합니다. `torch.flatten(x, 1)`은 맨 앞 배치 차원을 보존한 채 나머지를 펼칩니다. 입력 크기가 바뀌면 Flatten 뒤 `Linear` 입력 차원도 달라져 오류가 날 수 있습니다. 다만 모든 CNN이 고정 크기 Flatten을 쓰는 것은 아니며, **Adaptive Average Pooling** 등으로 다양한 입력 크기를 처리할 수 있습니다.

→ 왜 배우나·현업 활용: 텐서 차원과 FC층의 입력 크기를 이해하여, 학습 때와 다른 해상도 사진을 넣었을 때 발생하는 shape mismatch를 해결하기 위해 배웁니다.

## 5. MNIST 손글씨 분류 실습의 연결 구조

**[수업]** MNIST는 0~9 숫자 10종을 담은 **28×28 흑백 이미지 데이터셋**입니다. 실습에서는 `torchvision.datasets.MNIST`로 학습·테스트 데이터를 준비하고 `transforms.ToTensor()`로 텐서로 바꾸며, `DataLoader`로 예를 들어 **batch_size=64**, 학습 데이터는 `shuffle=True`로 구성하는 흐름을 설명했습니다. 학습 Epoch를 3회로 두는 예도 나왔지만, 성능은 실제 실행 결과에 따라 달라집니다.

**복습용 PyTorch 모델 구조 예시** (수업 원본 코드가 아니라 개념을 설명하기 위한 최소 모델):

```python
import torch
from torch import nn

class DigitCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 8, kernel_size=3, padding=0),
            nn.ReLU(),
            nn.Flatten(),
        )
        self.classifier = nn.Linear(8 * 26 * 26, 10)

    def forward(self, x):
        return self.classifier(self.features(x))  # logits: [N, 10]

model = DigitCNN()
print(model(torch.zeros(1, 1, 28, 28)).shape)
# 예상: torch.Size([1, 10])
```

- 실행 위치: Windows PowerShell의 Python 가상환경 또는 Linux 가상환경. `torch` 설치가 필요합니다.
- 확인 목적: 입력 `[1,1,28,28]`이 Conv를 지나 `[1,8,26,26]`이 되고, Flatten으로 `[1,5408]`, 최종적으로 **10개 분류 점수(logits)**가 나오는 구조를 확인합니다.
- 분류 규칙: 각 샘플의 정답은 0~9 가운데 하나이므로 분류 출력 차원은 10입니다. 추론에서는 `argmax(dim=1)`로 가장 높은 점수의 클래스 인덱스를 고릅니다.
- **[보충·정정]** PyTorch `nn.CrossEntropyLoss`는 **Softmax 이전의 logits**을 받습니다. 학습 코드에서 Softmax를 별도로 적용한 뒤 이 손실함수에 넣는 것이 아닙니다. 사용자에게 확률처럼 보여줄 때만 `softmax(logits, dim=1)`를 적용합니다.

**[수업]** 실제 손글씨 시험에서는 학습용 테스트셋뿐 아니라 **직접 그린 이미지**를 넣어야 합니다. GUI는 Tkinter 캔버스나 Streamlit 등으로 만들고, 좌표를 따라 획을 그린 다음 28×28로 전처리해 모델에 전달할 수 있습니다. **MNIST는 일반적으로 검은 배경에 밝은 숫자 획**이므로, 흰 종이에 검정 펜으로 그린 그림은 반전 등 입력 변환이 필요할 수 있습니다. 글씨의 크기·중앙 정렬·두께도 학습 데이터와 비교해야 합니다.

→ 왜 배우나·현업 활용: 데이터 로딩에서 실제 사용자 입력 추론까지 연결하는 방법을 이해하여, 손글씨 인식 웹앱에서 테스트 정확도는 높지만 직접 그린 숫자는 틀리는 문제를 재현하고 수정하기 위해 배웁니다.

## 6. 모델 저장: 학습 코드와 서비스 코드를 분리하기

**[수업]** 강의에서는 AI 모델을 다시 매번 학습시키기보다, 학습된 **가중치를 파일로 저장한 후 추론 서비스에서 불러오는 흐름**을 특히 강조했습니다.

| 방식 | 저장 코드 예 | 장점 | 주의사항 |
|---|---|---|---|
| 가중치만 저장 | `torch.save(model.state_dict(), 'digit_weights.pth')` | 일반적으로 이식성과 유지보수에 유리 | 불러올 때 모델 구조를 동일하게 정의해야 함 |
| 모델 객체 전체 저장 | `torch.save(model, 'digit_full.pt')` | 예제에서는 간편하게 복원 가능 | Python 클래스 경로와 직렬화 환경에 의존하고 보안 위험이 있어 배포용으로 신중해야 함 |

**가중치 로드 예시 [보충]**

```python
model = DigitCNN()
state = torch.load('digit_weights.pth', map_location='cpu', weights_only=True)
model.load_state_dict(state)
model.eval()
with torch.inference_mode():
    logits = model(torch.zeros(1, 1, 28, 28))
    prediction = logits.argmax(dim=1).item()
```

- 실행 위치: `digit_weights.pth`와 모델 클래스 정의에 접근 가능한 Python 프로젝트.
- 목적: `map_location='cpu'`는 CPU 환경에서 가중치를 읽게 하고, `eval()`은 드롭아웃·배치 정규화 등의 추론 동작을 설정하며, `inference_mode()`는 불필요한 그래디언트 추적을 끕니다.
- 예상 결과·주의: `prediction`은 0~9 중 하나지만, 예시에 사용한 **0으로 가득한 더미 텐서의 결과에는 의미가 없습니다.** `digit_weights.pth`는 먼저 실제 학습 또는 준비된 가중치로 생성해야 합니다. 신뢰할 수 없는 모델 파일의 역직렬화는 피해야 합니다.

**[보충]** 수업에서 “전체 모델 저장이 무조건 더 무겁다”는 취지로 설명한 부분은 일반화할 수 없습니다. 파일 크기는 저장한 구조·가중치·추가 객체에 따라 달라집니다. 실무에서는 체크포인트 형식, 모델 구조 버전, 전처리 규칙과 클래스 목록을 함께 관리하는 것이 중요합니다.

**[수업]** 에폭마다 평가 지표가 개선될 때만 모델을 저장하는 **best checkpoint** 전략을 소개했습니다. 이를 사용하려면 정확도만이 아니라 손실과 검증용 데이터 분리도 고려해야 합니다.

→ 왜 배우나·현업 활용: 모델과 서비스를 분리하는 방법을 이해하여, FastAPI 서버나 데스크톱 앱이 시작할 때 학습을 반복하지 않고 검증된 가중치만 로드하도록 구성하기 위해 배웁니다.

## 7. 전이학습: 이미 학습한 특징을 어디까지 재사용할까

**[수업]** 전이학습(Transfer Learning)은 다른 데이터로 미리 학습한 모델의 특징 추출 능력을 새 문제에 활용하는 방법입니다. 예를 들어 **ResNet의 기존 분류 출력이 1000개**라면, 부엌/거실의 두 클래스로 새로 분류하고 싶을 때 마지막 분류층을 **2개 출력**으로 바꿉니다. 필요한 경우 일부 깊은 층도 다시 학습시키며 이를 **Fine-tuning(미세조정)**이라고 부릅니다.

- **Freeze(동결)**: 해당 파라미터를 업데이트하지 않습니다. `requires_grad=False`.
- **Unfreeze(동결 해제)**: 해당 파라미터를 업데이트하도록 허용합니다. `requires_grad=True`.
- **Feature extraction**: 대체로 사전학습된 특징 추출층을 고정하고 새 분류층만 학습합니다.
- **Fine-tuning**: 마지막 블록 등 일부 또는 모든 사전학습층도 낮은 학습률 등으로 추가 학습합니다.

**ResNet 마지막 블록 + 분류층 변경 예시 [보충]**

```python
import torch.nn as nn
from torchvision.models import resnet18, ResNet18_Weights

model = resnet18(weights=ResNet18_Weights.DEFAULT)
for param in model.parameters():
    param.requires_grad = False
for param in model.layer4.parameters():
    param.requires_grad = True
model.fc = nn.Linear(model.fc.in_features, 2)  # 새 FC는 기본적으로 학습 가능
```

- 실행 위치: `torch`, `torchvision`이 설치되고 사전학습 가중치를 다운로드할 수 있는 Python 환경. 최초 실행은 네트워크 접근이 필요할 수 있습니다.
- 목적·확인: `layer4`와 새 `fc`를 학습 가능하게 두고, 나머지를 고정합니다. 이후 **부엌/거실 라벨이 붙은 실제 학습 데이터**, DataLoader, 손실함수, optimizer, 검증 과정이 별도로 필요합니다. 이 코드만으로 학습이 이루어지지는 않습니다.
- **[보충]** 새 문제의 종류에 따라 **분류 헤드만 학습 → 일부 블록 해제 → 검증 점수로 비교**하는 순서를 추천합니다. 이미지 한 장의 특징 맵 모양만으로 최적 동결 구간을 확정할 수 없습니다. ResNet 종류에 따라 블록 구성과 입력 전처리가 달라집니다.

→ 왜 배우나·현업 활용: 기존 모델을 재사용하는 원리를 이해하여, 적은 양의 도메인 이미지로 새 분류 서비스를 만들 때 전체 재학습 비용과 과적합 위험을 줄이기 위해 배웁니다.

## 8. 특징 맵 시각화와 AI 에이전트 자동화 구상

**[수업]** 준비한 JPEG를 `RGB`로 변환한 후 모델에 맞는 `transforms`를 적용해 입력합니다. PIL/OpenCV에서 보편적인 `HWC(높이, 너비, 채널)` 배열을 PyTorch가 요구하는 `CHW(채널, 높이, 너비)`로 바꾸는데, `ToTensor()`가 일반적인 이미지 입력에서 이를 처리합니다. 여기에 배치 차원까지 추가합니다. 사전학습 ResNet은 **해당 가중치에 맞는 Resize/Crop/Normalize 설정**을 사용하는 것이 중요합니다.

강의의 아이디어는 다음 순서였습니다.

1. **특징 맵 추출**: ResNet의 초기 합성곱층과 `layer1`~`layer4` 등의 중간 출력 일부 채널을 시각화합니다.
2. **해석**: 단계별 그림에서 어떤 특징이 강조되는지 관찰하고, 동결/해제 후보를 정합니다.
3. **자동화 구상**: 특징 맵 이미지 또는 히스토그램·활성값 분포 등의 요약 통계로 GPT가 판단 근거를 제시하도록 구성합니다.
4. **구조화된 결과**: 예컨대 `{"freeze": ["layer1", "layer2", "layer3"], "train": ["layer4", "fc"]}`처럼 JSON으로 기록해 다음 코드가 활용하게 합니다.
5. **검증**: 추천 결과를 그대로 믿지 않고 여러 이미지와 검증 데이터로 정확도·재현율·속도 등을 비교합니다.

**[확인 필요·정정]** 녹취 중에는 한 샘플 그림의 특징 맵이 흐릿해 보이기 때문에 특정 레이어를 재학습한다는 취지의 설명이 나옵니다. **시각적으로 원본 형태가 사라진다고 해서 특징 정보가 쓸모없어진다는 뜻은 아닙니다.** 고수준 특징은 원래 사람 눈으로 해석하기 어려울 수 있습니다. GPT의 레이어 추천은 **실험 가설**이며, 데이터셋 전체의 검증 성능으로 확인해야 합니다. 히스토그램만으로 최적 레이어를 판별하는 것도 입증된 보편적 규칙은 아닙니다.

**[수업]** 코드를 한 번에 만들지 말고 파트별로 진행하여 각 단계의 성공 여부를 확인하고, 결과·프롬프트·JSON·모델 선택 이유를 문서화하라고 했습니다. 이후 혼동행렬(confusion matrix), 정밀도·재현율, 설명 가능한 AI(XAI: 모델이 어느 부분에 반응했는지 설명하는 기법) 분석까지 확장할 수 있습니다.

→ 왜 배우나·현업 활용: 중간 특징의 관찰과 검증 실험을 연결하여, 전이학습 설정을 자동 제안하는 도구를 만들 때 AI 추천의 근거와 실패 사례를 기록하고 검증하기 위해 배웁니다.

## 9. 모델 평가: 정확도만 보면 부족한 이유

**[수업]** MNIST처럼 쉬운 공개 데이터에서 높은 정확도가 나와도 그것만으로 서비스 품질을 판단할 수 없으며, 숫자별 어떤 오분류가 발생했는지 **혼동행렬**, **정밀도(Precision)**, **재현율(Recall)** 등을 확인해야 한다고 했습니다. 실제 서비스에서 반드시 맞혀야 하는 어려운 사례를 따로 모은 **골든 데이터셋**도 강조했습니다.

**[보충]** 정밀도는 '그 클래스로 예측한 것 중 실제 맞은 비율', 재현율은 '실제 그 클래스인 것 중 찾아낸 비율'입니다. 골든 데이터셋은 요구사항과 라벨을 신중하게 검토한 대표·경계·실패 사례를 포함하도록 설계하며, 학습에 누출되지 않도록 분리합니다. 데이터를 반복해 보며 하이퍼파라미터를 조정했다면 최종 독립 테스트셋을 별도로 두는 것이 안전합니다.

→ 왜 배우나·현업 활용: 분류 성능의 편향과 취약한 입력을 이해하여, 특정 숫자·제품·환경에서만 오탐이 늘어나는 현상을 출시 전 시험으로 발견하기 위해 배웁니다.

## 10. 배포에서는 전처리·속도·기기 제약이 핵심

**[수업]** 모델이 실제 사용될 장소가 **서버 API**인지, **모바일 온디바이스(on-device)**인지 처음부터 결정하라고 강조했습니다. 서버 추론은 클라이언트가 이미지를 보내고 서버가 예측을 반환하는 방식이고, 온디바이스 추론은 모바일 기기에서 직접 모델을 실행합니다. 입력 해상도, 방향, 배경, 중앙 정렬, 처리 지연, 메모리와 하드웨어 호환성까지 확인해야 합니다.

**[수업]** 모바일의 자원 제한에 대응하는 대표적 방법으로 **양자화(quantization)**를 들었습니다. 예를 들어 32비트 부동소수점 연산 일부를 8비트 표현으로 바꾸면 모델 크기나 추론 자원 요구량을 줄일 가능성이 있습니다. 다만 정확도 저하 여부와 목표 기기에서의 실제 속도 향상 여부를 직접 평가해야 합니다.

| 항목 | 서버 API 추론 | 모바일 온디바이스 추론 |
|---|---|---|
| 연산 위치 | 서버/클라우드 | 사용자 스마트폰 |
| 장점 | 모델 교체·중앙 관리 쉬움 | 네트워크 없이도 작동 가능, 원본 데이터를 기기에 둘 수 있음 |
| 주의점 | 전송 지연·서버 요금·보안 | 메모리·배터리·칩셋 호환성·앱 배포 |
| 반드시 확인 | 요청~응답 지연, 처리량, 비용 | 기기별 지연, 메모리, 발열·전력, 정확도 |

**[확인 필요·정정]** 녹취에서 사진 크기를 “반드시 10%씩 반복 축소해야 한다”는 취지의 표현이 나오지만 **보편적인 필수 규칙은 아닙니다.** 적합한 보간법(`INTER_AREA`, bilinear 등), 종횡비 보존, 작게 쓰인 객체·문자 보존, 모델의 학습 전처리와 일치 여부를 실험으로 판단해야 합니다. 또한 양자화 후 정확도와 성능은 하드웨어 및 런타임에 따라 달라집니다.

→ 왜 배우나·현업 활용: 추론 위치와 경량화의 트레이드오프를 이해하여, 스마트폰 앱이나 FastAPI 추론 서버에서 지연·메모리·품질 목표에 맞게 배포 구조를 설계하기 위해 배웁니다.

5. **ResNet 전이학습 비교** — 목표 이미지의 라벨 폴더를 `train/val/test`로 분리하고 ResNet의 **FC층만 교체한 모델**과 **마지막 블록까지 해제한 모델**을 비교합니다. → 동결 구간 선택을 근거 있는 실험으로 만듭니다.
6. **배포 평가** — 목표 기기나 서버에서 처리 시간, 메모리, 오분류 사례를 기록하고, 필요하면 양자화 전후를 같은 테스트셋에서 비교합니다. → 사용 가능한 서비스를 판단합니다.

## ④ 예상 신입 면접 질문과 답변

**Q1. CNN에서 채널·커널·패딩·스트라이드는 각각 어떤 역할을 하나요?**  
A. 채널은 입력/출력 특징 맵의 종류와 개수이고, 커널은 특징을 계산하는 필터의 공간 크기입니다. 스트라이드는 필터의 이동 간격이고 패딩은 가장자리에 픽셀을 추가해 출력 크기나 경계 정보를 조절합니다. 이 값들을 잘못 맞추면 연산량이 증가하거나 다음 층과의 텐서 크기가 일치하지 않을 수 있습니다.

**Q2. Softmax와 CrossEntropyLoss를 PyTorch에서 어떻게 사용하나요?**  
A. 모델은 클래스별 점수인 logits를 그대로 출력하고, `nn.CrossEntropyLoss`에 logits와 정답 인덱스를 전달해 학습합니다. `CrossEntropyLoss` 내부에 로그 소프트맥스에 해당하는 처리가 포함되므로 학습 전에 Softmax를 중복 적용하지 않습니다. 화면에 확률처럼 보여줄 때는 추론 점수에 Softmax를 적용합니다.

**Q3. MNIST 테스트 정확도는 높은데 사용자가 손으로 쓴 숫자를 틀리게 읽습니다. 무엇부터 확인하겠습니까?**  
A. 먼저 학습 이미지와 서비스 입력의 배경/글자 색, 해상도, 중앙 정렬, 정규화, 배치 차원이 같은지 확인하겠습니다. 실제 실패 이미지를 수집해 전처리 전후를 비교하고, 특정 입력 유형에서만 오류가 나는지 분석하겠습니다. 필요하다면 해당 유형을 검증셋에 포함해 모델 개선 효과를 확인하겠습니다.

**Q4. 전이학습에서 왜 일부 층을 동결하나요?**  
A. 사전학습 모델의 유용한 특징 추출 능력을 활용하면서 새 데이터에 맞춰야 하는 파라미터만 학습하기 위해서입니다. 데이터가 적으면 처음에는 분류층만 학습하고, 부족하면 깊은 블록을 일부 해제해 비교할 수 있습니다. 어느 층을 해제할지는 이미지의 모양만 보고 정하기보다 검증 데이터의 성능을 기준으로 선택하겠습니다.

**Q5. 모바일 배포 전에 AI 모델에서 반드시 검증할 사항은 무엇인가요?**  
A. 입력 전처리가 학습 조건과 일치하는지 확인하고 목표 단말에서 지연 시간, 메모리, 발열 또는 전력, 기기 호환성을 측정해야 합니다. 양자화 등을 적용했다면 모델이 작아졌다는 사실만 볼 것이 아니라 실제 처리 속도와 원본 대비 정확도 저하를 검증해야 합니다. 또한 대표 사례와 어려운 골든 데이터셋을 별도로 시험하겠습니다.
