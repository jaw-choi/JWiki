## 1. 왜 문장을 숫자로 바꿀까?

사용자는 문장으로 검색하지만 컴퓨터는 단어와 문장의 관계를 계산해야 검색 결과를 정렬할 수 있습니다. 가장 단순한 시작은 문서를 단어 단위로 쪼개고, 각 단어가 몇 번 나왔는지 숫자로 표현하는 것입니다. 이를 **문서-단어 행렬(Document-Term Matrix)**이라고 합니다.

예를 들어 `이미지 대체 텍스트`, `이미지 설명`, `링크 목적`이라는 세 문장이 있으면 공통 단어 목록을 만들고 문장마다 출현 횟수를 셉니다. 단어의 위치나 맥락보다는 *어떤 단어가 몇 번 나왔는지*를 표현합니다.

→ 왜 배우나·현업 활용: 문서를 숫자로 표현하는 원리를 이해하여, 실제 검색 엔진이나 RAG 시스템에서 키워드 검색의 결과가 왜 나왔는지 분석하기 위해 배웁니다.

### 실습: 리스트 컴프리헨션 없이 문서-단어 행렬 만들기

**실행 위치:** Windows PowerShell 또는 Linux 터미널에서 Python 3이 설치된 환경. 아래 코드는 별도의 외부 패키지 없이 실행됩니다.

```python
from collections import Counter

corpus = ["이미지 대체 텍스트", "이미지 설명", "링크 목적"]

tokenized = []
for sentence in corpus:
    tokenized.append(sentence.split())

vocab_set = set()
for words in tokenized:
    for word in words:
        vocab_set.add(word)
vocab = sorted(vocab_set)

rows = []
for words in tokenized:
    count = Counter(words)
    row = []
    for word in vocab:
        row.append(count[word])
    rows.append(row)

for document_id, values in enumerate(rows, start=1):
    print("D" + str(document_id), dict(zip(vocab, values)))
```

- `split()`은 **공백 기준** 분리입니다. 한국어의 조사를 제거하거나 활용형을 정규화하는 형태소 분석이 아닙니다.
- `Counter`는 단어별 출현 횟수를 기록합니다. `sorted`로 어휘 순서를 고정하여 모든 문서의 숫자 열이 같은 단어를 의미하게 합니다.
- 결과에서 해당 문서에 있는 단어는 `1`, 없는 단어는 `0`입니다. 여기서는 동일 문장 안에서 중복된 단어가 없기 때문이며, 일반적으로 반복되면 `2` 이상도 됩니다.
- **확인할 것:** 동일한 열 순서를 유지하지 않으면 문서 벡터를 비교할 수 없습니다.

→ 왜 배우나·현업 활용: 벡터의 각 차원이 어떤 단어를 뜻하는지 이해하여, 실제 문서 검색 전처리에서 잘못된 어휘 매핑이나 토큰화 오류를 찾기 위해 배웁니다.

## 2. 벡터의 노름(Norm)과 코사인 유사도

벡터는 숫자가 순서대로 나열된 값입니다. **노름**은 벡터의 크기를 나타내는 값이며, 가장 일반적인 L2 노름은 각 원소 제곱의 합에 제곱근을 취합니다.

\[\|x\|_2 = \sqrt{x_1^2+x_2^2+\cdots+x_n^2}\]

예를 들어 `(3, 4)`의 L2 노름은 `5`입니다. 벡터끼리 비교할 때 길이가 다른 영향을 줄이기 위해 노름으로 나누어 **정규화**하기도 합니다. 단, 0벡터는 길이가 0이어서 나눌 수 없으므로 별도 처리가 필요합니다.

→ 왜 배우나·현업 활용: 벡터의 크기와 방향을 구분하여, 실제 검색 유사도 계산에서 문서 길이에 따른 점수 왜곡을 진단하기 위해 배웁니다.

**코사인 유사도**는 두 벡터 사이의 각도를 활용합니다. 내적을 각각의 노름으로 나누어 계산합니다.

\[\operatorname{cosine}(A,B)=\frac{A\cdot B}{\|A\|_2\|B\|_2}\]

- 같은 방향이면 `1`, 직각이면 `0`, 반대 방향이면 `-1`입니다.
- 단어 출현 횟수나 TF-IDF처럼 성분이 음수가 아닌 벡터에서는 보통 `0~1` 범위의 값이 나옵니다.
- **주의:** 코사인 유사도는 단어의 실제 의미를 자동으로 이해하지 않습니다. 어떤 벡터 표현을 사용했는지가 중요합니다.

```python
import math

a = [1, 1, 0]
b = [1, 0, 1]

dot = 0
norm_a_sq = 0
norm_b_sq = 0
for i in range(len(a)):
    dot += a[i] * b[i]
    norm_a_sq += a[i] ** 2
    norm_b_sq += b[i] ** 2

norm_a = math.sqrt(norm_a_sq)
norm_b = math.sqrt(norm_b_sq)

if norm_a == 0 or norm_b == 0:
    print("코사인 유사도 계산 불가: 0벡터")
else:
    print(dot / (norm_a * norm_b))  # 약 0.5
```

**실습 이유:** 벡터를 먼저 만든 다음, 내적과 노름으로 상대적 방향을 비교하는 순서입니다. 코드에서 `0`으로 나누는 예외를 처리했는지 확인하세요.

→ 왜 배우나·현업 활용: 유사도 점수의 계산 원리를 이해하여, 실제 유사 문서 추천이나 벡터 검색 결과의 정렬 기준을 설명하기 위해 배웁니다.

## 3. TF-IDF는 무엇을 해결하나?

단순 빈도 검색에서는 `이`, `그`, `있다`처럼 여러 문서에 흔히 등장하는 단어가 검색 점수에 과도한 영향을 줄 수 있습니다. **TF-IDF(Term Frequency–Inverse Document Frequency)**는 한 문서에서 자주 나오면서 문서 집합 전체에서는 드문 단어에 더 큰 가중치를 부여합니다.

- **TF**: 특정 단어가 한 문서에서 얼마나 등장했는지.
- **DF**: 특정 단어를 포함한 문서의 수.
- **IDF**: 여러 문서에 흔하게 등장하는 단어의 중요도를 낮추는 가중치.
- **TF-IDF**: TF와 IDF를 결합한 단어 가중치. 구현 라이브러리마다 세부 공식·평활화·정규화 방식은 다를 수 있습니다.

TF-IDF는 문장 사이의 *의미적 연관성*을 직접 학습하는 것이 아니라 **단어 출현 통계**를 활용합니다. 예를 들어 `자동차`와 `승용차`는 관련어여도 두 문서에서 동일한 단어가 겹치지 않으면 유사도가 낮을 수 있습니다.

→ 왜 배우나·현업 활용: 검색 점수가 어떤 통계에 의해 높아지는지 이해하여, 실제 사내 문서 검색에서 흔한 단어 때문에 관련 없는 문서가 상위 노출될 때 개선하기 위해 배웁니다.

### 실습: scikit-learn으로 TF-IDF 만들기

**실행 위치:** Windows PowerShell, 활성화된 Python 가상환경을 권장합니다.

```powershell
python -m pip install scikit-learn
```

`python -m pip`는 현재 `python` 명령으로 실행되는 인터프리터 환경에 패키지를 설치합니다. `pip`를 단독 실행하는 경우와 환경이 달라지는 문제를 줄일 수 있습니다.

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

corpus = ["이미지 대체 텍스트", "이미지 설명", "링크 목적"]
vectorizer = TfidfVectorizer(token_pattern=r"(?u)\b\w+\b")
X = vectorizer.fit_transform(corpus)

print(vectorizer.get_feature_names_out())
print(X.toarray())
print(cosine_similarity(X))
```

- `fit_transform`: 문서에서 어휘와 IDF를 학습한 뒤 TF-IDF 행렬을 만듭니다.
- `get_feature_names_out`: 각 열에 해당하는 단어를 보여줍니다.
- `toarray`: 작은 실습용 자료를 보기 쉽게 밀집 배열로 바꿉니다. **대규모 희소 행렬에서 실행하면 메모리 사용이 급증할 수 있습니다.**
- `cosine_similarity`: 문서별 TF-IDF 벡터 간 유사도 행렬을 출력합니다. 대각선은 일반적으로 자기 자신과의 유사도 1입니다.
- 위 문장들은 공백 토큰화가 가능한 짧은 예시입니다. 한국어 실제 서비스에서는 형태소 분석기, n-gram 등을 검토합니다.

→ 왜 배우나·현업 활용: TF-IDF 행렬과 문서 간 점수를 직접 확인하여, 실제 검색 모델을 바꿀 때 기준선(baseline) 성능을 측정하기 위해 배웁니다.

### TF-IDF의 대표적인 한계

1. 같은 뜻의 다른 단어(동의어)를 잘 연결하지 못합니다.
2. 공백 분리만 사용하면 조사·활용형 때문에 한국어 검색 정확도가 떨어질 수 있습니다.
3. 단어 순서와 긴 문맥을 충분히 반영하기 어렵습니다.
4. 오타나 표현 변형에 취약하며, 새 문서·어휘가 들어오면 어휘집/IDF 관리가 필요합니다.
5. 문서 길이, 반복 단어 등의 영향은 TF-IDF 구현의 가중치 및 정규화 설정에 따라 달라집니다.

→ 왜 배우나·현업 활용: 정확도가 낮은 원인이 토큰화인지 의미 불일치인지 구분하여, 실제 검색 시스템에서 형태소 분석·BM25·임베딩 중 필요한 개선책을 선택하기 위해 배웁니다.

## 4. TF-IDF와 BM25 비교

**BM25(Best Matching 25)**는 키워드 기반 문서 검색 순위 모델입니다. TF-IDF와 마찬가지로 질의 단어의 등장과 문서 집합에서의 희귀성을 활용하지만, **단어 빈도의 포화**와 **문서 길이 정규화**를 명시적으로 반영합니다.

| 관점 | TF-IDF | BM25 |
|---|---|---|
| 기본 방식 | 단어 빈도와 역문서 빈도로 벡터 가중치 계산 | 질의-문서 관련성 점수 계산 |
| 동일 단어 반복 | TF 설정에 따라 증가 | 빈도 효과가 점차 포화 |
| 문서 길이 보정 | 벡터 정규화 등 설정에 의존 | 보통 평균 문서 길이 기반 보정 사용 |
| 장점 | 개념 단순, 벡터 분석·기준선 만들기 쉬움 | 실무 키워드 검색에서 널리 쓰이는 강력한 기준선 |
| 한계 | 동의어·의미 연결 어려움 | 역시 동의어·의미 연결에 한계 |

BM25의 `k1`은 단어 빈도가 점수에 반영되는 포화 정도를, `b`는 문서 길이 보정의 정도를 조절하는 대표 파라미터입니다. 무조건 값을 높이면 좋다는 뜻이 아니며, 실제 검색 질의와 문서 특성에 따라 평가해야 합니다.

→ 왜 배우나·현업 활용: TF-IDF와 BM25의 점수 차이를 이해하여, 실제 검색 결과에서 지나치게 긴 문서나 반복 키워드가 상위에 몰리는 현상을 분석하기 위해 배웁니다.

## 5. Elasticsearch와 OpenSearch는 어떤 역할인가?

**Elasticsearch**와 **OpenSearch**는 검색·분석 엔진입니다. 애플리케이션의 문서 데이터를 인덱싱(검색하기 쉬운 자료 구조로 준비)하고, 검색어를 입력받아 관련 문서를 반환합니다. 둘은 공통된 기술적 출발점을 갖지만 현재는 별도 프로젝트이며 제품 버전별 API 및 기능 호환성은 확인해야 합니다.

일반적인 키워드 검색 흐름은 다음과 같습니다.

`원본 문서 → 텍스트 분석(토큰화 등) → 역색인 생성 → 검색어 분석 → BM25 등 점수 산정 → 결과 반환`

**역색인(Inverted Index)**은 `단어 → 그 단어가 들어 있는 문서들`의 관계를 저장한 자료 구조입니다. 모든 문서를 처음부터 끝까지 읽지 않아도 후보 문서를 빠르게 찾는 데 유리합니다. 검색 엔진은 단순 DB 저장소가 아니라 분석기, 색인, 점수 계산, 필터링 기능을 함께 제공합니다.

→ 왜 배우나·현업 활용: 검색 엔진의 인덱싱과 질의 처리를 이해하여, 실제 로그 검색이나 사내 지식 검색 API에서 색인 오류와 검색 품질 문제를 조사하기 위해 배웁니다.

### 전통 검색과 의미 검색의 차이

- **키워드 검색**: BM25처럼 질의 단어와 문서에 있는 단어의 일치를 주로 활용합니다. 고유명사, 오류코드, 제품번호 찾기에 강할 수 있습니다.
- **벡터/의미 검색**: 임베딩 모델이 만든 밀집 벡터를 비교합니다. 단어가 달라도 비슷한 뜻을 연결할 가능성이 있지만, 특정 고유 문자열을 정확히 찾는 데는 약할 수 있습니다.
- **하이브리드 검색**: 키워드 점수와 벡터 검색 결과를 함께 활용합니다. 결합 방식(RRF 등의 순위 융합, 점수 정규화 등)은 별도로 설계·평가해야 합니다.

→ 왜 배우나·현업 활용: 검색 대상에 맞는 검색 방식을 선택하여, 실제 RAG에서 정확한 오류코드 검색과 비슷한 의미의 설명 검색을 함께 지원하기 위해 배웁니다.

## 6. 오늘 학습의 연결 구조

1. **공백/형태소 기준 토큰화**로 문장을 단어 단위로 나눕니다.
2. **문서-단어 행렬**로 출현 횟수를 숫자로 표현합니다.
3. **TF-IDF**로 단어별 중요도를 조절합니다.
4. **노름과 코사인 유사도**로 문서 벡터를 비교합니다.
5. **BM25 / 검색 엔진**으로 키워드 검색 품질과 성능을 개선합니다.
6. 필요한 경우 **임베딩과 하이브리드 검색**으로 표현이 다른 유사 문장까지 탐색합니다.

이것은 개념을 이해하기 좋은 학습 순서이며, 실제 녹음의 강의 순서라고 주장하지 않습니다.

→ 왜 배우나·현업 활용: 전처리에서 검색 결과 생성까지 한 번에 연결하여, 실제 검색 서비스에서 어느 단계가 품질을 떨어뜨리는지 단계별로 디버깅하기 위해 배웁니다.

## ④ 예상 신입 면접 질문과 답변

**Q1. TF-IDF는 어떤 문제를 해결하기 위한 기법인가요?**  
>A. 단순 단어 빈도만 사용하면 여러 문서에 흔하게 나오는 단어가 과대평가될 수 있습니다. TF-IDF는 문서 안에서의 빈도와 전체 문서에서의 희귀성을 함께 반영합니다. 다만 단어의 의미 자체를 학습하지는 않습니다.

**Q2. 코사인 유사도와 유클리드 거리의 차이는 무엇인가요?**  
>A. 코사인 유사도는 두 벡터가 이루는 각도, 즉 방향의 유사성을 측정합니다. 유클리드 거리는 두 점 사이의 직선 거리를 측정하므로 벡터 크기에도 민감합니다. 어느 것이 적절한지는 벡터의 의미와 정규화 여부에 따라 달라집니다.

**Q3. TF-IDF 대신 BM25를 사용하는 이유는 무엇인가요?**  
>A. BM25는 단어가 반복될 때 점수 증가가 점차 둔화되는 효과와 문서 길이 보정을 반영합니다. 이 특징 덕분에 길이가 다른 문서의 키워드 검색에서 강력한 기준선이 됩니다. 다만 정확도가 항상 더 높다고 단정하지 않고 실제 데이터로 평가해야 합니다.

**Q4. Elasticsearch나 OpenSearch에서 검색어가 있는데 결과가 나오지 않으면 어떻게 점검하겠습니까?**  
>A. 우선 문서가 정상 색인되었는지, 검색 대상 인덱스와 필드가 맞는지 확인합니다. 그다음 인덱스·검색 분석기의 토큰화 결과, 필터 조건, 대소문자나 형태소 처리를 점검합니다. 관련 로그와 재현 가능한 최소 질의로 원인을 좁혀 보겠습니다.

**Q5. RAG 검색에서 의미는 같은데 단어가 다른 문서를 못 찾는다면 어떤 방법이 있나요?**  
>A. TF-IDF나 BM25 같은 키워드 검색은 단어 불일치에 약할 수 있습니다. 문장 임베딩을 활용한 의미 검색을 추가하고, 정확한 용어 검색이 필요하다면 키워드 검색과 결합하는 하이브리드 방식을 검토하겠습니다. 개선 여부는 정답 문서가 상위 k개에 포함되는지 평가하겠습니다.
