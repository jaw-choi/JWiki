## 2. 컴퓨터 기초: CS는 컴퓨터를 이해하는 기본 상식

CS는 Computer Science의 약자입니다. 넓게는 컴퓨터과학을 뜻하지만, 이번 수업에서는 컴퓨터를 다루는 데 필요한 기초부터 시작합니다.

### 주요 구성 요소

| 용어 | 역할 | 쉬운 비유 |
| --- | --- | --- |
| CPU | 명령을 처리하고 계산 | 일을 하는 사람 |
| 메모리(RAM) | 실행 중인 작업에 필요한 정보를 임시 보관 | 작업 중인 책상 |
| 저장장치(SSD·HDD) | 파일과 프로그램을 보관 | 자료를 넣어 두는 서랍 |
| 운영체제(OS) | 하드웨어와 프로그램의 자원을 관리 | 일을 배분하는 관리자 |
| 네트워크 | 컴퓨터끼리 데이터를 주고받도록 연결 | 자료가 오가는 길 |

클라우드·데브옵스 업무는 서비스를 배포하고 운영하므로 운영체제, 네트워크, 저장장치, 프로그램 실행 방식 등을 함께 이해해야 합니다.

### 왜 Windows의 기본 드라이브는 C일까?

과거 DOS·PC 환경에서는 플로피디스크 드라이브에 주로 `A:`와 `B:`를 사용했습니다. 이후 하드디스크에 `C:`를 부여하는 관례가 이어졌습니다.

- `A:`, `B:`: 과거 플로피디스크 드라이브에 사용하던 문자
- `C:`: 일반적으로 Windows가 설치된 드라이브
- `D:`, `E:` 등: 다른 저장장치나 파티션 등에 사용

드라이브 문자는 논리적인 구분입니다. `C:`와 `D:`가 있어도 반드시 물리적인 디스크가 두 개라는 뜻은 아닙니다.

## 3. 파일·폴더·경로 이해하기

| 용어 | 뜻 | 예시 |
| --- | --- | --- |
| 파일 | 내용을 저장한 단위 | `샘플.txt` |
| 디렉토리 | 폴더와 같은 뜻 | `test` |
| 경로 | 파일이나 폴더의 위치 | `C:\test\샘플.txt` |
| 루트 디렉토리 | 해당 드라이브의 최상위 폴더 | `C:\` |
| 현재 디렉토리 | 지금 작업하는 폴더 | `C:\test` |
| 상위 디렉토리 | 현재 폴더를 포함하는 바로 위 폴더 | `C:\test`의 상위는 `C:\` |
| 확장자 | 파일 이름 끝에서 형식을 나타내는 부분 | `.txt`, `.md`, `.png` |

**절대 경로**는 `C:\test\샘플.txt`처럼 위치를 처음부터 적습니다. **상대 경로**는 `샘플.txt`, `..`처럼 현재 위치를 기준으로 적습니다.

## 4. CLI: 글자로 컴퓨터에 명령하기

- **GUI**: 화면의 아이콘과 메뉴를 마우스로 클릭하는 방식
- **CLI**: 명령어를 글자로 입력하는 방식

CLI는 서버 관리, 개발 도구 실행, 반복 작업 자동화에 자주 사용됩니다. 모든 작업을 CLI로 해야 하는 것은 아니며, 목적에 맞게 GUI와 함께 사용합니다.

### Windows CMD 기본 명령어

아래 예시는 **Windows 명령 프롬프트(CMD)** 기준입니다. PowerShell이나 Linux 셸에서는 일부 문법과 동작이 다릅니다.

| 명령어 | 기능 |
| --- | --- |
| `cmd` | 명령 프롬프트 실행 |
| `dir` | 현재 폴더의 파일과 하위 폴더 목록 보기 |
| `cd` | 현재 경로 확인 |
| `cd 폴더명` | 지정한 폴더로 이동 |
| `cd ..` | 상위 폴더로 이동 |
| `cd \` | 현재 드라이브의 최상위 폴더로 이동 |
| `cd /d C:\` | 드라이브까지 바꾸어 C 드라이브의 최상위로 이동 |
| `mkdir 폴더명` | 폴더 만들기 |
| `rmdir 폴더명` | 빈 폴더 삭제 |
| `del 파일명` | 파일 삭제 |
| `type 파일명` | 텍스트 파일 내용 보기 |
| `cls` | 명령 프롬프트 화면 지우기 |
| `명령어 /?` | 해당 CMD 명령어의 도움말 보기 |

`del`로 삭제한 파일은 보통 휴지통으로 이동하지 않으므로 실행 전에 대상을 확인합니다.

### 실습: C 드라이브에 test 폴더와 샘플 파일 만들기

다음은 직접 CMD에 입력하는 예시이며, 이 문서에서 실행한 결과는 아닙니다.

```bat
mkdir C:\test
cd /d C:\test
echo 안녕하세요. 샘플 파일입니다.>샘플.txt
dir
type 샘플.txt
```

1. `C:\test` 폴더를 만듭니다.
2. 해당 폴더로 이동합니다.
3. 문장이 들어 있는 `샘플.txt`를 만듭니다.
4. 폴더의 파일 목록을 확인합니다.
5. 파일 안의 내용을 확인합니다.

`>`는 같은 이름의 파일이 있으면 내용을 덮어씁니다. `>>`는 기존 내용 뒤에 추가합니다. 경로에 공백이 있으면 `cd /d "C:\My Folder"`처럼 큰따옴표로 감쌉니다.

### 와일드카드: 여러 파일을 한꺼번에 지정하기

`*`는 파일 이름에서 여러 문자를 대신하는 기호입니다.

```bat
dir *.jpg
dir *.txt
```

- `*.jpg`: 이름이 무엇이든 `.jpg`로 끝나는 파일
- `*.txt`: 이름이 무엇이든 `.txt`로 끝나는 파일

이 명령은 **이름의 확장자**를 기준으로 목록을 찾습니다. 파일 내부가 실제 JPG인지 검사하는 것은 아닙니다.

### `/`가 들어가는 명령은 무엇일까?

`/`의 의미는 사용하는 프로그램에 따라 다릅니다.

| 구분 | 예시 | 의미 |
| --- | --- | --- |
| CMD 명령어 옵션 | `dir /b` | 파일·폴더 이름 위주로 간단히 표시 |
| CMD 명령어 옵션 | `dir /s` | 하위 폴더까지 포함하여 조회 |
| CMD 도움말 | `dir /?` | `dir` 사용법 확인 |
| CMD 이동 옵션 | `cd /d C:\test` | 드라이브와 폴더를 함께 변경 |
| AI 도구의 슬래시 명령 | 입력창에서 `/`로 시작하는 메뉴·명령 | 도구가 제공하는 전용 기능 호출 |

AI 도구의 슬래시 명령은 제품과 버전에 따라 다릅니다. 원문에는 대상 도구가 명시되지 않았으므로 특정 도구의 명령어 목록은 확정하지 않았습니다.

## 5. 생성형 AI: 질문에서 실행까지

### 질문·설계와 구현을 나누어 생각하기

강의 메모의 “생각하고 물어보는 것은 ChatGPT, 실제로 만드는 것은 Claude”는 **도구를 나누어 활용하는 개인적인 작업 방식**으로 이해하면 됩니다. 제품의 기능을 구분하는 절대적인 규칙은 아닙니다.

핵심은 제품 이름보다 **어떤 도구와 실행 환경이 연결되어 있는가**입니다.

| 사용 방식 | 주로 하는 일 | 확인할 점 |
| --- | --- | --- |
| 대화 중심 AI | 개념 설명, 기획, 코드 초안, 검토 | 코드 작성과 실제 실행은 구분해야 함 |
| 도구가 연결된 AI | 제공된 파일 분석, 연결된 환경에서 작업 | 연결된 도구와 권한에 따라 가능 범위가 다름 |
| 코딩 에이전트 | 코드 수정, 명령 실행, 오류 확인, 재작업 | 접근 가능한 프로젝트와 실행 환경이 필요함 |

웹 화면에서 사용한다고 실행이 항상 불가능한 것은 아닙니다. 반대로 코딩 에이전트라고 해서 내 PC의 모든 파일에 자동으로 접근하는 것도 아닙니다. **현재 연결된 환경과 허용된 권한**을 확인해야 합니다.

### AI 에이전트의 작업 흐름

1. 사용자의 목표를 이해합니다.
2. 작업 계획을 세웁니다.
3. 코드를 작성하거나 파일을 수정합니다.
4. 실행하고 결과를 확인합니다.
5. 오류가 있으면 수정하고 다시 확인합니다.

완료 여부는 “완료했다”는 말만으로 판단하지 말고, 만들어진 파일과 실행 결과로 확인합니다.

## 6. 좋은 프롬프트: 대상·목표·결과물을 명확하게

### 설명받을 사람의 수준 지정하기

> 나는 비전공자야. 컴퓨터를 처음 배우는 할머니에게 설명하듯이, 어려운 말은 풀어서 설명해 줘.

이 표현은 설명 대상과 난이도를 지정합니다. “당신은 컴퓨터 기초 강사입니다”처럼 AI의 역할을 지정하는 페르소나 설정과 함께 사용할 수 있습니다.

### 큰 주제에서 작은 작업으로 나누기

1. “이미지 파일을 배우기 위한 큰 주제를 나눠 줘.”
2. “첫 번째 주제인 픽셀을 쉽게 설명해 줘.”
3. “일상생활 비유와 예시를 추가해 줘.”
4. “배운 내용을 표로 정리해 줘.”
5. “전체 내용을 하나의 마크다운 문서로 합쳐 줘.”

### 재사용하기 좋은 요청 틀

```text
대상: 컴퓨터 기초를 배우는 비전공자
목표: 이미지 파일 형식의 차이를 이해하기
범위: JPG, PNG, GIF, WebP, SVG
설명 방식: 쉬운 비유와 비교표 사용
결과물: 마크다운 문서
확인 사항: 확실하지 않은 내용은 구분해서 표시
```

작업을 나누면 검토와 수정이 쉬워집니다. 다만 같은 자료를 매번 반복해서 입력하면 전체 토큰 사용량이 늘 수 있으므로, 분할 자체가 항상 비용 절약을 보장하지는 않습니다.

## 7. 컨텍스트·토큰·비용 관리

| 용어 | 쉬운 설명 |
| --- | --- |
| 토큰 | AI가 글 등을 처리할 때 사용하는 작은 단위. 글자 수와 정확히 같지는 않음 |
| 컨텍스트 | AI가 현재 답변을 만들 때 참고하는 정보 |
| 컨텍스트 창 | 한 번에 다룰 수 있는 정보량의 한계 |
| 출력 한도 | 한 번의 응답에서 생성할 수 있는 최대 분량 |

컨텍스트에는 지시사항, 대화 기록, 참고 문서, 도구 결과 등이 포함될 수 있습니다. 컨텍스트 창과 최대 출력량은 같은 개념이 아니며 모델과 서비스에 따라 제한 방식이 다릅니다.

### 효율적으로 사용하는 방법

- 필요한 자료와 목표를 먼저 정합니다.
- 큰 작업은 의미 있는 단위로 나눕니다.
- 원하는 형식과 분량을 처음부터 지정합니다.
- 간단한 명령은 직접 입력할 수 있도록 익힙니다.
- 반복 지시는 문서로 정리해 재사용합니다.
- 긴 작업은 현재 상태와 결정 사항을 짧게 정리합니다.

`dir`처럼 간단한 조회는 직접 실행하면 AI 호출을 줄일 수 있습니다. 복잡한 분석이나 여러 단계의 작업은 AI가 시간을 더 많이 절약해 줄 수 있습니다.

**비용은 요금만이 아니라 결과 품질, 작업 시간, 검증·수정 시간까지 함께 판단합니다.** 구독형 서비스의 사용 한도와 API의 토큰 과금도 구분해야 합니다.

## 8. 이미지 기초: 비트맵과 벡터

| 구분 | 비트맵(래스터) | 벡터 |
| --- | --- | --- |
| 구성 | 작은 색상 점인 픽셀 | 점·선·도형의 위치와 계산 정보 |
| 확대 | 확대하면 픽셀이 드러날 수 있음 | 벡터 도형은 확대해도 선명함 |
| 적합한 자료 | 사진, 복잡한 색감 | 로고, 아이콘, 도형 |
| 대표 형식 | JPG, PNG, GIF, WebP | SVG, AI 등 |
| 프로그램 예시 | Photoshop | Illustrator |

- **비트맵**: 색종이 조각을 촘촘히 붙여 만든 그림과 비슷합니다.
- **벡터**: “여기에 원을 이 크기로 그려라”라는 설계도와 비슷합니다.

벡터 파일 안에도 비트맵 사진이 포함될 수 있으며, 그 사진까지 무한히 선명해지는 것은 아닙니다.

### 픽셀 수 계산

`4000 × 900` 이미지의 전체 픽셀 수는 다음과 같습니다.

```text
4,000 × 900 = 3,600,000픽셀 = 360만 픽셀
```

픽셀 수만으로 저장 파일의 용량이 정해지지는 않습니다. 색상 정보, 압축 방식, 이미지 내용 등이 함께 영향을 줍니다.

### RGB와 알파 채널

| 기호 | 의미 |
| --- | --- |
| R | 빨강(Red) |
| G | 초록(Green) |
| B | 파랑(Blue) |
| A | 투명도(Alpha) |

화면에서는 빨강·초록·파랑의 빛을 섞어 색을 표현합니다. 여기에 투명도 정보를 더한 표현이 RGBA입니다. PNG는 투명도를 저장할 수 있지만 모든 PNG가 반드시 RGBA인 것은 아닙니다.

## 9. 이미지 형식과 실제 파일 확인

### 주요 형식 비교

| 형식 | 주요 특징 | 적합한 용도 |
| --- | --- | --- |
| JPG·JPEG | 일반적으로 손실 압축 사용, 투명 배경 미지원 | 사진 |
| PNG | 무손실 압축, 투명도 지원 | 화면 캡처, 투명 배경 이미지 |
| GIF | 프레임당 제한된 색상, 애니메이션 지원 | 단순한 짧은 움직임 |
| WebP | 손실·무손실 압축, 투명도·애니메이션 지원 | 웹용 이미지 |
| SVG | 벡터 도형을 표현하는 텍스트 기반 형식 | 로고, 아이콘 |
| WMF | Windows 메타파일, 벡터와 비트맵 요소를 포함할 수 있음 | 기존 Office 도형·클립아트 |

**손실 압축**은 일부 정보를 버려 용량을 줄이는 방식이고, **무손실 압축**은 압축 과정에서 원래의 이미지 정보를 잃지 않는 방식입니다.

PNG가 항상 JPG보다 큰 것은 아닙니다. 사진인지 단순한 도형인지, 어떤 압축 설정을 사용했는지에 따라 달라집니다.

### 확장자와 헤더의 차이

- **확장자**: 파일 이름에 붙은 형식 표시
- **헤더·파일 시그니처**: 파일 내부에서 형식 식별에 활용하는 정보

> 확장자는 겉에 붙인 이름표이고, 헤더는 안쪽에서 확인하는 단서입니다.

`photo.png`를 `photo.jpg`로 이름만 바꾸어도 실제 JPEG로 변환되지는 않습니다. 형식을 바꾸려면 프로그램에서 변환하거나 내보내야 합니다.

### 깨진 파일도 형식을 알 수 있을까?

파일의 시작 부분이나 내부 구조가 남아 있으면 실제 형식을 추정하거나 식별할 수 있습니다. 다만 다음은 구분해야 합니다.

- 확장자가 틀린 것인지, 내부 데이터가 손상된 것인지
- 파일 형식을 알아낸 것인지, 이미지 복구까지 성공한 것인지
- 시그니처만 확인한 것인지, 실제로 파일을 읽는 데 성공한 것인지

헤더까지 손상되면 형식을 확정하기 어려울 수 있습니다. 또한 모든 형식에 동일한 방식의 고정 시그니처가 있는 것은 아닙니다.

## 10. 마크다운: 구조가 보이는 문서 작성

마크다운은 간단한 기호로 제목, 목록, 강조, 코드 등을 표시하는 문법입니다. 보통 `.md` 확장자로 저장합니다.

### 기본 문법

| 기능 | 문법 예시 |
| --- | --- |
| 큰 제목 | `# 제목` |
| 작은 제목 | `## 소제목` |
| 글머리 목록 | `- 항목` |
| 번호 목록 | `1. 첫 번째 항목` |
| 굵게 | `**중요한 내용**` |
| 인용 | `> 인용문` |
| 한 줄 코드 | 백틱으로 명령어를 감싸기 |
| 코드 블록 | 백틱 3개로 코드의 위아래를 감싸기 |

```markdown
# 이미지 학습 노트

## 오늘 배운 내용

- JPG는 사진에 많이 사용한다.
- PNG는 투명 배경을 저장할 수 있다.

**확장자 변경과 파일 변환은 다르다.**
```

마크다운 파일도 기본적으로 텍스트입니다. 제목이나 표처럼 보이는 것은 **뷰어가 문법을 해석해서 표시하기 때문**입니다. 확장자만 바꾼다고 모든 프로그램에서 자동으로 서식이 적용되는 것은 아닙니다.

### AI 작업에 유용한 이유

- 지시사항과 참고자료를 구분하기 쉽습니다.
- 긴 내용을 제목과 항목으로 나눌 수 있습니다.
- 작업 지시를 파일로 보관하고 재사용할 수 있습니다.
- Git으로 변경 사항을 비교하기 좋습니다.
- 검색용 문서를 정리할 때 구조를 활용할 수 있습니다.

### `.md` 파일은 실행 파일이 아니다

“`wallpaper_report.md` 실행”은 일반적으로 **AI가 문서를 읽고 그 안의 지시에 따라 작업하라**는 뜻으로 해석해야 합니다. 운영체제가 마크다운 문서를 프로그램처럼 직접 실행하는 것은 아닙니다.

더 명확한 요청은 다음과 같습니다.

> `wallpaper_report.md`를 읽고, 그 안에 적힌 절차대로 작업해 줘. 결과 파일과 확인한 내용을 알려 줘.

문서를 읽는 데에도 토큰이 사용됩니다. 마크다운의 주된 이점은 **지시의 일관성과 재사용성**입니다.

### 마크다운 뷰어 실습

강의에서 다룬 제작 요청:

> 마크다운 뷰어를 HTML로 만들어 줘. 왼쪽은 마크다운 입력창, 오른쪽은 서식이 적용된 결과 화면으로 구성해 줘.

이 실습은 AI에게 화면 구성과 기능을 설명하고, 만들어진 결과를 열어 확인하는 연습입니다.

## 11. Git·GitHub와 포트폴리오

| 도구 | 역할 |
| --- | --- |
| Git | 파일 변경 이력을 기록하는 버전 관리 도구 |
| GitHub | Git 저장소를 온라인에서 공유하고 협업하는 서비스 |
| 블로그 | 배운 내용과 문제 해결 과정을 설명하는 공간 |

### 기록하면 좋은 내용

- 프로젝트를 만든 목적
- 사용한 데이터와 도구
- 실행 방법
- 발생한 오류와 해결 과정
- 결과 화면과 분석 내용
- 한계와 다음 개선 사항

활동 횟수만 늘리기보다 **어떤 문제를 어떻게 해결했는지 설명할 수 있는 기록**이 중요합니다. 다른 사람의 프로젝트를 참고했다면 출처와 자신이 바꾼 부분을 구분합니다.

## 12. RAG: 자료를 찾아보고 답하는 AI

RAG는 Retrieval-Augmented Generation의 약자로, **관련 자료를 검색한 뒤 그 자료를 참고해 답변을 생성하는 방식**입니다.

책을 외워서만 답하는 대신 필요한 부분을 찾아보며 답하는 방식에 비유할 수 있습니다.

### 기본 흐름

1. 사용자가 질문합니다.
2. 시스템이 관련 문서나 문단을 검색합니다.
3. 검색한 내용을 AI에게 참고자료로 제공합니다.
4. AI가 참고자료에 근거해 답변합니다.
5. 출처와 답변의 정확성을 확인합니다.

### 예시: 마우스 설명서 비교

“민첩성이 가장 좋은 마우스는?”은 기준이 모호합니다. 다음처럼 비교 기준을 구체화하면 좋습니다.

> 세 제품의 설명서에서 무게와 폴링레이트를 찾아 비교해 줘. 설명서에 없는 수치는 ‘확인 불가’로 표시하고, 근거 위치도 알려 줘.

검색한 자료에 없는 내용을 확정하지 않는 것이 중요합니다. RAG도 검색이 잘못되거나 문서가 오래되면 부정확한 답을 만들 수 있습니다.

### RAG와 보안

RAG를 쓴다고 자료가 자동으로 외부에 나가지 않는 것은 아닙니다. 문서 저장 위치, 검색 시스템, 모델 실행 위치, 외부 전송 여부, 접근 권한을 어떻게 설계했는지에 따라 달라집니다.

### RAG 엔지니어의 주요 업무

- 문서를 수집하고 읽기 좋은 형태로 정리하기
- 문서를 검색에 적합한 단위로 나누기
- 검색 시스템 구축과 개선
- 검색 결과와 답변 품질 평가
- 문서별 접근 권한 관리
- 변경된 자료를 갱신하고 서비스 운영하기

RAG는 문서를 검색해 참고하는 방식이며, 문서를 이용해 모델 자체를 추가 학습시키는 것과는 구분됩니다.

## 13. 스팀 데이터 분석: 실습 주제로 연결하기

원문에는 **“스팀데이터 분석”이라는 주제만 있고 데이터나 분석 결과는 없습니다.** 아래는 강의 내용을 적용할 수 있도록 보완한 실습 구성 예시입니다.

### 분석 질문 예시

- 장르별 게임 수는 얼마나 다른가?
- 가격대별 사용자 평가 비율은 어떻게 다른가?
- 출시 시기별 게임 수는 어떻게 변했는가?

### 진행 순서

1. 분석할 질문을 하나 정합니다.
2. 데이터 출처, 수집 시점, 포함 항목을 확인합니다.
3. 누락값·중복·잘못된 숫자를 정리합니다.
4. 필요한 항목을 집계하고 비교합니다.
5. 표나 그래프로 결과를 확인합니다.
6. 결과와 한계를 마크다운 보고서로 작성합니다.
7. 코드와 실행 방법을 GitHub에 기록합니다.

가격은 통화·지역·할인 시점의 영향을 받고, 리뷰 수는 판매량과 같지 않습니다. 데이터에 없는 값을 추측해 결과로 쓰지 않습니다.

## 14. 강의 설명에서 바로잡아 기억할 점

| 단순화된 표현 | 정확하게 이해할 내용 |
| --- | --- |
| 질문은 ChatGPT, 제작은 Claude | 하나의 활용 방식이며 기능을 고정적으로 나누는 규칙은 아님 |
| 웹 AI는 실행 불가, Codex는 내 PC 접근 가능 | 도구 연결, 실행 위치, 권한에 따라 달라짐 |
| `.md` 파일을 실행한다 | AI가 문서를 읽고 지시를 수행하는 것 |
| 마크다운을 쓰면 무조건 토큰 절약 | 재사용에 유리하지만 문서 내용도 토큰으로 처리됨 |
| 작업을 나누면 항상 비용 감소 | 반복 입력과 호출 증가로 비용이 늘 수도 있음 |
| 회사는 싼 AI가 가장 중요 | 품질·시간·운영비용을 함께 평가해야 함 |
| RAG를 쓰면 외부 유출이 없다 | 시스템 구성과 접근 통제가 필요함 |
| 확장자를 바꾸면 형식이 바뀐다 | 내부 형식은 변환 작업을 해야 바뀜 |
| 헤더만 보면 모든 파일을 확정·복구할 수 있다 | 손상 정도와 내부 구조에 따라 다름 |
| PNG는 흰 배경이고 항상 용량이 크다 | 투명도 저장이 가능하며 용량은 내용·설정에 따라 다름 |
| 4000 × 900은 36만 픽셀 | 정확히 360만 픽셀 |
| `cd \`는 언제나 C 드라이브로 이동 | 현재 드라이브의 루트로 이동. C로 바꾸려면 `cd /d C:\` |
