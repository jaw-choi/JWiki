# 2026-09-28 네트워크 / Packet Tracer 수업 정리

## 1. 오늘 수업의 핵심

오늘 수업에서 가장 중요한 판단 기준은 다음 한 문장으로 정리할 수 있다.

> **목적지가 같은 네트워크에 있으면 상대방의 MAC 주소를 찾아 직접 전달하고, 다른 네트워크에 있으면 게이트웨이의 MAC 주소를 찾아 라우터를 통해 전달한다.**

이 판단을 하기 위해 필요한 개념이 다음과 같다.

- IP 주소
- 서브넷 마스크 / CIDR
- MAC 주소
- ARP
- L2 스위치
- 라우터 / L3
- 게이트웨이
- ICMP / Ping
- VLAN
- 정적 / 동적 라우팅
- 방화벽

---

## 2. IP 주소와 서브넷

### IP 주소

IP 주소는 네트워크에서 장치를 구분하기 위한 **논리적 주소**이다.

예:

```text
192.168.10.2
```

IP 주소만 보고 통신하는 것처럼 보이지만, 같은 네트워크 안에서 실제 이더넷 프레임을 전달할 때는 **MAC 주소**가 필요하다.

---

### 서브넷 마스크

서브넷 마스크는 IP 주소에서

- 어디까지가 네트워크 부분인지
- 어디부터가 호스트 부분인지

를 구분한다.

예:

```text
192.168.10.2/24
```

`/24`는 앞의 24비트가 네트워크 부분이라는 뜻이다.

```text
192.168.10.xxx
^^^^^^^^^^^
네트워크 부분
```

따라서 다음 주소는 같은 `/24` 네트워크이다.

```text
192.168.10.2
192.168.10.3
192.168.10.100
```

반면 다음은 서로 다른 네트워크이다.

```text
192.168.10.2/24
192.168.20.2/24
```

---

## 3. 같은 네트워크와 다른 네트워크

### 같은 네트워크

예:

```text
PC0: 192.168.10.2/24
PC1: 192.168.10.3/24
```

둘은 같은 네트워크에 있으므로 라우터를 거칠 필요가 없다.

통신 흐름은 대략 다음과 같다.

```text
PC0
 ↓
ARP로 PC1의 MAC 주소 확인
 ↓
L2 스위치
 ↓
PC1
```

핵심은 **상대 PC의 MAC 주소를 알아내는 것**이다.

---

### 다른 네트워크

예:

```text
PC0: 192.168.10.2/24
PC1: 192.168.20.2/24
```

둘은 서로 다른 네트워크이다.

이 경우 PC0는 PC1의 MAC 주소를 직접 찾는 것이 아니라 먼저 **기본 게이트웨이의 MAC 주소**를 찾는다.

```text
PC0
 ↓
게이트웨이 MAC 확인
 ↓
스위치
 ↓
라우터
 ↓
다른 네트워크
 ↓
스위치
 ↓
PC1
```

즉,

```text
같은 네트워크 → 목적지 MAC
다른 네트워크 → 게이트웨이 MAC
```

으로 기억하면 된다.

---

## 4. MAC 주소

MAC 주소는 데이터 링크 계층(L2)에서 사용하는 주소이다.

예:

```text
00:1A:2B:3C:4D:5E
```

같은 네트워크 안에서 실제 프레임을 전달할 때는 IP 주소가 아니라 MAC 주소가 필요하다.

또한 라우터를 여러 번 거치면 각 구간마다 Ethernet 프레임이 새로 만들어지기 때문에 **출발지와 목적지 MAC 주소는 홉마다 달라질 수 있다.**

반면 최종 목적지 IP는 일반적인 통신에서는 목적지까지 유지된다.

---

## 5. ARP

ARP(Address Resolution Protocol)는

```text
IP 주소 → MAC 주소
```

를 알아내기 위한 프로토콜이다.

예를 들어 PC0가 다음 장비로 보내고 싶다고 하자.

```text
192.168.10.3
```

하지만 MAC 주소를 모른다면 ARP 요청을 보낸다.

### ARP Request

ARP 요청은 **브로드캐스트**이다.

의미:

```text
"192.168.10.3 사용하는 장비 누구야?
네 MAC 주소 알려줘."
```

같은 네트워크의 모든 장비가 요청을 받는다.

---

### ARP Reply

해당 IP를 가진 장비만 응답한다.

응답은 일반적으로 **유니캐스트**로 전달된다.

```text
"내가 192.168.10.3이야.
내 MAC 주소는 XX:XX:XX:XX:XX:XX야."
```

그 결과 PC에는 ARP 테이블이 만들어진다.

확인 명령:

```bash
arp -a
```

---

## 6. 브로드캐스트와 유니캐스트

### 브로드캐스트

같은 네트워크 안의 모든 장비에게 전달한다.

ARP Request가 대표적인 예이다.

```text
한 장비 → 전체 장비
```

---

### 유니캐스트

특정 한 장비에게만 전달한다.

ARP Reply가 대표적인 예이다.

```text
한 장비 → 특정 장비
```

---

## 7. L2 스위치

L2 스위치는 OSI 2계층인 **데이터 링크 계층**에서 동작한다.

주요 판단 기준:

```text
MAC 주소
```

스위치는 자신이 학습한 MAC 주소와 포트의 관계를 MAC Address Table에 저장한다.

예:

```text
MAC 주소                포트
AA:AA:AA:AA:AA:01       Fa0/1
AA:AA:AA:AA:AA:02       Fa0/2
```

Packet Tracer 스위치 CLI에서 확인할 수 있다.

```text
enable
show mac address-table
```

통신 전에는 비어 있을 수 있지만, Ping 등을 수행하면 MAC 주소가 학습된다.

---

## 8. 허브와 스위치 차이

### 허브

받은 데이터를 연결된 여러 장비에 그대로 전달한다.

```text
입력
 ↓
모든 포트로 전달
```

### 스위치

MAC Address Table을 이용하여 필요한 포트로 전달한다.

```text
입력
 ↓
MAC 확인
 ↓
필요한 포트로 전달
```

따라서 스위치가 허브보다 효율적으로 트래픽을 전달할 수 있다.

---

## 9. L3와 라우터

라우터는 OSI 3계층인 **네트워크 계층**에서 동작한다.

주요 판단 기준:

```text
IP 주소
```

라우터의 역할은

```text
패킷을 어느 네트워크로 보낼지 결정
```

하는 것이다.

서로 다른 네트워크 사이를 연결하려면 라우터가 필요하다.

---

## 10. 기본 게이트웨이

기본 게이트웨이는

```text
"내 네트워크 밖으로 나갈 때 먼저 보내는 장비"
```

라고 이해하면 된다.

예:

```text
PC
IP: 192.168.10.2
Mask: 255.255.255.0
Gateway: 192.168.10.1
```

PC가 `192.168.20.2`로 데이터를 보내려면 같은 네트워크가 아니므로 먼저

```text
192.168.10.1
```

의 MAC 주소를 알아낸 후 게이트웨이로 프레임을 보낸다.

게이트웨이를 잘못 설정하면 외부 네트워크로 패킷을 전달할 수 없다.

---

## 11. Ping과 ICMP

`ping`은 네트워크 연결 상태를 확인하는 가장 기본적인 명령이다.

예:

```bash
ping 203.230.7.2
```

Ping에서는 ICMP 프로토콜이 사용된다.

대표적인 흐름:

```text
ICMP Echo Request
        ↓
상대방
        ↓
ICMP Echo Reply
```

즉,

```text
"너 연결돼 있어?"
"응, 연결돼 있어."
```

를 확인하는 과정이라고 이해하면 된다.

---

## 12. TTL

TTL(Time To Live)은 패킷이 네트워크 안에서 무한히 돌지 못하게 하는 값이다.

라우터를 거칠 때 일반적으로 TTL이 1씩 감소한다.

```text
TTL 64
 ↓
TTL 63
 ↓
TTL 62
 ↓
...
```

TTL이 0이 되면 패킷은 폐기된다.

이를 통해 라우팅 오류 등으로 발생할 수 있는 무한 루프를 방지한다.

# Packet Tracer 실습

## 13. Packet Tracer란?

Cisco Packet Tracer는 네트워크를 직접 구성하고 통신 과정을 시뮬레이션하는 프로그램이다.

직접 배치할 수 있는 장비 예:

- PC
- Server
- Switch
- Router
- IoT 장비

장비를 드래그해서 배치하고 케이블로 연결한 뒤 IP를 설정하여 실제 네트워크처럼 실습할 수 있다.

---

## 14. Wireshark와 Packet Tracer 차이

### Packet Tracer

네트워크 자체를 가상으로 구성하고 실험한다.

```text
PC ─ Switch ─ Router ─ Switch ─ PC
```

주요 목적:

- 네트워크 구성
- 장비 설정
- 패킷 이동 확인
- 장애 상황 실습

### Wireshark

실제 네트워크에서 오가는 패킷 내부를 분석한다.

주요 목적:

- 패킷 캡처
- 프로토콜 분석
- 헤더 확인
- 장애 분석

정리:

```text
Packet Tracer = 네트워크 구성 및 시뮬레이션
Wireshark     = 실제 패킷 상세 분석
```

---

## 15. Packet Tracer 같은 네트워크 실습

예시 주소:

```text
PC0    203.230.7.1/24
Server 203.230.7.2/24
```

둘은 같은 `/24` 네트워크이다.

따라서 기본 게이트웨이가 없어도 서로 직접 통신할 수 있다.

확인:

```bash
ping 203.230.7.2
```

## 16. 정적 IP 설정

오늘 실습에서는 DHCP가 아니라 직접 IP를 입력하는 **정적 IP 방식**을 사용하였다.

Packet Tracer:

```text
PC 클릭
→ Desktop
→ IP Configuration
→ IP 주소 직접 입력
```

예:

```text
IP Address: 203.230.7.1
Subnet Mask: 255.255.255.0
```

서버:

```text
203.230.7.2
```

이처럼 사람이 직접 IP를 넣는 방법이 정적 IP 할당이다.

## 17. L2 스위치 2960 실습

같은 네트워크의 여러 PC를 연결할 때 Cisco 2960 L2 스위치를 사용할 수 있다.

구조:

```text
PC0
     Switch 2960
  /
PC1
```

두 PC를 같은 네트워크로 설정한다.

예:

```text
PC0: 203.230.7.1/24
PC1: 203.230.7.2/24
```

그 뒤 Ping을 수행한다.

---

## 18. Ping 전후 ARP 테이블 확인

Ping 전에:

```bash
arp -a
```

ARP 정보가 없을 수 있다.

Ping 실행:

```bash
ping 203.230.7.2
```

Ping 이후:

```bash
arp -a
```

상대방의 IP와 MAC 주소가 ARP 테이블에 등록된다.

즉 Ping을 수행하는 과정에서 먼저 필요한 ARP 통신이 발생할 수 있다.

---

## 19. 스위치 MAC Address Table 확인

스위치 CLI:

```text
enable
show mac address-table
```

통신 전에는 항목이 없을 수 있다.

하지만 PC 사이에 Ping을 보내면 스위치가 각 장비의 MAC 주소가 어느 포트에 연결되어 있는지 학습한다.

---

## 20. Simulation Mode

Packet Tracer의 Simulation Mode를 사용하면 패킷이 이동하는 과정을 단계별로 볼 수 있다.

오늘 확인한 주요 프로토콜:

```text
ARP
ICMP
```

### ARP

IP 주소에 해당하는 MAC 주소를 찾는다.

### ICMP

Ping 요청과 응답을 처리한다.

Simulation Mode에서는 봉투 모양의 패킷을 클릭하여 계층별 정보를 확인할 수 있다.

이를 통해

```text
PC → Switch → PC
```

형태로 패킷이 이동하는 과정을 직접 볼 수 있다.

# 추가 네트워크 개념

## 21. 캡슐화

데이터가 네트워크 계층을 내려가면서 각 계층에 필요한 헤더 정보가 추가되는 것을 **캡슐화**라고 한다.

예를 들어 단순히

```text
안녕
```

이라는 데이터를 보낸다고 해도 실제 네트워크에서는 여러 정보가 붙는다.

개념적으로:

```text
Data
 ↓
TCP/UDP Header + Data
 ↓
IP Header + TCP/UDP Header + Data
 ↓
Ethernet Header + IP Header + ...
```

각 계층의 통신에 필요한 정보가 차례로 추가된다.

---

## 22. VLAN

VLAN은 Virtual LAN의 약자이다.

하나의 물리적인 스위치를 논리적으로 여러 개의 네트워크처럼 나누는 기술이다.

예:

```text
Switch
 ├─ VLAN 10 : 개발팀
 └─ VLAN 20 : 영업팀
```

물리적으로 같은 스위치에 연결되어 있어도 VLAN이 다르면 서로 다른 네트워크처럼 분리할 수 있다.

같은 VLAN끼리는 L2 스위칭이 가능하다.

서로 다른 VLAN끼리 통신하려면 L3 장비나 라우팅 기능이 필요하다.

---

## 23. VLAN을 사용하는 이유

예를 들어 회사에 다음 두 부서가 있다고 하자.

```text
개발팀
영업팀
```

모두 같은 스위치에 연결되어 있더라도 VLAN을 사용하면 네트워크를 논리적으로 분리할 수 있다.

장점:

- 부서별 네트워크 분리
- 브로드캐스트 영역 분리
- 보안 향상
- 관리 편의성 향상

---

## 24. 라우팅

라우팅은 패킷을 어느 경로로 보낼지 결정하는 과정이다.

크게 두 가지가 있다.

### 정적 라우팅

관리자가 경로를 직접 설정한다.

예:

```text
ip route ...
```

장점:

- 단순함
- 예측 가능
- 자원 사용량이 적음

단점:

- 장애 발생 시 자동으로 우회하지 못함
- 큰 네트워크에서는 관리가 어려움

주로 작은 네트워크에서 사용한다.

---

### 동적 라우팅

라우터끼리 정보를 교환하면서 경로를 자동으로 결정한다.

대표적인 프로토콜:

- RIP
- OSPF
- BGP

장점:

- 네트워크 변화에 자동 대응
- 장애 발생 시 다른 경로 선택 가능

단점:

- 설정과 동작이 복잡함
- 추가적인 자원이 필요함

주로 크고 복잡한 네트워크에서 사용한다.

---

## 25. 방화벽

방화벽은 허용되지 않은 네트워크 통신을 차단하는 보안 장치 또는 기능이다.

일반적으로 다음 정보를 기준으로 제어할 수 있다.

### L3

```text
IP 주소
```

### L4

```text
TCP / UDP 포트
```

예:

```text
TCP 22번 포트 차단
```

SSH 접근을 막는 것과 연결될 수 있다.

현대의 방화벽은 애플리케이션 계층(L7)의 내용까지 분석하는 경우도 있다.

---

## 26. 네트워크 장애 시 확인 순서

통신이 안 될 때 무작정 프로그램부터 의심하지 말고 아래 순서대로 확인하는 것이 좋다.

### 1단계. 내 IP 확인

```bash
ipconfig
```

또는 Linux:

```bash
ip addr
```

---

### 2단계. 서브넷 확인

목적지가 같은 네트워크인지 다른 네트워크인지 판단한다.

---

### 3단계. 게이트웨이 확인

다른 네트워크라면 기본 게이트웨이가 올바르게 설정되어 있는지 확인한다.

---

### 4단계. ARP 확인

```bash
arp -a
```

목적지 또는 게이트웨이의 MAC 주소를 정상적으로 찾았는지 확인한다.

---

### 5단계. Ping 확인

```bash
ping <IP>
```

ICMP 응답 여부를 확인한다.

---

### 6단계. 스위치 MAC Table 확인

Packet Tracer에서는:

```text
show mac address-table
```

---

### 7단계. 라우팅 확인

서로 다른 네트워크라면 라우터가 목적지 네트워크로 가는 경로를 알고 있는지 확인한다.

---

### 8단계. 방화벽 확인

IP나 포트가 차단되어 있지 않은지 확인한다.

# 클라우드와 연결해서 이해하기

## 27. 클라우드에서도 같은 원리 사용

AWS 같은 클라우드 환경에서도 기본적인 네트워크 원리는 동일하다.

중요한 개념:

- CIDR
- Subnet
- Route Table
- Internet Gateway
- Public Network
- Private Network
- Firewall / Security Rule

특히 클라우드에서는 사용자가 실제 물리 네트워크 장비를 직접 다루기보다 논리적인 네트워크 설정을 많이 다룬다.

---

## 28. Public / Private 네트워크

### Public

외부 인터넷에서 접근할 수 있도록 구성된 네트워크.

예:

```text
웹 서버
```

### Private

외부 인터넷에서 직접 접근하지 못하도록 구성된 네트워크.

예:

```text
DB 서버
```

일반적으로 DB 서버를 인터넷에 직접 노출하지 않고 웹 서버나 애플리케이션 서버를 통해 접근하도록 구성한다.

# 오늘 반드시 기억할 핵심 10개

1. **IP는 논리 주소, MAC은 L2에서 실제 프레임 전달에 사용되는 주소다.**
2. **서브넷 마스크는 같은 네트워크인지 판단하는 기준이다.**
3. **같은 네트워크에서는 상대방 MAC 주소를 찾는다.**
4. **다른 네트워크에서는 기본 게이트웨이의 MAC 주소를 찾는다.**
5. **ARP는 IP 주소를 이용해 MAC 주소를 알아내는 과정이다.**
6. **ARP Request는 브로드캐스트, ARP Reply는 일반적으로 유니캐스트다.**
7. **L2 스위치는 MAC 주소를 기준으로 전달한다.**
8. **라우터는 L3에서 IP 주소를 기준으로 다른 네트워크를 연결한다.**
9. **Ping은 ICMP를 이용해 통신 가능 여부를 확인한다.**
10. **Packet Tracer에서는 이 과정을 Simulation Mode로 직접 확인할 수 있다.**

# 한 줄 흐름으로 최종 정리

```text
목적지 IP 확인
    ↓
서브넷 마스크로 같은 네트워크인지 판단
    ↓
┌──────────────────────┬────────────────────────┐
│ 같은 네트워크         │ 다른 네트워크           │
├──────────────────────┼────────────────────────┤
│ 상대 IP의 MAC 조회    │ 게이트웨이 MAC 조회      │
│ ARP 사용             │ ARP 사용                 │
│ L2 스위치로 전달      │ 게이트웨이로 전달         │
│                      │ 라우터가 다음 경로 결정    │
└──────────────────────┴────────────────────────┘
    ↓
ICMP Ping 등으로 통신 확인
```

이 흐름을 이해하면 오늘 배운 ARP, 스위치, 라우터, 게이트웨이, VLAN, Packet Tracer 실습 내용을 하나의 구조로 연결해서 이해할 수 있다.
