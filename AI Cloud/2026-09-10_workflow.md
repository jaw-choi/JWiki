이 대화에서는 공공데이터포털 API를 Python으로 호출하고, 결과를 `pandas DataFrame`으로 정리한 뒤 CSV와 HTML로 저장하는 자동화 흐름을 설계했다.

- pandas DataFrame 변환
- CSV 저장
- HTML 생성
- 오류 로그
- 재시도
- Codex를 이용한 자동복구

```text

getStrtpntAlocFndTrainInfo
```

초기에는 다음 두 기능을 분리해서 작성했다.

1. 역 코드 조회

결과는 `pandas DataFrame`으로 정리하고, API 오류 응답은 원문 그대로 출력하도록 했다.

## 3. 인증키 처리 방식

처음에는 `.env`에서 인증키를 읽도록 설계했으나 이후 요구에 따라 인증키를 Python 코드 안에 직접 넣는 방식으로 변경했다.

사용자가 제공한 키는 URL Encoding 상태이므로 코드에서는 다음 방식으로 처리하도록 했다.

```python
from urllib.parse import unquote

SERVICE_KEY = unquote("인증키")
```

> 보안상 본 요약 문서에는 실제 인증키 값을 다시 기록하지 않는다.

## 8. API Retry 워크플로우

API 호출은 최초 1회 + 재시도 2회 구조로 설계했다.

```text
API 호출
 ↓
실패
 ↓
재시도 1
 ↓
실패
 ↓
재시도 2
 ↓
실패
 ↓
해당 작업 SKIP
```

예를 들어 7일 × 2방향이면 총 14개 조회 작업을 만들고, 일부 조회 실패가 전체 실행 중단으로 이어지지 않도록 했다.

## 9. 데이터 검증 워크플로우

HTTP 200만으로 성공 처리하지 않고 JSON 구조도 확인하도록 했다.

```text
response 존재?
↓
body 존재?
↓
items 존재?
↓
item 존재?
↓
필수 데이터 존재?
```

정상이면 DataFrame으로 넘기고, 비정상이면 로그/재시도 처리한다.

## 12. Codex 자동복구 정책

PowerShell이 Python 실행 실패를 감지하면 Codex CLI를 자동 실행하도록 기획했다.

흐름:

```text
run_train_api.ps1
  ↓
train_api.py 실행
  ↓
오류
  ↓
error.log 기록
  ↓
Codex CLI 실행
  ↓
TASK.md + 최근 오류 확인
  ↓
최소 수정
  ↓
기존 파일 덮어쓰기
  ↓
재실행
```

### 수정 허용 범위
- Python 파일
- PowerShell 파일

### 수정 원칙
- 오류와 직접 관련된 부분만 수정
- 새 파일 남발 금지
- 불필요한 패키지 설치 금지
- 정상 코드 유지
- 기존 파일 직접 덮어쓰기
- 수정 후 재실행 및 검증

### 자동복구 제한

```text
최초 실행
 ↓
실패
 ↓
Codex 수정 #1
 ↓
재실행
 ↓
실패
 ↓
Codex 수정 #2
 ↓
재실행
 ↓
그래도 실패하면 STOP
```

최대 2회까지만 자동복구하도록 정했다.

## 16. 공중화장실 API 파이썬 구조

주요 설정 예:

```python
URL = "https://apis.data.go.kr/1741000/public_restroom_info_v2/info_v2"

AREAS = ["서울", "부산"]

ROWS = 100
MAX_PAGES = 50
```

도로명주소 LIKE 검색 조건을 이용해 서울/부산 데이터를 조회하도록 설계했다.

```python
"cond[LCTN_ROAD_NM_ADDR::LIKE]": area
```

## 22. 이 대화에서 정립한 공통 패턴

앞으로 다른 공공데이터 API로 바꿔도 아래 패턴을 재사용할 수 있다.

```text
1. API Endpoint 확인
2. 인증키 설정
3. 조회 조건 정의
4. API 호출
5. Retry
6. JSON 검증
7. DataFrame 변환
8. 필요한 데이터만 정리
9. CSV 저장
10. HTML 생성
11. 결과 검증
12. error.log 누적
13. Codex 자동복구
14. 복구 후 재실행
```

즉 특정 기차 API나 화장실 API에 종속된 방식이 아니라, 다른 공공데이터 API에도 적용 가능한 **API 수집·검증·저장·시각화·자동복구 워크플로우**로 확장했다.
