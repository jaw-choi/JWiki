# 2026-09-18 Linux / Ubuntu 실습 정리

## 오늘 수업의 핵심

오늘 수업은 단순히 Linux 명령어를 외우는 것이 아니라,

> **Windows 안에 Ubuntu 서버를 만들고, 그 서버를 네트워크를 통해 접속·관리하는 기본 구조를 이해하는 것**

이 핵심이었습니다.

전체 흐름은 다음과 같습니다.

```text
Windows PC
   ↓
Hyper-V / Multipass
   ↓
Ubuntu 가상 서버(VM)
   ↓
Linux 명령어로 서버 관리
   ↓
SSH로 원격 접속
   ↓
VS Code에서 원격 개발
```

## 1. Multipass의 Ubuntu는 별도의 컴퓨터처럼 생각한다

Multipass로 만든 Ubuntu 인스턴스는 단순한 폴더가 아니라  
**독립된 서버 한 대**처럼 생각해야 합니다.

예를 들어 내 PC에 Ubuntu 인스턴스를 두 개 만들었다면:

```text
Windows PC
 ├─ Ubuntu A
 │   └─ IP 주소 A
 │
 └─ Ubuntu B
     └─ IP 주소 B
```

A와 B는 같은 PC 안에 있어도 서로 별개의 서버입니다.

따라서 통신하려면 각 서버의 **IP 주소와 네트워크**를 사용해야 합니다.

핵심:

```text
같은 물리 PC 안에 있다
≠
자동으로 같은 컴퓨터처럼 통신한다
```

## 2. Linux에서 가장 먼저 알아야 할 경로

Linux 파일 시스템은 `/`에서 시작하는 트리 구조입니다.

```text
/
├─ home
│   └─ ubuntu
├─ root
├─ bin
├─ usr
├─ boot
├─ tmp
└─ var
```

현재 위치 확인:

```bash
pwd
```

현재 사용자 홈 확인:

```bash
echo $HOME
```

홈으로 이동:

```bash
cd ~
```

핵심 차이:

```text
pwd       = 지금 내가 있는 위치
$HOME     = 내 계정의 기본 홈 위치
```

## 3. root와 sudo

Linux는 사용자 권한을 구분합니다.

```text
일반 사용자
   ↓ 필요할 때
sudo
   ↓
관리자 권한

root
   ↓
시스템 전체 최고 관리자
```

관리자 권한으로 한 명령만 실행:

```bash
sudo 명령어
```

root 환경으로 전환:

```bash
sudo -i
```

종료:

```bash
exit
```

중요한 서버에서는 모든 사용자가 root 권한을 가지는 것이 아니라,  
관리자가 사용자별 계정과 권한을 나누어 관리합니다.

## 5. Linux 권한

권한은 다음 3개로 구성됩니다.

```text
r = read    = 읽기
w = write   = 쓰기
x = execute = 실행
```

숫자로는:

```text
r = 4
w = 2
x = 1
```

따라서:

```text
7 = rwx
6 = rw-
5 = r-x
4 = r--
0 = ---
```

예:

```bash
chmod 644 file.txt
```

의미:

```text
소유자 : 6 = rw-
그룹   : 4 = r--
기타   : 4 = r--
```

대표 예시:

```text
600 = rw- --- ---
644 = rw- r-- r--
750 = rwx r-x ---
755 = rwx r-x r-x
```

---

## 6. SSH 개인키는 권한이 중요하다

SSH 개인키는 다른 사람이 읽을 수 없도록 제한하는 것이 중요합니다.

대표적으로:

```bash
chmod 600 개인키
```

`600`은:

```text
소유자 : 읽기 + 쓰기
그룹   : 권한 없음
기타   : 권한 없음
```

즉 개인키를 **나만 사용할 수 있게 보호**하는 것입니다.

## 8. Pipe와 grep

Pipe `|`는 앞 명령의 결과를 뒤 명령으로 전달합니다.

```bash
명령어1 | 명령어2
```

예:

```bash
ls -l | grep txt
```

흐름:

```text
ls -l 실행
   ↓
출력 결과를 grep으로 전달
   ↓
txt가 포함된 줄만 출력
```

`grep`은 많은 출력 중 원하는 문자열을 찾을 때 매우 자주 사용합니다.

## 9. SSH란?

SSH는

> **네트워크를 통해 다른 컴퓨터의 터미널에 안전하게 접속하는 방법**

입니다.

구조:

```text
내 PC
   ↓ SSH
Ubuntu 서버
   ↓
서버 명령 실행
```

예:

```bash
ssh ubuntu@서버IP
```

즉 지금 Multipass에서 연습하는 SSH 방식은  
나중에 AWS 같은 실제 클라우드 서버에 접속할 때도 그대로 사용됩니다.

---

## 10. SSH 개인키 / 공개키 인증

SSH에서는 비밀번호 대신 **키 인증**을 많이 사용합니다.

구조:

```text
내 PC
└─ 개인키(private key)

Ubuntu 서버
└─ 공개키(public key)
```

두 키가 서로 맞는 한 쌍이면 서버가 인증합니다.

개념적으로:

```text
내가 가진 개인키
       ↓
서버의 공개키와 확인
       ↓
인증 성공
       ↓
SSH 접속 허용
```

중요:

```text
개인키 → 절대 남에게 주면 안 됨
공개키 → 접속 대상 서버에 등록
```

AWS에서도 같은 방식의 SSH 키 인증을 사용합니다.

## 11. Windows에서 SSH 설정

매번 IP와 사용자명, 키 파일을 길게 입력하지 않도록  
Windows의 SSH 설정 파일에 별칭을 등록할 수 있습니다.

파일:

```text
C:\Users\사용자명\.ssh\config
```

예:

```text
Host myubuntu
    HostName 172.23.45.67
    User ubuntu
    IdentityFile ~/.ssh/id_ed25519
```

의미:

```text
Host          = 내가 사용할 서버 별칭
HostName      = 실제 서버 IP
User          = 접속 계정
IdentityFile  = 사용할 개인키
```

이후에는:

```powershell
ssh myubuntu
```

처럼 간단히 접속할 수 있습니다.

---

## 12. IP 주소가 바뀌면 설정도 확인해야 한다

SSH 설정에서:

```text
HostName 172.23.45.67
```

처럼 IP 주소를 직접 적었다면  
Multipass 인스턴스의 IP가 바뀔 경우 접속이 안 될 수 있습니다.

이때는:

```bash
multipass list
```

등으로 현재 IP를 확인하고 SSH 설정의 `HostName`을 수정해야 합니다.

즉:

```text
SSH 설정은 맞는데 접속 안 됨
        ↓
현재 서버 IP 확인
```

도 중요한 점검 순서입니다.

## 13. VS Code와 SSH

서버에서 직접 Vim으로 코드를 작성할 수도 있지만,  
규모가 커지면 불편합니다.

그래서 실제 개발에서는:

```text
내 PC의 VS Code
      ↓ SSH
Ubuntu 서버
      ↓
서버 안의 파일을 VS Code에서 편집
```

하는 방식을 많이 사용합니다.

즉 VS Code의 원격 SSH 기능도 결국 기본은 **SSH 접속**입니다.

오늘 SSH를 배우는 이유가 단순히 터미널 접속 때문만은 아닙니다.

```text
SSH 이해
   ↓
원격 서버 접속
   ↓
VS Code Remote SSH
   ↓
클라우드 서버 개발
```

로 이어집니다.

## 14. 서버 한 대를 여러 사용자가 사용할 수 있다

실제 회사나 HPC 환경에서는 강력한 서버 한 대를  
여러 사용자가 계정별로 나눠 사용할 수 있습니다.

예:

```text
고성능 서버
├─ user1
├─ user2
├─ user3
└─ root
```

각 사용자에게는 다음과 같은 자원을 제한해서 제공할 수도 있습니다.

```text
CPU
RAM
Disk
GPU
```

root 관리자는 전체 계정과 시스템을 관리합니다.

Multipass에서 VM 생성 시 CPU, RAM, 디스크 용량을 정하는 것도  
이러한 **자원 할당 개념을 간단하게 실습하는 것**으로 볼 수 있습니다.

## 15. Windows ↔ Ubuntu 파일 공유

Windows와 Ubuntu는 기본적으로 별개의 파일 시스템입니다.

필요하면:

```text
Windows 폴더
      ↕
    Mount
      ↕
Ubuntu 폴더
```

처럼 폴더를 연결하여 사용할 수 있습니다.

또는 SSH 기반 파일 전송 방식으로 파일을 주고받을 수도 있습니다.

즉:

```text
서버에 접속하는 것
파일을 공유하는 것
```

은 서로 다른 개념이며 상황에 따라 SSH, 전송, Mount 등을 사용합니다.

# 가장 중요한 핵심 5개

### 1. Multipass Ubuntu는 별도의 서버다

같은 PC 안에 있어도 각각 IP를 가진 독립된 컴퓨터처럼 생각합니다.

### 2. Linux는 권한 관리가 중요하다

```text
user / group / other
r / w / x
chmod
sudo / root
```

를 이해해야 합니다.

### 3. 서버는 IP를 통해 통신한다

인스턴스 A와 B가 통신할 때도 각 서버의 네트워크 주소가 필요합니다.

### 4. SSH는 원격 서버에 들어가는 기본 기술이다

```text
내 PC → SSH → Ubuntu / AWS 서버
```

형태로 사용합니다.

### 5. 개인키와 공개키는 SSH 인증에 사용한다

```text
내 PC       : 개인키
원격 서버   : 공개키
```

가 한 쌍으로 맞을 때 접속을 허용합니다.
