## 1. AI 에이전트의 본질: 질문에 맞는 도구 실행

- **문제:** 단순 LLM 호출만으로는 상품 검색·가격 계산·재고 조회를 안정적으로 처리하기 어렵습니다.
- **원리:** 사용자의 질문을 해석하고, 도구의 `name`·`description`·`parameters`를 참고해 필요한 함수를 선택한 뒤, **실제 DB 조회나 계산은 코드가 수행**하도록 분리합니다.
- **예:** “키보드 재고 있어? 3개 사면 얼마야?” → 상품 식별 → 재고 조회 → 할인 규칙 및 총액 계산 → 답변 생성. 가격과 재고를 LLM이 추측해서는 안 됩니다.
- **설계:** `search_product()`, `recommend_product()`, `get_price()`, `get_stock()`, `calculate_total()`처럼 기능을 작게 나누면 재사용·테스트·오류 수정이 쉽습니다. 질문이 복합적이면 여러 함수를 순서대로 호출합니다.

→ 왜 배우나·현업 활용: **도구 호출과 데이터 처리의 역할을 분리하여, 쇼핑몰 상담 챗봇이 실제 재고·금액을 정확하게 조회하도록 설계하기 위해 배웁니다.**

## 2. LLM API 직접 호출 vs LangChain vs 클라우드 에이전트

| 방식 | 강점 | 주의점·채택 기준 |
|---|---|---|
| API 직접 호출 | 내부 동작·예외 처리·최적화를 세밀하게 제어 | 플랫폼마다 SDK 호출 방식이 다름; 세밀한 제어가 필요할 때 |
| LangChain | 모델·프롬프트·출력 처리 등을 재사용 가능한 구성 요소로 연결 | 버전 변화와 추상화 제약 확인; 여러 모델·단계의 조합에 적합 |
| LangGraph | 상태와 분기, 반복을 가진 에이전트 흐름 구성 | 복잡한 실행 흐름에서 유용 |
| AWS Bedrock 등 관리형 플랫폼 | 관리형 모델·서비스 및 클라우드 기능 연계 | 사용료·서비스 종속성·운영 조건 비교 후 채택 |

- **핵심:** OpenAI·Gemini·Claude를 바꿔 쓰려면 제공사별 호출 부분을 **어댑터/모듈로 분리**하고, 바깥에서는 플랫폼·모델·API 키 설정만 바꾸게 합니다. 공급사 SDK가 모두 동일한 것은 아닙니다.
- **체인:** `프롬프트 → 모델 → 출력 파서`처럼 처리 단계를 연결하는 개념입니다.
- **정확성 주의:** 녹취에 나온 “모든 상용 LLM이 오픈소스”, “모든 모델을 OpenAI API만으로 사용”한다는 표현은 일반적으로 사실이 아닙니다. 오픈웨이트 모델과 비공개 모델이 공존하며 공급사별 API가 다릅니다. 일부 서비스는 OpenAI 호환 API를 지원합니다.

→ 왜 배우나·현업 활용: **프레임워크별 추상화와 제어 수준을 비교하여, 프로젝트 요구에 맞게 모델을 교체하거나 운영 환경을 변경하기 위해 배웁니다.**

## 3. 의미 검색, 임베딩, 벡터 검색

- **키워드 검색:** “이어폰”처럼 정확한 단어를 찾는 방식으로, 다른 표현에 취약할 수 있습니다.
- **의미 검색:** 질문과 문서를 **임베딩(의미를 반영한 수치 벡터)**으로 바꾸고, 코사인 유사도·거리 등을 이용해 가까운 항목을 찾습니다. FAISS는 벡터의 최근접 이웃 검색에 활용하는 라이브러리입니다.
- **예:** “출퇴근할 때 음악 듣는 제품” → 이어폰 상품과 관련성이 높게 나올 수 있습니다. 단, 검색 결과의 정확성은 임베딩 모델과 상품 설명 데이터 품질에 달려 있습니다.
- **구분:** 벡터 검색은 **관련 상품 후보 탐색**, DB/업무 함수는 **재고·가격의 정확한 확인**을 담당합니다.

→ 왜 배우나·현업 활용: **정확한 단어가 없어도 관련 상품을 찾되, 가격·재고 같은 사실은 DB에서 검증하는 검색 시스템을 만들기 위해 배웁니다.**

## 4. 서비스 운영: 비용·지연시간·캐시

- 외부 LLM 호출은 **입력/출력 토큰 비용과 네트워크 지연**이 발생할 수 있습니다. 입력 길이 제한, 적절한 모델 선택, 호출 횟수 제한이 필요합니다.
- 같은 질문·동일한 문서 임베딩은 **캐시**로 반복 계산을 줄일 수 있습니다. 다만 재고·가격처럼 변하는 데이터에는 만료 시간이나 갱신 정책이 필요합니다.
- 짧고 명확한 요청은 정규표현식·규칙·로컬 검색으로 처리할 수 있습니다. 복잡한 의미 해석에만 LLM을 쓰는 **하이브리드 설계**를 고려합니다.
- 클라우드 배포 시 응답시간·월간 사용량·비용 한도·예외 처리·무한 도구 호출 방지를 함께 설계합니다.

→ 왜 배우나·현업 활용: **정확도뿐 아니라 비용과 응답속도를 관리하여, 실제 사용자가 늘어도 운영 가능한 에이전트를 배포하기 위해 배웁니다.**

## 5. 문서 변환과 청킹(Chunking)

- Jupyter Notebook(`.ipynb`)은 **코드 셀·결과·Markdown 설명**을 함께 보관합니다. HTML로 내보내거나 `.py`로 변환하면 공유·실행 방식을 바꿀 수 있습니다.
- 주석을 기준으로 자동 분할하려면 `# PART 1` 또는 `## ...`처럼 **일관된 구분 규칙**을 정해야 합니다. 임의의 `#` 주석마다 자르면 코드가 잘못 나뉠 수 있습니다.
- 문서를 검색 시스템에 넣을 때도 의미 있는 제목과 단위로 **청킹(작은 구간으로 나누기)** 해야 필요한 정보를 찾아올 수 있습니다.

→ 왜 배우나·현업 활용: **코드·교육 자료를 자동 문서화하고, 내부 기술 문서 검색용 데이터로 재사용하기 위해 배웁니다.**

## 6. 컴퓨터 비전과 YOLOv8

- **컴퓨터 비전:** 픽셀로 표현된 이미지를 분석하는 기술입니다. RGB는 보통 3채널, 그레이스케일은 1채널 강도값이며, 8비트 영상의 픽셀값은 일반적으로 0~255입니다.
- **분류(Classification):** 이미지 전체가 무엇인지 판별합니다.
- **객체 탐지(Object Detection):** 한 이미지 안의 여러 객체에 **종류·위치(바운딩 박스)·신뢰도**를 반환합니다.
- **분할(Segmentation):** 객체가 차지하는 픽셀 영역을 구분합니다.
- **YOLOv8:** 사전 학습 모델을 이용해 이미지의 객체를 탐지하고 박스를 시각화하는 실습을 진행했습니다. 제조 검사 등에서는 모델 성능뿐 아니라 현장 카메라·조명·처리시간을 함께 고려해야 합니다.

→ 왜 배우나·현업 활용: **분류·탐지·분할의 차이를 이해하여, 생산라인 불량 탐지나 영상 속 물체 위치 표시 작업에 맞는 기술을 고르기 위해 배웁니다.**

### YOLOv8 최소 실습 코드 — 추가 예시

**실행 환경:** Windows 또는 Linux의 Python 가상환경 / VS Code 터미널. Jupyter 셀에서 설치할 때만 `%pip`을 사용합니다.

```bash
python -m pip install ultralytics opencv-python
```

```python
from ultralytics import YOLO

model = YOLO("yolov8n.pt")              # 사전 학습된 작은 탐지 모델
results = model.predict(
    source="test.jpg",                   # 실제 이미지 경로로 변경
    conf=0.25,                           # 신뢰도 임계값
    imgsz=640,                           # 추론 입력 이미지 크기
    save=True,                           # 박스가 그려진 이미지 저장
    save_txt=True,                       # 탐지 결과를 라벨 TXT로 저장
    save_crop=True,                      # 탐지 객체 영역 별도 저장
)

annotated_bgr = results[0].plot()         # 박스/라벨이 그려진 이미지 배열
print(results[0].boxes.xyxy)             # 박스 좌표 (x1, y1, x2, y2)
```

- `results[0]`은 **첫 번째 입력 이미지의 결과**, `plot()`은 표시용 이미지 반환, `boxes.xyxy`는 좌상단·우하단 좌표입니다.
- `save=True` 결과는 보통 실행 폴더 아래 `runs/detect/predict...`에 저장되며 실행 설정에 따라 달라집니다. `save_txt=True`의 텍스트는 일반적으로 **클래스와 정규화된 박스값**을 담습니다.
- `conf`는 낮을수록 후보가 늘지만 오탐도 늘 수 있습니다. 결과가 없으면 파일 경로, 모델 다운로드, 신뢰도 기준부터 확인합니다.
- **주의:** `plot()` 결과는 OpenCV에서 쓰는 **BGR 배열**입니다. Matplotlib로 보여줄 때는 RGB 변환이 필요합니다.

→ 왜 배우나·현업 활용: **탐지 좌표·신뢰도·저장 옵션을 다루어, 객체 수를 세거나 특정 클래스만 표시하는 검사용 파이프라인을 만들기 위해 배웁니다.**

## 7. 모델 배포와 양자화

- PyTorch는 모델 연구·개발뿐 아니라 배포에도 사용됩니다. TensorFlow도 배포 도구가 있으며, 실제 선택은 지원 하드웨어·런타임·프로젝트 요구에 따라 달라집니다.
- **양자화(Quantization):** 모델의 일부 수치 표현을 FP32에서 INT8 등 낮은 정밀도로 바꿔 메모리 사용량과 추론 비용을 낮추려는 기법입니다. 속도 향상은 하드웨어·런타임에 따라 다르고, 정확도 저하를 검증해야 합니다.
- 모바일·엣지 배포는 장치가 지원하는 형식으로 모델을 내보내고 실제 장치에서 **정확도·속도·메모리 사용량**을 측정하는 것이 핵심입니다.

→ 왜 배우나·현업 활용: **개발 PC에서 동작한 탐지 모델을 모바일·현장 장비에 배포할 때 성능과 정확도 사이의 균형을 판단하기 위해 배웁니다.**

## 신입 예상 면접 질문과 답변

**Q1. 단순 LLM 호출과 AI 에이전트의 차이는 무엇인가요?**  
A. 단순 호출은 입력을 바탕으로 답변을 생성합니다. 에이전트는 질문에 맞는 도구를 선택하고 실제 함수·DB를 호출해 그 결과로 답변할 수 있습니다.

**Q2. 왜 상품 검색에 벡터 검색을 사용하나요?**  
A. 사용자가 상품명 대신 사용 상황을 설명해도 의미가 가까운 제품을 찾기 위해서입니다. 단, 가격과 재고는 벡터 검색 결과를 그대로 믿지 않고 원본 데이터베이스에서 다시 확인합니다.

**Q3. LangChain을 무조건 써야 하나요?**  
A. 그렇지 않습니다. 반복되는 모델 연동이나 체인이 많으면 편리하지만, 세밀한 제어와 간결한 호출은 직접 SDK 사용이 적합할 수 있습니다. 프로젝트 복잡도와 유지보수 비용을 비교합니다.

**Q4. YOLO 객체 탐지와 이미지 분류는 어떻게 다른가요?**  
A. 이미지 분류는 이미지 전체의 범주를 예측합니다. 객체 탐지는 이미지 안의 개별 물체를 찾고 종류와 바운딩 박스 좌표를 반환하므로 여러 물체의 위치를 다룰 수 있습니다.

**Q5. YOLO 모델이 PC에서는 빠른데 모바일에서는 느리다면 어떻게 대응하나요?**  
A. 우선 장치에서 추론시간·메모리·정확도를 측정합니다. 작은 모델, 입력 크기 조정, 지원 런타임으로 내보내기, 양자화를 검토하고 변경 전후 정확도도 확인합니다.
