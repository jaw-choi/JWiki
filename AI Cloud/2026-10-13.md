## 1. 오늘 수업의 큰 흐름

기존 YOLO 모델로 **이미지·영상의 객체를 탐지하는 것**에서 시작해, 모델이 모르는 객체를 직접 학습시키려면 무엇을 준비해야 하는지 살펴보았습니다. 전체 과정은 **목표 정의 → 이미지 수집 → 라벨링(어노테이션) → YOLO 형식으로 변환 → 데이터 분리와 YAML 설정 → 학습 → 평가 → 새로운 데이터로 검증**입니다. [수업]

→ 왜 배우나·현업 활용: 이 전체 흐름을 이해하여, 제조 공정의 결함이나 현장에서만 등장하는 물체처럼 기존 모델이 인식하지 못하는 대상을 학습시키기 위해 배웁니다.

## 2. 학습 데이터와 라벨링이 중요한 이유

**라벨링(labeling)**은 모델이 정답을 학습하도록 이미지·영상·음성에 정답 정보를 붙이는 작업입니다. 예를 들어 사진 속 사람을 둘러싼 **바운딩 박스(bounding box)**와 `person`이라는 클래스 이름을 저장할 수 있습니다. 물체의 윤곽을 따는 **폴리곤(polygon)**, 영상의 프레임별 위치 표시, 관절 점 표시, 음성을 글로 옮기는 **전사(transcription)**도 목적에 따라 사용하는 작업입니다. [수업]

라벨링에서는 “가려진 물체는 어디까지 박스를 칠 것인가”, “마네킹도 사람으로 포함할 것인가”, “잘린 객체는 어떻게 처리할 것인가” 등의 **작업 가이드라인**을 먼저 정해야 합니다. 기준이 다르면 동일한 이미지에서도 정답이 흔들려 모델 품질이 떨어질 수 있습니다. AI Hub처럼 데이터셋을 제공하는 곳을 활용하더라도 직접 몇 장을 라벨링해 보는 이유가 여기에 있습니다. [수업]

→ 왜 배우나·현업 활용: 정답 기준을 통일하여, 서로 다른 작업자가 만든 라벨 때문에 객체 탐지 모델의 오탐·미탐이 증가하는 문제를 줄이기 위해 배웁니다.

## 3. 컴퓨터 비전에서 무엇을 찾아내는가

| 작업 | 결과 | 사용 예 |
|---|---|---|
| 이미지 분류(Classification) | 이미지 전체의 클래스 | 사진이 고양이인지 강아지인지 판별 |
| 객체 탐지(Object Detection) | 객체 클래스 + 사각형 위치 | 화면 속 사람·차량 위치 찾기 |
| 세그멘테이션(Segmentation) | 객체 또는 영역의 픽셀 단위 마스크 | 사람만 분리해 배경을 교체 |
| 포즈 추정(Pose Estimation) | 관절 등 키포인트 위치 | 팔 들기·자세 분석 |

[수업] 객체 탐지의 바운딩 박스만으로는 사람의 정확한 실루엣을 분리할 수 없고, 사람의 윤곽을 분리하려면 세그멘테이션이 필요합니다. 포즈 추정은 사람의 신체 관절을 점으로 찾아 행동 규칙을 만들 때 사용합니다.

[보충] 컴퓨터 비전 모델은 이미지의 가장자리, 패턴, 질감 등 다양한 특징을 추출합니다. 수업에서 설명한 필터의 이동, 특징 추출, 가중치(W)와 편향(b)은 원리를 설명하기 위한 단순화된 흐름입니다. 모든 현대 비전 모델이 반드시 이미지 특징을 한 줄로 펼치는 동일 구조를 갖지는 않습니다.

→ 왜 배우나·현업 활용: 필요한 출력이 사각형인지, 픽셀 마스크인지, 관절 좌표인지 구분하여 기능에 맞는 모델을 선정하기 위해 배웁니다.

## 4. YOLO와 OpenCV: 역할이 다릅니다

**YOLO(You Only Look Once)**는 빠른 객체 탐지를 위한 모델 계열입니다. 수업에서는 초기 YOLO 논문의 7×7 그리드를 이용해 개념을 설명했습니다. [보충] 그 숫자는 초기 YOLO의 역사적 설명이며 **YOLOv8의 고정된 출력 구조를 뜻하지 않습니다**. YOLOv8 탐지 모델은 일반적으로 anchor-free 방식을 사용합니다. 모델 버전·크기·작업 종류에 따라 정확도와 속도는 달라집니다.

**OpenCV(Open Source Computer Vision Library)**는 이미지·영상을 읽고, 크기를 바꾸고, 색상·경계를 가공하고, 결과를 그리는 도구입니다. 수업에서는 ① 영상을 곧바로 YOLO에 전달하는 방식과 ② OpenCV로 프레임을 하나씩 읽어 YOLO에 전달하는 방식을 비교했습니다. 어느 방식이 빠른지는 입력 영상, 하드웨어, 전처리 여부를 동일하게 두고 측정해야 합니다. [수업]

[보충] OpenCV 전처리가 **항상** 필요한 것은 아닙니다. 학습된 모델이 기대하는 입력 형식과 실제 영상 조건을 고려하여 필요한 경우에 적용합니다. 특히 색상 변환·리사이즈·노이즈 처리 등이 오히려 성능을 떨어뜨리지 않는지 검증해야 합니다.

→ 왜 배우나·현업 활용: 카메라 입력 처리와 AI 추론 단계를 분리하여, 영상 분석 서비스의 속도 저하와 색상·해상도 문제를 찾아내기 위해 배웁니다.

## 5. YOLOv8 어노테이션 데이터 형식

바운딩 박스는 왼쪽 위·오른쪽 아래 점의 `(x1,y1,x2,y2)`로 표현하거나, 중심점·너비·높이의 `(cx,cy,w,h)`로 표현할 수 있습니다. YOLO 탐지 라벨은 일반적으로 이미지의 전체 너비와 높이로 나눈 **0~1 정규화 값**을 사용합니다. [수업]

```text
<class_id> <center_x> <center_y> <width> <height>
0 0.50 0.50 0.40 0.30
```

[보충] 위 수치는 **형식 설명용 임의 예시**이며 실제 수업에서 저장된 값이 아닙니다. 한 이미지에 물체가 여러 개 있으면 `.txt`에 객체마다 한 줄을 추가합니다. 클래스 번호는 가이드나 `data.yaml`에 정한 순서대로 0부터 부여하며, 가나다순·알파벳순으로 자동 고정되는 것은 아닙니다.

```text
dataset/
├── images/
│   ├── train/
│   │   └── 001.jpg
│   └── val/
│       └── 002.jpg
├── labels/
│   ├── train/
│   │   └── 001.txt
│   └── val/
│       └── 002.txt
└── data.yaml
```

```yaml
path: ./dataset
train: images/train
val: images/val
names:
  0: custom_object
```

[보충] 위 폴더와 YAML은 **권장 예시**입니다. 수업에서 강조한 핵심은 **이미지 파일명과 라벨 파일명을 일치시키고**, 학습·검증 데이터를 구분해, YOLO가 읽을 수 있는 형식으로 내보내는 것입니다. 정식 성능 보고가 필요하면 별도 `test` 세트도 확보하는 편이 좋습니다.

→ 왜 배우나·현업 활용: 어노테이션 프로그램과 학습 파이프라인 간의 데이터 형식을 맞춰서, 파일 경로 오류나 라벨 누락 없이 커스텀 모델을 훈련하기 위해 배웁니다.

## 6. YOLOv8 Pose: 키포인트로 행동 해석하기

[수업] YOLOv8 Pose의 대표적인 COCO 사람 포즈 모델은 **17개 키포인트(0~16번)**를 출력합니다. 예를 들어 왼쪽 어깨 5, 오른쪽 어깨 6, 왼쪽 팔꿈치 7, 오른쪽 팔꿈치 8, 왼쪽 손목 9, 오른쪽 손목 10의 위치로 팔 움직임을 판단할 수 있습니다.

**추론(inference)**은 학습된 모델에 새로운 데이터를 넣어 예측 결과를 얻는 과정입니다. 수업에서는 `results`에서 키포인트의 `xy` 좌표와 신뢰도 정보를 확인하고, 필요하면 `.cpu().numpy()`로 CPU의 NumPy 배열로 변환해 처리하는 과정을 살펴봤습니다. OpenCV 이미지(BGR)를 RGB로 표시할 때는 색상 순서도 맞춰야 합니다. [수업]

팔을 들었는지 판단하려면 어깨·팔꿈치·손목의 **Y 좌표 차이**와 임계값(threshold)을 비교할 수 있습니다. 다만 화면의 위쪽이 작은 Y인 일반 이미지 좌표계에서, 단순히 두 점의 Y가 비슷하다고 팔을 들었다고 확정할 수 없습니다. 사람이 누워 있거나 팔을 수평으로 벌리는 등 예외 상황을 고려해야 합니다. [수업]

→ 왜 배우나·현업 활용: 포즈 모델의 출력 좌표에 규칙을 적용하여, 운동 동작 카운트·작업자 자세 이상 경고 같은 기능을 구현하기 위해 배웁니다.

## 7. 정밀도·재현율·혼동 행렬

**혼동 행렬(confusion matrix)**은 실제 정답과 모델의 예측을 비교해 옳고 그름을 분류하는 표입니다. 여기서는 관심 클래스가 '양성(1)'인 이진 분류를 가정합니다.

| 실제 / 예측 | 예측 0 | 예측 1 |
|---|---:|---:|
| 실제 0 | TN | FP |
| 실제 1 | FN | TP |

- **TP(True Positive)**: 실제 양성을 양성으로 맞춤
- **FP(False Positive)**: 실제 음성을 양성으로 잘못 판단(오탐)
- **FN(False Negative)**: 실제 양성을 음성으로 놓침(미탐)
- **TN(True Negative)**: 실제 음성을 음성으로 맞춤

**정밀도(Precision) = TP / (TP + FP)**: 양성이라고 예측한 것 중 실제 양성의 비율입니다. **재현율(Recall) = TP / (TP + FN)**: 실제 양성 중 모델이 찾아낸 비율입니다. **F1 = 2PR / (P + R)**는 정밀도와 재현율의 조화평균입니다. [수업·보충]

[수업] 예를 들어 실제 자동차 10대 중 7대를 검출했다면 재현율은 70%입니다. 모델이 자동차로 탐지한 8개 중 7개가 실제 자동차면 정밀도는 87.5%입니다. 안전과 관련된 낙상 감지처럼 **놓치면 위험한 상황**에서는 재현율이 특히 중요할 수 있고, 잘못된 경보가 큰 비용을 유발하면 정밀도도 중요합니다.

[보충] 하나의 모델에서 탐지 임계값을 조정하면 정밀도·재현율 사이에 흔히 상충 관계가 생기지만, **두 지표 중 하나가 높아지면 다른 하나가 무조건 떨어진다는 뜻은 아닙니다**. 또한 YOLO 객체 탐지 평가에는 클래스 예측뿐 아니라 정답 박스와 예측 박스의 겹침인 **IoU(Intersection over Union)**, 정밀도-재현율 곡선을 활용하는 **AP/mAP** 등이 사용됩니다. 단순 이진 분류의 혼동 행렬만으로 객체 탐지 성능을 완전히 설명할 수는 없습니다.

→ 왜 배우나·현업 활용: 낙상 감지의 미탐이나 불량품 검사의 오탐처럼 실제 서비스 비용이 다른 오류를 정량적으로 평가하고 임계값을 결정하기 위해 배웁니다.

## 8. 커스텀 YOLO 모델 제작 과정

1. **대상과 활용 현장 정의**: 무엇을 검출하며 어떤 카메라 환경에서 사용할지 정합니다.
2. **이미지 수집**: 조명·거리·각도·가림·배경 조건을 포함한 자료를 확보합니다.
3. **라벨링 규칙 정의**: 클래스 이름, 박스 범위, 모호한 객체의 처리 기준을 정합니다.
4. **어노테이션**: 바운딩 박스를 그려 YOLO 형식의 라벨 `.txt`를 생성합니다.
5. **분리·내보내기**: 학습(train), 검증(val), 가능하면 독립 테스트(test) 세트로 나눕니다. `data.yaml`을 생성합니다.
6. **학습**: 사전학습된 YOLOv8 가중치에서 시작하여 이미지 크기, 에폭(epoch: 학습 데이터 반복 횟수), 배치(batch: 한 번에 처리하는 데이터 묶음) 등을 설정합니다.
7. **성능 검증**: 정밀도·재현율·mAP 및 실제 오탐·미탐 사례를 확인합니다.
8. **개선 후 재평가**: 부족한 상황의 데이터를 추가하거나, 적절한 증강(회전·밝기·크롭 등)을 시도합니다.

[보충] 데이터가 부족하더라도 **무조건 많이 모으는 것만이 답은 아닙니다**. 잘못된 라벨·중복 이미지·테스트 데이터 유출을 막고, 실제 사용 환경을 대표하는 다양한 정답 데이터를 확보하는 것이 중요합니다.

→ 왜 배우나·현업 활용: 공장 균열·맞춤형 제품·특수한 작업자 행동 등 공개된 모델에 클래스가 없는 현장에서 자체 탐지 모델을 제작하기 위해 배웁니다.

## 9. 오늘 실습 코드 핵심과 실행 환경

**실행 환경: Windows의 VS Code 터미널(PowerShell), Python 3.x 가상환경을 가정한 복습용 예시입니다.** 실제 수업의 전체 코드 및 실행 성공 여부가 녹취만으로 확인되지는 않습니다.

```powershell
# 프로젝트 작업 폴더에서 실행
python -m pip install ultralytics opencv-python
```

- 목적: YOLOv8 추론·학습 및 OpenCV 영상 처리를 위한 패키지를 설치합니다.
- 예상 결과: 패키지 설치 완료 메시지. 이미 설치되어 있다면 이미 충족되었다는 메시지가 나올 수 있습니다.
- 확인: `python -c "from ultralytics import YOLO; import cv2; print('ok')"`에서 `ok`가 표시되는지 확인합니다.

**[보충] 학습 데이터가 준비된 이후** 실행하는 예시:

```python
from ultralytics import YOLO

model = YOLO("yolov8n.pt")
model.train(data="dataset/data.yaml", epochs=10, imgsz=640, batch=8)
metrics = model.val(data="dataset/data.yaml")
```

- `data`: 이미지 경로와 클래스 이름을 정한 YAML 파일
- `epochs`: 학습 데이터를 반복하여 학습하는 횟수
- `imgsz`: 학습 시 입력 이미지 크기
- `batch`: 한 번에 처리하는 이미지 수(하드웨어에 맞게 조절)
- 예상 결과: 학습 로그·가중치·평가 결과가 출력/저장되며, 경로는 실행 설정에 따라 달라집니다.
- 해석: 검증 지표만 보지 말고 학습에 사용하지 않은 새 이미지에서도 예측 결과를 확인합니다.

[수업] `save=True`는 추론 결과 저장, `save_txt=True`는 탐지·포즈 등 해당 작업의 텍스트 출력, `stream=True`는 결과를 반복적으로 처리하는 스트리밍 인터페이스에 해당합니다. 출력 폴더 이름과 구조는 설정·버전에 따라 달라질 수 있으므로 고정 경로로 가정하지 않습니다.

→ 왜 배우나·현업 활용: 데이터 형식과 설정값을 분리하여 실험을 반복하고, 이전 버전 대비 모델 성능을 재현 가능하게 비교하기 위해 배웁니다.

## 14. 예상 신입 면접 질문과 답변

**Q1. 객체 탐지와 세그멘테이션은 어떻게 다릅니까?**  
객체 탐지는 물체의 종류와 대략적인 사각형 위치를 예측합니다. 세그멘테이션은 객체나 영역에 해당하는 픽셀을 구분하므로 사람만 정확히 잘라내는 작업에 더 적합합니다.

**Q2. YOLO 형식의 박스 좌표를 정규화하는 이유는 무엇입니까?**  
이미지마다 픽셀 크기가 달라도 같은 범위의 좌표 체계를 사용하기 위해서입니다. YOLO 탐지 라벨에는 일반적으로 클래스 번호 뒤에 이미지 너비·높이로 나눈 중심 좌표와 박스 크기를 저장합니다.

**Q3. Precision과 Recall 중 어느 것이 더 중요합니까?**  
서비스에서 오탐과 미탐이 일으키는 비용에 따라 다릅니다. 위험 상황을 놓치면 안 되는 감지 시스템에서는 Recall을 중점적으로 보되, 오탐 경보의 비용도 함께 평가해야 합니다.

**Q4. YOLO 모델의 성능이 실제 현장에서 떨어지면 어떻게 대응합니까?**  
먼저 실제 입력 영상의 조명·촬영 각도·해상도와 학습 데이터의 차이를 확인하겠습니다. 이후 오탐·미탐 사례를 모아 라벨과 데이터 분포를 검사하고, 필요하면 데이터를 보강한 뒤 독립 검증 세트로 성능을 다시 측정하겠습니다.

**Q5. OpenCV와 YOLO를 함께 사용하는 이유는 무엇입니까?**  
OpenCV는 카메라나 영상 파일에서 프레임을 읽고 입력을 가공하거나 결과를 그리는 데 유용합니다. YOLO는 해당 프레임에 대해 객체·포즈 등을 예측하므로, 두 도구의 역할을 분리해 영상 처리 서비스를 만들 수 있습니다.
