## 전사 오류 및 기술적 보정

자동 전사 오류가 많아 문맥에 따라 다음과 같이 통합했다.

| 전사 표현 | 문맥상 의미 |
|---|---|
| `C SUV` | CSV |
| `SK, SQ, 에스겔` | SQL |
| `제이슨, 재심` | JSON |
| `APA` | API |
| `아이디 서버` | AWS RDS 또는 데이터베이스 서버로 추정 — 확인 필요 |
| `하이선, 팔선` | Python |
| `HPL` | HTML로 추정 |
| `엔드미` | README로 추정 |
| `노샤` | Notion 또는 별도 도구로 추정 — 확인 필요 |
| `오픈서치` | Amazon OpenSearch Service 또는 OpenSearch |
| `트리거` | 예약·이벤트 기반 실행 조건 |

반드시 교정해야 할 내용은 다음과 같다.

- **[기술적 보정] API는 인증 방법이 아니다.** API는 프로그램이 다른 프로그램의 기능이나 데이터에 접근하기 위한 인터페이스이고, API key·OAuth·JWT 등은 API 접근을 통제하는 인증/인가 방식이다.
- **[기술적 보정] CSV도 스키마를 가질 수 있다.** 파일 자체에 중첩 구조를 표현하기 어렵다는 뜻이지, 열 이름·자료형·제약 조건을 별도 데이터 정의서나 schema 파일로 관리할 수 없는 것은 아니다.
- **[기술적 보정] JSON은 구조화된 데이터 형식이다.** 일반적으로 반정형 데이터로 분류하며 객체와 배열을 중첩해 계층 구조를 표현할 수 있다.
- **[기술적 보정] SQL은 데이터베이스 서버 그 자체가 아니라 관계형 데이터베이스를 정의·조회·변경하는 언어다.** 대량 데이터의 성능은 SQL 문법만이 아니라 인덱스, 실행 계획, 스키마, 파티셔닝, 하드웨어와 DB 엔진에 좌우된다.
- **[기술적 보정] `?`는 URL에서 query string의 시작, `&`는 query parameter 사이의 구분자로 주로 쓰인다.** 이것이 반드시 데이터베이스 변수에 직접 대응한다는 뜻은 아니다.
- **[기술적 보정] HTTPS는 HTTP 통신을 TLS로 암호화하고 서버 신원을 검증한다.** “한글을 제공하는 프로토콜”이나 단순 보안 옵션이 아니다.
- **[기술적 보정] JSON과 XML은 API 응답의 대표 형식이지만 유일한 형식은 아니다.** CSV, Protocol Buffers, MessagePack, binary media 등도 사용할 수 있다.
- **[기술적 보정] JSON에 정답 구조가 하나 없다는 말은 문법이 없다는 뜻이 아니다.** JSON 문법은 엄격하지만 업무 데이터의 필드와 중첩 설계가 목적에 따라 달라진다는 의미다.
- **[기술적 보정] MCP는 조건문 저장소가 아니다.** MCP는 AI 애플리케이션이 tools, resources, prompts 등을 표준 방식으로 발견하고 호출하도록 연결하는 프로토콜이다.

1. **[수업]** CSV는 행과 열로 된 정형 데이터를 쉽게 저장·교환하는 단순한 형식이다.
2. **[수업]** 데이터가 많아지고 반복 조회가 필요하면 데이터베이스와 SQL을 사용한다.
3. **[수업]** 다른 회사나 공공기관의 데이터를 받으려면 상대 시스템이 공개한 API와 데이터 명세를 확인해야 한다.
4. **[수업]** API 응답은 CSV보다 JSON이나 XML로 제공되는 경우가 많으며, 이를 원하는 CSV·DB 구조로 바꾸는 일은 소비자 측 프로그램의 역할일 수 있다.
5. **[수업]** JSON은 key-value와 배열·객체를 사용해 데이터의 계층 구조를 표현할 수 있다.
6. **[수업]** API를 사용하려면 endpoint, parameter, 인증 방식, 인코딩, 응답 예시를 문서에서 확인해야 한다.
7. **[수업]** Python은 API 호출, JSON 파싱, CSV 저장, 데이터 분석 등 여러 영역을 하나의 언어로 처리하기 쉬워 AI 개발에서 널리 사용된다.
8. **[수업]** 환율 API처럼 공개 데이터를 주기적으로 수집하면 계산기, 변화 그래프, 임계값 알림 같은 기능을 만들 수 있다.
9. **[수업]** 자연어 요청을 이해해 적절한 계산기나 데이터 수집 도구를 선택하는 구조가 Agent의 기초다.
10. **[멘토 보충]** 최종 프로젝트에서는 환율 API 자리에 Game State API와 Game Knowledge API가 들어가며, JSON Schema가 Unreal Engine과 FastAPI의 계약이 된다.

# 2. 수업 내용 상세 정리

## 2.1 정형 데이터와 데이터 구조

### 개념

**정형 데이터(structured data)**는 열, 자료형, 제약 조건처럼 정해진 스키마에 따라 저장된 데이터다. 고객 번호, 이름, 지역, 구매 금액처럼 필드 의미가 명확한 표가 대표적이다.

**반정형 데이터(semi-structured data)**는 고정된 표 모양은 아니어도 key, tag, hierarchy 같은 구조 정보를 포함한다. JSON과 XML이 대표적이다.

**비정형 데이터(unstructured data)**는 문서 본문, 이미지, 음성처럼 행·열 스키마로 바로 표현하기 어려운 데이터다.

### 사용 목적

- 프로그램이 동일한 규칙으로 데이터를 읽는다.
- 데이터 검증과 검색을 자동화한다.
- 다른 시스템과 데이터 계약을 맺는다.
- AI 학습·RAG·평가 파이프라인에서 입력의 의미를 일관되게 유지한다.

### 주요 구성 요소

| 요소 | 설명 | 예시 |
|---|---|---|
| 필드명 | 데이터의 의미 | `region`, `sales_amount` |
| 자료형 | 허용되는 값의 종류 | string, integer, number |
| 제약 조건 | 값의 규칙 | 필수, 범위, enum |
| 식별자 | 레코드를 구별하는 값 | `customer_id` |
| 관계 | 다른 객체와의 연결 | 고객 1명 ↔ 주문 여러 개 |
| 메타데이터 | 데이터의 출처·시간·버전 | `created_at`, `schema_version` |

### 주의할 점

- 표에 열 이름이 있다고 의미가 완전히 전달되는 것은 아니다. 단위, null 허용 여부, 코드값 의미, 시간대까지 정의해야 한다.
- `region=1`이 서울인지 부산인지는 코드 정의서가 없으면 알 수 없다.
- AI에게 데이터를 주기 전 스키마와 품질을 먼저 점검한다. 잘못된 데이터는 모델 출력 전체를 오염시킨다.

## 2.2 CSV와 Excel

### CSV

**CSV(Comma-Separated Values)**는 한 행의 여러 필드를 구분자로 나누어 저장하는 텍스트 파일이다.

```csv
customer_id,name,region,sales_amount
1001,김민수,서울,32000
1002,이서연,부산,27000
```

### 장점

- 단순하고 대부분의 언어·DB·스프레드시트가 지원한다.
- 사람이 열어 볼 수 있고 스트리밍 처리도 쉽다.
- 작은 데이터 교환과 분석용 export에 적합하다.

### 한계

- 중첩 객체·배열을 자연스럽게 표현하기 어렵다.
- 자료형과 제약 조건이 파일 자체에 강하게 포함되지 않는다.
- 구분자, 줄바꿈, 따옴표, 문자 인코딩 문제를 주의해야 한다.
- 여러 테이블 관계를 한 파일로 표현하기 어렵다.

### Excel과 차이

Excel 파일은 셀 서식, 여러 시트, 수식, 차트 등을 담을 수 있다. CSV는 순수 데이터 교환에 가깝다. 서버 간 API 응답으로 Excel을 기본 형식으로 쓰는 경우는 드물고, 사람이 다운로드하는 보고서에 더 적합하다.

## 2.3 관계형 데이터베이스와 SQL

### 개념

**관계형 데이터베이스**는 데이터를 테이블로 저장하고 key와 관계를 통해 여러 테이블을 연결한다.

**SQL(Structured Query Language)**은 관계형 데이터베이스의 테이블을 생성·조회·수정·삭제하는 언어다.

### 전사의 매출 집계 예시 복원

“한 달 동안 서울 지역의 매출 합계를 큰 순서대로 나열”한다면 실제 스키마에 따라 다음처럼 작성할 수 있다.

```sql
SELECT
    store_id,
    SUM(sales_amount) AS total_sales
FROM sales
WHERE region = '서울'
  AND sold_at >= DATE '2026-09-01'
  AND sold_at <  DATE '2026-10-01'
GROUP BY store_id
ORDER BY total_sales DESC;
```

### 실행 흐름

1. `WHERE`가 서울 지역과 기간을 필터링한다.
2. `GROUP BY`가 매장별 행을 묶는다.
3. `SUM`이 매장별 매출을 합산한다.
4. `ORDER BY ... DESC`가 큰 금액부터 정렬한다.

### 자연어→SQL

**[수업]** 자연어를 SQL로 바꾸는 도구가 좋아졌으며 LLM API를 붙여 같은 기능을 만들 수 있다고 설명했다.

**[멘토 보충]** 생성된 SQL을 곧바로 운영 DB에서 실행하면 위험하다.

- read-only DB 계정을 사용한다.
- 허용 table·column 목록을 둔다.
- `SELECT`만 허용하고 다중 statement를 차단한다.
- row limit과 query timeout을 설정한다.
- SQL parser 또는 policy validator로 검사한다.
- 운영 DB 대신 replica 또는 분석 DB를 사용한다.

## 2.4 데이터베이스 서버와 클라우드 관리형 DB

### 수업 내용

**[수업]** 데이터 양이 커지면 DB 전용 서버를 두기도 하며, 클라우드에서는 데이터베이스용 관리형 서비스를 사용할 수 있다고 설명했다.

### 멘토 보충

AWS의 대표 관계형 관리형 DB는 Amazon RDS다. 관리형이라고 해서 스키마·쿼리·인덱스·백업 정책을 모두 자동으로 완벽하게 해결해 주는 것은 아니다. 클라우드 제공자는 인프라의 많은 부분을 관리하지만 사용자는 데이터 모델, 접근 권한, 성능 설정, 비용을 책임져야 한다.

### 프로젝트 선택 기준

| 저장 대상 | 추천 저장소 예시 | 이유 |
|---|---|---|
| 플레이어·세션·실행 상태 | PostgreSQL/RDS | 트랜잭션과 관계 조회 |
| 원본 게임 문서 | S3 | 저렴한 객체 저장 |
| 임베딩·검색 인덱스 | pgvector/OpenSearch 등 | 유사도 검색 |
| 짧은 세션 캐시 | Redis/ElastiCache | 낮은 latency |
| 로그·trace | 관측 플랫폼/로그 저장소 | 검색·집계·보존 정책 |

## 2.5 API의 정확한 의미

### 개념

**API(Application Programming Interface)**는 한 소프트웨어가 다른 소프트웨어의 데이터나 기능을 정해진 계약으로 사용할 수 있게 하는 인터페이스다.

### API 요청의 주요 구성 요소

| 구성 요소 | 역할 | 예시 |
|---|---|---|
| Method | 수행 의도 | `GET`, `POST`, `PATCH`, `DELETE` |
| Endpoint | 접근할 리소스 주소 | `/v1/sales` |
| Path parameter | 특정 리소스 지정 | `/players/{player_id}` |
| Query parameter | 필터·정렬·페이지 등 | `?region=seoul&limit=100` |
| Header | 인증·형식·추적 정보 | `Authorization`, `Content-Type` |
| Body | 생성·처리할 데이터 | JSON request body |
| Status code | 처리 결과 범주 | `200`, `400`, `401`, `404`, `500` |
| Response | 반환 데이터 | JSON object/array |

### 인증과 인가

- **인증(authentication):** 요청자가 누구인지 확인한다.
- **인가(authorization):** 확인된 요청자가 무엇을 할 수 있는지 결정한다.
- **API key:** 애플리케이션 식별과 사용량 제한에 흔히 사용한다.
- **OAuth 2.0:** 사용자가 제3자 앱에 제한된 권한을 위임할 때 사용한다.
- **JWT:** 인증·권한 정보를 서명된 token으로 전달하는 데 사용할 수 있다.

### 주의할 점

- API key를 Unreal 패키지나 Git 저장소에 넣으면 추출될 수 있다.
- UE는 본인 서비스인 FastAPI만 호출하고, 외부 LLM·클라우드 비밀키는 서버에 보관한다.
- TLS 인증서 검증을 끄지 않는다.
- rate limit, timeout, retry, idempotency를 설계한다.

## 2.6 API 문서와 데이터 정의서

### 수업 핵심

**[수업]** 외부 데이터를 받으려면 상대 회사가 제공한 URL, endpoint, field, code value, 인증 방식, 문자 인코딩을 문서에서 확인해야 한다. 예를 들어 지역 코드 `1`이 서울이라는 규칙은 명세가 있어야 알 수 있다.

### 최소 API 문서 항목

```text
API 이름과 목적
Base URL
Endpoint와 HTTP method
인증 방법
Request path/query/header/body
Response schema와 예시
필드 자료형·필수 여부·코드값
오류 코드
rate limit
pagination
문자 인코딩과 시간대
버전·변경 이력
```

### OpenAPI 연결 — 멘토 보충

FastAPI는 OpenAPI schema를 자동 생성한다. UE 연동 전에 OpenAPI 문서에서 request/response model을 검토하면 언어가 다른 클라이언트와 서버 사이의 계약 오류를 줄일 수 있다.

## 2.7 JSON

### 한 문장 정의

**JSON(JavaScript Object Notation)**은 객체, 배열, 문자열, 숫자, 불리언, null을 사용해 계층 구조 데이터를 표현하는 텍스트 형식이다.

### 문법

```json
{
  "writer": {
    "name": "김개발",
    "version": 1.0
  },
  "questions": [
    {
      "id": 1,
      "question": "DNS의 역할은 무엇인가?",
      "choices": ["암호화", "이름 해석", "파일 압축", "GPU 연산"],
      "answer_index": 1
    }
  ]
}
```

### 주요 문법

- 객체는 `{}`로 감싼다.
- 배열은 `[]`로 감싼다.
- object property는 `"key": value` 형식이다.
- key와 문자열은 큰따옴표를 사용한다.
- 숫자, `true`, `false`, `null`은 따옴표로 감싸지 않는다.
- 마지막 항목 뒤에 trailing comma를 넣지 않는다.

### Python 변환

```python
import json

with open("quiz.json", encoding="utf-8") as file:
    data = json.load(file)       # JSON file → Python dict/list

writer_version = data["writer"]["version"]

json_text = json.dumps(
    data,
    ensure_ascii=False,
    indent=2,
)                              # Python dict/list → JSON string
```

### 주의할 점

- JSON parser로 읽었다고 데이터가 유효한 것은 아니다. JSON Schema나 Pydantic으로 업무 규칙까지 검증한다.
- 큰 JSON 전체를 LLM context에 넣으면 비용과 정확성 문제가 생긴다.
- schema version을 두고 호환성을 관리한다.
- 날짜는 JSON 고유 자료형이 없으므로 ISO 8601 문자열을 권장한다.

## 2.8 XML과 JSON 비교

### XML 정의

**XML(Extensible Markup Language)**은 시작·종료 tag와 attribute를 이용해 계층 구조를 표현하는 마크업 형식이다.

```xml
<writer>
  <name>김개발</name>
  <version>1.0</version>
</writer>
```

### 비교

| 항목 | JSON | XML |
|---|---|---|
| 표현 방식 | object·array·value | element·attribute·text |
| 크기 | 비교적 간결 | tag 때문에 길어질 수 있음 |
| 웹 API | 매우 흔함 | 레거시·기업·문서 시스템에 여전히 사용 |
| schema | JSON Schema 등 | XSD 등 |
| namespace | 기본 기능 없음 | namespace 지원 |
| Python 처리 | `json` | `xml.etree`, `lxml` 등 |

어느 형식이 절대적으로 우수한 것이 아니라 상대 API의 계약과 도메인 요구에 따라 선택한다.

## 2.9 이미지·AI 데이터셋과 JSON 메타데이터

### 수업 내용

**[수업]** 이미지 파일 위치와 설명(label/caption)을 JSON으로 연결한 대량 데이터가 이미지 AI 학습에 사용된다고 설명했다. 데이터 설계나 labeling이 잘못되면 전체 모델 결과가 나빠질 수 있다.

### 예시

```json
{
  "dataset_version": "1.0",
  "items": [
    {
      "image_uri": "s3://game-ai-data/npc/guard_001.png",
      "caption": "성문을 지키는 경비 NPC",
      "labels": ["npc", "guard"],
      "split": "train"
    }
  ]
}
```

### 주의할 점

- 원본 출처·라이선스·개인정보를 관리한다.
- class imbalance와 label error를 측정한다.
- train/validation/test 누수를 막는다.
- 이미지와 metadata 경로 불일치를 검사한다.
- 데이터셋 버전과 생성 과정을 재현 가능하게 기록한다.

**[멘토 보충]** 최종 프로젝트의 핵심은 fine-tuning보다 RAG와 Agent이므로 대규모 학습 데이터 제작에 시간을 빼앗기지 말고 Game Knowledge와 평가셋 품질에 우선 투자한다.

## 2.10 공개 API와 환율 예제

### 수업 내용

**[수업]** 인증 없이 호출할 수 있는 환율 API에서 USD 기준 KRW·EUR 등의 값을 JSON으로 받아 환율 계산기, 시간별 저장, 그래프, 임계값 알림을 만들 수 있다고 설명했다.

전사에는 정확한 API URL이 보존되지 않았다. 수업 자료의 “3번/8번 URL” 원문을 확인해야 한다.

### Python 수집 예시 — 멘토 보충

```python
from datetime import datetime, timezone
import csv
import requests

API_URL = "수업 자료의 정확한 환율 API URL 확인 필요"


def fetch_rates() -> dict:
    response = requests.get(API_URL, timeout=10)
    response.raise_for_status()
    payload = response.json()
    return payload


def append_rate(csv_path: str, krw_rate: float) -> None:
    row = {
        "observed_at": datetime.now(timezone.utc).isoformat(),
        "base": "USD",
        "quote": "KRW",
        "rate": krw_rate,
    }
    with open(csv_path, "a", newline="", encoding="utf-8-sig") as file:
        writer = csv.DictWriter(file, fieldnames=row.keys())
        if file.tell() == 0:
            writer.writeheader()
        writer.writerow(row)
```

### 실행 흐름

```text
GET API 호출
→ HTTP status 검사
→ JSON parsing
→ 필요한 KRW field 선택
→ 자료형·범위 검증
→ UTC timestamp 추가
→ CSV 또는 DB 저장
→ 그래프·알림에서 사용
```

### 반드시 보완할 오류 처리

- connect/read timeout
- DNS·TLS 오류
- `429 Too Many Requests`
- `5xx` 서버 오류
- JSON parsing 실패
- 필드 누락 또는 schema 변경
- 환율 값이 0·음수·비정상 범위
- 중복 timestamp 저장
- API 제공자의 갱신 주기와 이용 약관

## 2.11 Python을 사용하는 이유

### 수업 내용

**[수업]** Python은 특정 한 분야에만 묶이지 않고 API, 파일, DB, AI, 분석, 자동화를 폭넓게 지원해 비전공자와 AI 개발자가 사용하기 좋다고 설명했다.

### 프로젝트에서 필요한 Python 역량

1. 기본 문법과 type hint
2. `dict`, `list`, JSON serialization
3. 함수·class·module 분리
4. 예외 처리와 logging
5. `requests`/`httpx`와 timeout
6. Pydantic validation
7. FastAPI async endpoint
8. pytest·mock
9. DB transaction
10. package·environment·Docker 관리

“AI가 코드를 만들어 준다”와 “코드의 실패 원인을 설명하고 검증한다”는 다른 역량이다. 취업에서는 후자가 중요하다.

## 2.12 자동 실행과 트리거

### 개념

**트리거(trigger)**는 특정 시간, 이벤트, 상태 변화가 작업 실행을 시작하게 하는 조건이다.

### 수업 예시

- 매 시간 환율 API 호출
- 시간·환율을 CSV/JSON에 누적
- 일정 환율을 넘으면 알림
- 수집 데이터로 변화 그래프 생성

### 멘토 보충

| 규모 | 적합한 방식 예시 |
|---|---|
| 개인 PC 실습 | Windows Task Scheduler, cron |
| 단순 AWS 예약 | EventBridge Scheduler + Lambda/ECS task |
| 데이터 파이프라인 | Step Functions, Airflow 등 |
| Kubernetes | CronJob |
| Agent 내부 | LangGraph의 event/state transition |

예약 작업은 실행 여부만이 아니라 exit code, 마지막 성공 시각, 지연, 재시도, 중복 실행 방지를 관측해야 한다.

## 2.13 Agent, Tool Calling, MCP

### 수업의 Agent 예시

사용자가 “6달러는 얼마야?”라고 말하면 시스템이 환율 질문임을 파악하고 환율 API/계산기 도구를 실행해 답한다. 또 환율이 임계값을 넘으면 확인 또는 알림 작업을 실행할 수 있다.

### 올바른 역할 분리

```text
LLM
  └─ 사용자의 의도와 필요한 도구 판단

Tool
  └─ 환율 API 호출, 숫자 계산, Game API 조회처럼 결정적 작업 수행

Application policy
  └─ 권한, 허용 범위, timeout, retry, 비용 제한

MCP
  └─ tool/resource를 표준 방식으로 노출하고 연결
```

### Agent가 해야 하는 것과 코드가 해야 하는 것

| 작업 | 담당 |
|---|---|
| “6달러가 얼마냐”는 의도 파악 | LLM/분류기 |
| 최신 환율 가져오기 | API tool |
| `6 × rate` 계산 | 일반 코드 |
| 환율이 임계값 이상인지 판단 | 일반 코드 |
| 사용자에게 자연스럽게 설명 | LLM 또는 template |
| 알림 전송 권한 확인 | application policy |

# 4. 내 관심 분야와의 연결

## AI Agent Architecture — 직접 관련 있음

자연어 환율 요청을 도구 호출로 바꾸는 흐름은 Agent의 최소 구조다. 최종 프로젝트에서는 이를 `의도 파악 → Game State 조회 → RAG → 행동 도구 → 검증 → 응답`으로 확장한다.

## RAG Architecture — 간접 관련 있음

오늘 수업은 retrieval·embedding·chunking을 직접 다루지 않았다. 다만 JSON metadata, 데이터 정의서, schema version은 RAG ingestion과 검색 filter 설계의 기반이다.

## LangGraph Workflow — 개념적으로 관련 있음

프레임워크 자체는 다루지 않았지만 API 수집→검증→저장→알림 흐름은 LangGraph node와 conditional edge로 표현할 수 있다.

## Tool Calling / MCP — 직접 관련 있음

환율 API와 계산기를 자연어 의도에 따라 호출하는 것이 Tool Calling 사례다. MCP의 구체적인 server/client 구현은 수업에서 다루지 않았다.

## Python / FastAPI Backend — Python은 직접 관련, FastAPI는 간접 관련

Python으로 API 데이터를 받고 JSON을 처리해 CSV로 저장하는 흐름이 직접 나왔다. FastAPI route와 Pydantic 구현은 별도 학습이 필요하다.

## Unreal Engine ↔ AI API — 간접 관련 있음

API와 JSON 계약이 곧 UE↔FastAPI 연동의 핵심이다. Unreal에서 JSON field를 C++/Blueprint 구조체로 변환할 때 필드명, 자료형, null, version을 맞춰야 한다.

## Docker — 오늘 수업과 직접적인 관련 없음

수집 프로그램을 배포할 때 컨테이너화할 수 있지만 Docker 명령과 image 구성은 수업에 없었다.

## AWS — 직접 관련 있음

관리형 DB, OpenSearch, 클라우드 서비스와 자동화가 언급됐다. 다만 구체적인 IAM/VPC/RDS 설정은 수업 범위가 아니다.

## Kubernetes — 오늘 수업과 직접적인 관련 없음

정기 수집을 CronJob으로 운영할 수 있다는 것은 멘토 보충이며 수업에서 직접 다루지 않았다.

## AI Evaluation / Monitoring — 간접 관련 있음

수집 데이터의 시간별 저장과 오류 감시는 평가·모니터링의 기반이다. Agent 품질 metric 자체는 직접 다루지 않았다.

# 5. 최종 프로젝트 적용 방법

## 적용 기능

**Game Context Tool Gateway**를 만든다. Unreal이 보낸 현재 상태를 검증하고, Agent가 Game API와 RAG를 구조화 tool로 사용하며, 모든 입력·출력·오류를 trace로 남기는 계층이다.

## 전체 흐름도

```text
Unreal Engine
  │ JSON request
  ▼
FastAPI
  ├─ 인증/인가
  ├─ Pydantic schema validation
  ├─ trace_id 생성
  └─ timeout/error mapping
  ▼
LangGraph Agent
  ├─ Intent Router
  ├─ RAG Tool ──────> Vector DB / Game Knowledge
  ├─ Memory Tool ───> Session Store
  └─ Game Tool ─────> Game State / Game API
  ▼
Rule Verifier
  ├─ entity ID 존재 여부
  ├─ state version 일치
  ├─ action allowlist
  └─ result schema 검증
  ▼
FastAPI JSON response
  ▼
Unreal Engine 반영
```

## 권장 데이터 구조

### Agent 요청

```json
{
  "schema_version": "1.0",
  "session_id": "session-123",
  "player_id": "player-7",
  "message": "현재 퀘스트에서 다음에 어디로 가야 해?",
  "game_state": {
    "version": 1842,
    "map_id": "forest_01",
    "position": {"x": 10.2, "y": 5.1, "z": 1.0},
    "active_quest_ids": ["quest-19"]
  }
}
```

### Tool 결과

```json
{
  "tool_call_id": "tool-uuid",
  "tool_name": "get_quest_state",
  "success": true,
  "data": {
    "quest_id": "quest-19",
    "stage": 3,
    "next_objective_id": "objective-19-4"
  },

  "latency_ms": 42

```

### 공통 오류 구조

```json
{

    "code": "GAME_STATE_CONFLICT",
    "message": "요청 이후 게임 상태가 변경되었습니다.",
```

## 예상 구현 순서

1. UE와 FastAPI가 공유할 JSON data contract를 먼저 작성한다.
2. Pydantic request/response model과 OpenAPI 문서를 만든다.
3. Mock Game API를 만들고 정상·오류 JSON sample을 고정한다.
4. Python client로 mock API를 호출하고 timeout·schema 오류를 처리한다.
5. 해당 client를 LangGraph tool로 감싼다.
6. RAG 결과에도 source ID와 metadata schema를 적용한다.
7. Rule Verifier와 상태 버전 검사를 구현한다.
8. UE C++/Blueprint에서 async 호출과 JSON 역직렬화를 구현한다.
9. 평가셋과 trace schema를 만들고 metric을 계산한다.

5. object는 `dict`, array는 `list`다.

7. 데이터 변경·유출·과부하·prompt injection 위험이 있다.

## 오늘 작성할 코드 또는 아키텍처 1개

**FastAPI 기반 Game Tool Contract Prototype**

```python
from typing import Literal
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class GameState(BaseModel):
    version: int = Field(ge=0)
    map_id: str
    hp: int = Field(ge=0, le=100)


class AgentRequest(BaseModel):
    schema_version: Literal["1.0"]
    session_id: str
    player_id: str
    message: str = Field(min_length=1, max_length=1000)
    game_state: GameState


class AgentResponse(BaseModel):
    trace_id: str
    reply: str
    state_version: int


@app.post("/v1/agent/runs", response_model=AgentResponse)
async def run_agent(request: AgentRequest) -> AgentResponse:
    # 다음 단계에서 LangGraph 호출로 교체한다.
    return AgentResponse(
        trace_id="prototype-trace",
        reply=f"현재 맵은 {request.game_state.map_id}입니다.",
        state_version=request.game_state.version,
    )
```

### 코드 목적

- UE와 FastAPI 사이 JSON 계약을 먼저 고정한다.
- Pydantic이 범위와 필수값을 검증한다.
- Agent를 붙이기 전에 API boundary를 독립적으로 테스트한다.
