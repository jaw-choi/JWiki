### [예상] 본인이 카카오뱅크에 영입되어야 하는 이유(역량 및 강점)를 구체적인 경험을 바탕으로 기술해 주세요. (1,000자)
*(861자 / 제한 1000자)*

인증은 고객이 서비스를 믿고 쓰게 만드는 첫 관문이고, 저는 그 관문을 사용자와 개발자 양쪽에서 모두 다뤄 본 사람입니다. 미국 스타트업 인턴으로 App Store에 출시된 데이팅 앱 JOOPI의 프로필 편집과 이미지 업로드를 Firebase 기반으로 구현하며, 사용자 식별 정보가 앱과 서버 사이에서 어떻게 오가고 실시간으로 동기화되는지를 직접 다뤘습니다. 또 SeSAC 팀 프로젝트로 AI 비서를 만들 때 팀원의 명령 API에 붙는 클라이언트를 맡아 개발 계정 로그인, 계정이 없을 때 자동 가입, 토큰 만료 시 재로그인 흐름을 구현했고, 요청마다 request_id를 붙여 음성 명령부터 실행 결과까지 추적할 수 있게 했습니다. 실행 결과는 success/failed/rejected로 규격을 정해 다른 모듈과의 계약을 문서로 맞췄습니다. AX 측면에서는 19개 도구와 69개 평가 문장을 직접 정의해 규칙과 LLM을 섞은 하이브리드 라우팅을 설계했고, LLM 단독 대비 정확도를 88%에서 91%로 높이면서 처리 시간과 토큰을 약 60% 줄였습니다. 인증센터의 일은 법과 가이드라인을 정확히 이해하고, 제휴사가 헷갈리지 않는 API 문서를 쓰고, 반복되는 심사 대응을 줄이는 일이라고 생각합니다. 현재는 4인 팀 프로젝트 GGD에서 C++ 자체 엔진 JinEngine으로 디펜스 게임을 개발하며 유닛 합성·판매, 라운드 이자 보상, 웨이브 스킵, 바이너리 저장 같은 게임플레이를 구현하고 있습니다. AI는 구조와 방향을 제가 먼저 설계한 뒤, 제안된 코드의 이유와 대안을 묻고 제가 설명할 수 있을 때만 적용하는 검토 도구로 활용합니다. 기술을 이해하는 기획자로서 라이선스 기반 위에 새로운 인증 서비스를 만드는 데 기여하겠습니다.

### [필수 제출] 포트폴리오 구성안 (PDF, 표지 제외 10장 이내)
*(667자 / 제한 없음자)*

1장 한 줄 소개와 이 직무에 맞는 이유(Why) — 인증·API·AX 세 가지 조건 중 ②③을 중심으로 ①을 보강. 2~3장 [②API 기획·설계] AI 비서의 명령 API 클라이언트: 로그인·자동 가입·토큰 만료 재로그인 흐름도, request_id와 source(voice/ui) 전달 규약, success/failed/rejected 응답 규격, GET /agent/config·GET /commands/{request_id} 대응 설계와 그렇게 정한 이유. 4~6장 [③AI로 수동 작업 효율화] 하이브리드 라우팅: 문제(규칙 78%, LLM 88%지만 느리고 비쌈) → 가설 → 69개 평가 문장 설계 → 결과표(정확도 91%, 처리 시간·토큰 약 60% 감소) → 위험한 작업 앞 확인 정책. 7~8장 [①인증 관련] JOOPI 인턴: 프로필 편집·이미지 업로드·Firebase 실시간 동기화 화면 흐름, 사용자 데이터가 앱과 서버 사이를 오가는 구조. 9장 인증센터에서 해 보고 싶은 것: 제휴사 API 운영 매뉴얼 템플릿화, 라이선스 심사 대응 체크리스트를 LLM으로 초안화하는 아이디어. 10장 정리와 연락처. ※ 각 장에 '왜 이렇게 기획했는지(Why)'와 '어떻게 검증했는지(How)'를 반드시 한 줄씩 넣기. 공고상 기획 의도가 빠진 결과물 나열은 평가에서 제외됩니다.
