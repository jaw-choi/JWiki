## C++ Fast I/O 최적화 (Clean Code)

### 목표

C++ 표준 입출력(iostream)의 성능을 개선하여 알고리즘 문제 해결 시 실행 시간을 단축합니다.

### 배경

C++의 `cin`과 `cout`은 C의 `stdio`와 동기화되어 있고, 추가적인 안전 검사 때문에 기본적으로 느립니다. 이 동기화를 해제하고, 불필요한 버퍼링을 제거하면 상당한 성능 향상을 얻을 수 있습니다.

### Clean Code 원칙 적용

1.  **명확하고 간결한 함수**: I/O 최적화 코드를 별도의 함수로 분리하여 코드의 목적을 명확히 합니다.
2.  **의미 있는 이름**: 함수 이름(`FastIO`)을 통해 해당 함수가 어떤 역할을 하는지 명확하게 알 수 있도록 합니다.
3.  **일관성**: `endl` 대신 `\n`을 사용하여 개행하고, 코드 전체에서 일관성을 유지합니다.
4.  **최소한의 주석**: 코드가 명확하다면 불필요한 주석을 제거합니다.

### 리팩토링된 코드

```cpp
#include <iostream>

// C++ Fast I/O 최적화
inline void FastIO() {
    std::ios_base::sync_with_stdio(false);
    std::cin.tie(nullptr);
    std::cout.tie(nullptr);
}

int main() {
    FastIO();
    int t;
    std::cin >> t;
    while (t--) {
        int a, b;
        std::cin >> a >> b;
        std::cout << a + b << '\n';
    }
    return 0;
}
```

### 적용된 개념

-   **`std::ios_base::sync_with_stdio(false)`**: C++ 표준 스트림과 C 표준 스트림 간의 동기화를 비활성화합니다. C++ 스트림을 독립적으로 사용하여 I/O 성능을 향상시킵니다.
-   **`std::cin.tie(nullptr)`**: `cin`과 `cout`의 묶음을 해제합니다. 기본적으로 `cin` 작업 전에 `cout` 버퍼를 비우도록 설정되어 있지만, 묶음을 해제하면 이러한 동작을 방지하여 I/O 성능을 개선합니다.
-   **`inline` 함수**: `FastIO` 함수를 inline 함수로 선언하여 함수 호출 오버헤드를 줄입니다. 컴파일러는 가능하다면 함수 호출을 함수의 내용으로 대체하여 실행 속도를 높입니다.
-   **RAII (Resource Acquisition Is Initialization)**: 명시적으로 적용된 것은 아니지만, `FastIO` 함수 내에서 스트림 설정을 변경하고 프로그램이 종료될 때 자동으로 원래 상태로 돌아가도록 하는 것은 RAII의 개념과 유사합니다.

### 사용 예시

위 코드는 `FastIO()` 함수를 호출하여 I/O 스트림을 최적화한 후, 간단한 덧셈 연산을 수행하는 예제입니다. 알고리즘 문제 해결 시 이 코드를 활용하여 실행 시간을 단축할 수 있습니다.

### 주의사항

I/O 최적화는 특정 환경에서만 유효할 수 있으며, 모든 문제에서 항상 성능 향상을 보장하지는 않습니다. 또한, 과도한 최적화는 코드의 가독성을 해칠 수 있으므로 적절한 균형을 유지해야 합니다.

## C++ 날짜 클래스 (Clean Code)

### 목표

C++로 작성된 날짜 클래스를 Clean Code 원칙에 따라 개선하여 가독성, 유지보수성, 확장성을 높입니다.

### 배경

기존 코드는 날짜 처리 로직이 복잡하고, 코드 중복이 있으며, 예외 처리나 유효성 검사가 미흡합니다. Clean Code 원칙을 적용하여 이러한 문제점을 해결하고, 더 안정적이고 효율적인 코드를 만듭니다.

### Clean Code 원칙 적용

1.  **의미 있는 이름**: 변수, 함수, 클래스 이름을 명확하고 이해하기 쉽게 변경합니다.
2.  **함수 분리**: 단일 책임을 갖는 작은 함수로 분리하여 코드 중복을 줄이고 가독성을 높입니다.
3.  **유효성 검사**: 입력 값에 대한 유효성 검사를 추가하여 예외 상황을 방지합니다.
4.  **불변성**: 불변 객체를 사용하여 상태 변경으로 인한 오류를 줄입니다.
5.  **RAII**: 자원 관리를 자동화하여 메모리 누수를 방지합니다.

### 리팩토링된 코드

```cpp
#include <iostream>
#include <stdexcept> // 예외 처리를 위해 포함

class Date {
private:
    int year_;
    int month_; // 1부터 12까지
    int day_;   // 1부터 31까지

public:
    // 생성자: 유효성 검사 포함
    Date(int year, int month, int day) : year_(year), month_(month), day_(day) {
        if (!IsValidDate(year_, month_, day_)) {
            throw std::invalid_argument("Invalid date");
        }
    }

    // 날짜 설정 메서드 (필요한 경우)
    void SetDate(int year, int month, int day) {
        if (!IsValidDate(year, month, day)) {
            throw std::invalid_argument("Invalid date");
        }
        year_ = year;
        month_ = month;
        day_ = day;
    }

    // 날짜 증가 메서드
    void AddDays(int days) {
        day_ += days;
        NormalizeDate();
    }

    void AddMonths(int months) {
        month_ += months;
        NormalizeDate();
    }

    void AddYears(int years) {
        year_ += years;
    }

    // 날짜 표시 메서드
    void ShowDate() const {
        std::cout << year_ << "-" << month_ << "-" << day_ << std::endl;
    }

private:
    // 날짜 유효성 검사
    bool IsValidDate(int year, int month, int day) const {
        if (month < 1 || month > 12) return false;
        if (day < 1 || day > DaysInMonth(year, month)) return false;
        return true;
    }

    // 윤년 확인
    bool IsLeapYear(int year) const {
        return (year % 4 == 0 && year % 100 != 0) || (year % 400 == 0);
    }

    // 월별 일수 계산
    int DaysInMonth(int year, int month) const {
        if (month == 2) {
            return IsLeapYear(year) ? 29 : 28;
        } else if (month == 4 || month == 6 || month == 9 || month == 11) {
            return 30;
        } else {
            return 31;
        }
    }

    // 날짜 정규화
    void NormalizeDate() {
        while (day_ > DaysInMonth(year_, month_)) {
            day_ -= DaysInMonth(year_, month_);
            month_++;
            if (month_ > 12) {
                month_ = 1;
                year_++;
            }
        }
    }
};

int main() {
    try {
        Date date(2024, 1, 31);
        date.ShowDate(); // 출력: 2024-1-31

        date.AddDays(1);
        date.ShowDate(); // 출력: 2024-2-1

        date.AddMonths(1);
        date.ShowDate(); // 출력: 2024-3-1

        date.AddYears(1);
        date.ShowDate(); // 출력: 2025-3-1
    } catch (const std::invalid_argument& e) {
        std::cerr << "Exception: " << e.what() << std::endl;
        return 1;
    }

    return 0;
}
```

### 적용된 개념

-   **RAII (Resource Acquisition Is Initialization)**:
    -   생성자를 통해 객체 초기화 시 유효성 검사를 수행하고, 잘못된 값이 들어오면 예외를 발생시켜 객체 생성을 막습니다. 이는 객체가 항상 유효한 상태를 유지하도록 보장합니다.
-   **예외 처리**:
    -   `std::invalid_argument` 예외를 사용하여 잘못된 날짜 값에 대한 예외 처리를 구현했습니다. 이를 통해 프로그램이 예기치 않은 오류로 종료되는 것을 방지하고, 사용자에게 유용한 오류 메시지를 제공할 수 있습니다.
-   **함수 분리 및 재사용**:
    -   `IsValidDate`, `IsLeapYear`, `DaysInMonth`, `NormalizeDate`와 같은 함수를 분리하여 코드의 가독성을 높이고, 중복 코드를 제거했습니다.
-   **const 정확성**:
    -   `ShowDate`, `IsValidDate`, `IsLeapYear`, `DaysInMonth` 함수를 `const` 멤버 함수로 선언하여 객체의 상태를 변경하지 않음을 명시했습니다.
-   **생성자**:
    -   클래스 생성 시 유효한 날짜인지 확인하여 잘못된 객체 생성을 방지합니다.

### 설명

-   **생성자**: `Date` 클래스의 생성자는 년, 월, 일을 인자로 받아 객체를 초기화합니다. 이때 `IsValidDate` 함수를 호출하여 입력된 날짜가 유효한지 검사하고, 유효하지 않은 경우 `std::invalid_argument` 예외를 발생시킵니다.
-   **날짜 유효성 검사**: `IsValidDate` 함수는 주어진 년, 월, 일이 유효한 날짜인지 확인합니다. 월이 1부터 12 사이의 값인지, 일이 해당 월의 최대 일수를 초과하지 않는지 검사합니다.
-   **윤년 확인**: `IsLeapYear` 함수는 주어진 년도가 윤년인지 확인합니다. 윤년은 4로 나누어 떨어지면서 100으로 나누어 떨어지지 않거나, 400으로 나누어 떨어지는 해입니다.
-   **월별 일수 계산**: `DaysInMonth` 함수는 주어진 년도와 월에 따라 해당 월의 일수를 반환합니다. 윤년인 경우 2월은 29일을 반환합니다.
-   **날짜 정규화**: `NormalizeDate` 함수는 날짜가 유효한 범위를 벗어날 경우 날짜를 정규화합니다. 예를 들어, 1월 32일은 2월 1일로 변경됩니다.

**ai**: ## 언리얼 엔진 개발자를 위한 GC (Garbage Collection) 설명

### GC란 무엇인가?

GC(Garbage Collection, 가비지 컬렉션)는 프로그램에서 더 이상 사용하지 않는 메모리 영역을 자동으로 찾아 해제하여 메모리 누수를 방지하는 기술입니다. 언리얼 엔진에서는 오브젝트(UObject)를 메모리에서 관리할 때 GC가 중요한 역할을 합니다.

### 왜 GC가 중요한가?

-   **메모리 누수 방지**: 개발자가 명시적으로 메모리를 해제하지 않아도 GC가 자동으로 처리하므로 메모리 누수를 줄일 수 있습니다.
-   **개발 편의성**: 메모리 관리에 대한 부담을 줄여 개발자가 게임 로직에 집중할 수 있도록 합니다.
-   **안정성**: 메모리 관련 오류를 줄여 게임의 안정성을 높입니다.

### 언리얼 엔진의 GC 작동 방식

1.  **오브젝트 생성**: 언리얼 엔진에서 `NewObject` 함수 등을 사용하여 오브젝트를 생성하면, GC는 이 오브젝트를 추적하기 시작합니다.
2.  **Root Set**: GC는 "Root Set"이라는 특별한 오브젝트 집합을 관리합니다. 이 Root Set에 속한 오브젝트들은 GC에 의해 삭제되지 않습니다. 예를 들어, 레벨에 배치된 액터(Actor)나 게임 인스턴스 등이 Root Set에 포함됩니다.
3.  **Reachability**: GC는 Root Set에 있는 오브젝트로부터 참조되는 모든 오브젝트를 "reachable"하다고 판단합니다. 즉, Root Set에서부터 참조 체인을 따라 도달할 수 있는 오브젝트들은 삭제되지 않습니다.
4.  **Unreachable 오브젝트 수집**: Root Set에서 도달할 수 없는 오브젝트들은 "unreachable"하다고 판단하고, GC는 이러한 오브젝트들을 수집하여 메모리에서 해제합니다.
5.  **GC 주기**: GC는 주기적으로 또는 필요에 따라 수동으로 실행됩니다. `CollectGarbage()` 함수를 호출하여 GC를 수동으로 실행할 수 있습니다.

### GC 관련 주요 개념

-   **UObject**: 언리얼 엔진의 모든 오브젝트는 `UObject` 클래스를 상속받습니다. GC는 `UObject` 인스턴스들을 관리합니다.
-   **UPROPERTY**: `UPROPERTY` 매크로를 사용하여 오브젝트를 참조하면, GC는 이 참조를 추적합니다. `UPROPERTY`로 선언된 오브젝트 참조는 GC Root로 간주되어 메모리에서 해제되지 않습니다.
-   **TWeakObjectPtr**: 약한 참조(Weak Reference)를 나타내는 스마트 포인터입니다. 오브젝트가 GC에 의해 삭제될 수 있음을 나타내며, 오브젝트가 삭제되면 자동으로 `nullptr`이 됩니다.
-   **Mark & Sweep**: 언리얼 엔진의 GC는 Mark & Sweep 알고리즘을 사용합니다. Mark 단계에서는 Root Set에서부터 시작하여 모든 reachable 오브젝트를 "mark"하고, Sweep 단계에서는 mark되지 않은 unreachable 오브젝트들을 메모리에서 해제합니다.

### GC 팁과 주의사항

-   **순환 참조 피하기**: 오브젝트 간에 순환 참조가 발생하면 GC가 메모리를 해제하지 못할 수 있습니다. `TWeakObjectPtr`를 사용하여 순환 참조를 해결할 수 있습니다.
-   **`UPROPERTY` 사용**: 오브젝트를 멤버 변수로 선언할 때 `UPROPERTY` 매크로를 사용하여 GC가 참조를 추적할 수 있도록 합니다.
-   **수동 GC 호출 주의**: `CollectGarbage()` 함수를 너무 자주 호출하면 성능에 영향을 줄 수 있습니다. 필요한 경우에만 호출하도록 합니다.
-   **오브젝트 라이프사이클 관리**: 오브젝트의 생성과 소멸 시점을 명확히 관리하여 불필요한 오브젝트가 메모리에 남아있지 않도록 합니다.

### 결론

GC는 언리얼 엔진 개발에서 메모리 관리를 자동화하여 개발자가 게임 로직에 집중할 수 있도록 돕는 중요한 시스템입니다. GC의 작동 방식을 이해하고, 관련 개념과 팁을 활용하면 메모리 누수를 방지하고 게임의 안정성을 높일 수 있습니다.
