7.  **QuadTree 관련 오류:**
    -   QuadTree.h에 Actor를 전방 선언하는 대신 #include "Actor"를 사용하여 해결했습니다.
    -   GameLevel.h에서 using namespace Wanted;를 사용하지 않아 발생한 ambiguous 오류를 해결했습니다.

8.  **어이없는 오류:**
    -   전방 선언 시 QuadTree를 Quadtree로 잘못 입력하여 발생한 문제를 해결했습니다.

### 개선된 코드 제공 (예시)

```cpp
// 기존 코드
for (int i = 0; i < objects.size(); ++i) {
    if (objects[i]->IsDead()) {
        delete objects[i];
        objects.erase(objects.begin() + i); // O(N)
    }
}

// 개선된 코드 (스왑-팝)
for (int i = 0; i < objects.size();) {
    if (objects[i]->IsDead()) {
        delete objects[i];
        objects[i] = objects.back();
        objects.pop_back(); // O(1)
    } else {
        ++i;
    }
}
```

### 면접 예상 질문 및 답변

**질문:** QuadTree를 구현하면서 raw 포인터를 사용했는데, 스마트 포인터를 사용하지 않은 이유는 무엇이며, raw 포인터를 사용할 때 주의해야 할 점은 무엇인가요?

**답변:** 스마트 포인터를 사용하면 메모리 관리를 자동으로 해 주지만, QuadTree의 노드가 자식 노드를 소유하는 구조에서 스마트 포인터를 사용하면 순환 참조 문제가 발생할 수 있습니다. 따라서 raw 포인터를 사용하여 메모리 관리를 직접 수행했습니다. raw 포인터를 사용할 때는 다음과 같은 점에 주의해야 합니다.

-   메모리 누수가 발생하지 않도록 delete를 통해 메모리를 해제해야 합니다.
-   댕글링 포인터가 발생하지 않도록 주의해야 합니다.
-   이중 해제가 발생하지 않도록 주의해야 합니다.
