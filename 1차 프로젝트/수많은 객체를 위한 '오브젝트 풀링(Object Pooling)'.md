
   * 핵심 목표: 수백, 수천 개의 총알과 적을 생성하고 제거할 때 발생하는 성능 부하(new, delete 연산 비용)를 최소화한다.
   * 구현 전략:
       1. `ObjectPool` 클래스 설계: Enemy, PlayerBullet 등 재활용할 객체 타입별로 오브젝트 풀을 만듭니다.
       2. 사전 생성: 게임 시작 시, 각 풀에 일정 개수(예: 총알 500개, 적 200개)의 객체를 미리 생성해두고 inactive 상태로 둡니다.
       3. 가져오기(`Get`): 총알이나 적이 필요할 때 new 대신 pool.Get()을 호출합니다. 풀은 inactive 상태인 객체를 찾아 위치, 체력 등 상태를 초기화한 뒤
          active로 전환하여 반환합니다.
       4. 반납하기(`Return`): 객체가 화면 밖으로 나가거나 죽었을 때 delete 대신 pool.Return(object)을 호출합니다. 해당 객체는 다시 inactive 상태가 되어
          재사용을 기다립니다.
   * 위기와 해결:
       * 위기(Problem): 게임 중후반, 수많은 객체가 동적으로 생성/소멸되면서 메모리 단편화와 CPU 부하로 게임이 끊기거나 멈춘다.
       * 해결(Solution): 오브젝트 풀링을 통해 메모리 할당/해제 오버헤드를 '0'에 가깝게 만들어, 부드럽고 안정적인 프레임을 유지합니다.
