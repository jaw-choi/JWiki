 1 #if ENGINE_BUILD_DLL // <-- 이 부분이 핵심입니다.
   2 #define WANTED_API DLLEXPORT
   3 #else
   4 #define WANTED_API DLLIMPORT
   5 #endif


  이 매크로가 `DLLIMPORT`로 지정된 이유


   1. `#if` 전처리기 지시자: #if ENGINE_BUILD_DLL 이라는 부분은 컴파일러가 소스 코드를 컴파일하기 전에
      ENGINE_BUILD_DLL이라는 전처리 변수가 정의되어 있고 그 값이 0이 아닌지 확인합니다.
   2. `ENGINE_BUILD_DLL`의 역할:
       * Engine DLL을 빌드할 때: Engine 프로젝트를 빌드하는 시점에는 ENGINE_BUILD_DLL이라는 전처리 변수가
         정의되어 있어야 (예: `ENGINE_BUILD_DLL=1`) #if 조건이 참이 되어 WANTED_API가 DLLEXPORT로
         확장됩니다. 이렇게 되면 Engine 프로젝트 내의 클래스나 함수들이 .dll 파일 밖으로
         "내보내진다(export)"는 표시가 됩니다.
       * `Engine.dll`을 사용할 때: Game 프로젝트와 같이 Engine.dll을 가져다 쓰는 프로젝트를 빌드하는
         시점에는 ENGINE_BUILD_DLL이 정의되어 있지 않아야 #if 조건이 거짓이 되어 WANTED_API가 DLLIMPORT로
         확장됩니다. 이렇게 되면 Game 프로젝트가 Engine.dll로부터 클래스나 함수들을 "가져온다(import)"는
         표시가 됩니다.
   3. 오류의 원인: WANTED_API가 DLLEXPORT가 아닌 DLLIMPORT로 지정되었다는 것은, Engine 프로젝트를 빌드할 때
      `ENGINE_BUILD_DLL`이라는 전처리 변수가 제대로 정의되지 않았기 때문입니다. #if ENGINE_BUILD_DLL 조건이
      거짓으로 평가되어 else 블록이 실행된 것입니다.

  제공해주신 코드에 //#define ENGINE_BUILD_DLL 1 이 부분이 주석 처리되어 있습니다. 바로 이것이 원인입니다.
  코드를 통해 전역적으로 정의하려 했지만 주석 처리되어 있어서 실제로는 정의되지 않은 것입니다.


  올바른 `ENGINE_BUILD_DLL` 정의 방법

  ENGINE_BUILD_DLL과 같은 전처리기 변수는 일반적으로 코드 파일 내에서 직접 #define하지 않고, 프로젝트
  설정에서 정의하는 것이 표준적인 방법입니다.

->Gemini 답변인데 그렇다기엔 다른 파일에서는 Export 잘가르켜서
-> 질문 해봐야할듯




   * Visual Studio 기준:
       1. `Engine` 프로젝트를 선택하고, 마우스 오른쪽 버튼을 클릭하여 속성(Properties)을 엽니다.
       2. 구성 속성(Configuration Properties) -> C/C++ -> 전처리기(Preprocessor) 탭으로 이동합니다.
       3. 전처리기 정의(Preprocessor Definitions) 항목에 ENGINE_BUILD_DLL을 추가합니다. (다른 정의들과
          세미콜론;으로 구분합니다.)
       4. 변경 사항을 저장하고 Engine 프로젝트를 다시 빌드합니다.


  이렇게 Engine 프로젝트 설정에서 ENGINE_BUILD_DLL을 정의하면, Engine 프로젝트를 빌드할 때는 WANTED_API가
  DLLEXPORT로 확장되고, Game 프로젝트를 빌드할 때는 자동으로 ENGINE_BUILD_DLL이 정의되지 않아 DLLIMPORT로
  확장될 것입니다.


  이 수정을 통해 IStatHolder의 가상 소멸자가 Engine.dll에서 올바르게 내보내지고, 링커 오류가 해결될
  것입니다.
