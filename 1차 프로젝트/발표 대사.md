## 개인 프로젝트 분석 및 개선 제안

### 프로젝트 진행 일정 (실행 내역)

- **1일차:** Player, Enemy, Bullet 클래스 및 쫓아가는 기능 구현, Vector2 float 구현
- **2일차:** 충돌 구현 (AABB, QuadTree)
- **3~5일차:** HP 시스템, 무적 기능, UI (HP Bar, Level 표시), 인 게임 업그레이드, 스탯 저장/읽기, 이동 방식 변경, 충돌 인지 애니메이션, 스탯 적용, 적 추격, 오브젝트 풀링, 디버그 모드, 맵 생성, 카메라 이동, UI 구현 등

### 필수 구현 기술 및 구현 방법

1.  **광활한 맵과 스크롤링 카메라:**
    -   카메라 Margin을 설정하여 카메라가 맵의 경계를 넘어가지 않도록 구현했습니다.
    -   잔디를 심어 맵을 시각적으로 풍성하게 만들었습니다.
2.  **오브젝트 풀링 (Object Pooling):**
    -   Gem, Enemy, Bullet 등에 오브젝트 풀링을 적용하여 메모리 할당 및 해제 비용을 줄이고 성능을 최적화할 계획입니다.
3.  **효율적인 충돌 처리 (Quadtree):**
    -   AABB 충돌 처리를 구현하고, QuadTree 공간 분할을 통해 충돌 검사 대상 객체 수를 줄여 성능을 향상시켰습니다.
    -   QuadTree 구현 시 스마트 포인터 대신 raw 포인터를 사용하여 메모리 관리에 주의를 기울였습니다.
4.  **지능적인 적 AI (A\* 알고리즘 최적화):**
    -   A\* 알고리즘을 적용하려 했으나, 적의 움직임이 부자연스러워 방향 벡터를 사용하는 방식으로 변경했습니다.
    -   추후 맵 구조를 고려하여 A\* 알고리즘을 최적화할 계획입니다.
5.  **절차적 맵 생성 및 스테이지 설계:**
    -   절차적 맵 생성을 통해 다양한 맵을 자동으로 생성하고, 스테이지를 설계할 계획입니다.

### 트러블슈팅

1.  **Enemy 이동 속도 문제:**
    -   Normalized를 적용하지 않아 Enemy가 멀리 있을 때는 빠르고 가까울 때는 느려지는 문제가 발생했습니다. Vector2f, normalized 구현 후 해결했습니다.
2.  **Bullet moveSpeed 조절 문제:**
    -   int, float 형변환에 주의하여 moveSpeed가 정상적으로 조절되도록 수정했습니다.
3.  **Enemy 이동 문제:**
    -   Tick 함수 내에서 timer.tick() 이후 return; 문이 있어 move 함수가 실행되지 않는 문제를 해결했습니다.
4.  **레벨업 시 게임 멈춤 문제:**
    -   GameLevel()에서 super::Tick(deltaTime)을 그대로 두고 하위 코드에서 deltaTime을 0으로 설정하여 발생한 문제를 해결했습니다.
5.  **Interface와 Stat struct 적용 오류:**
    -   WANTED\_API 매크로가 dllexport가 아닌 dllimport로 설정되어 링크 에러가 발생했습니다. 매크로 설정을 확인하고 직접 \_\_declspec(dllexport)를 붙여 해결했습니다.
6.  **Quadtree 적용 후 메모리 에러:**
    -   Enemy dead 시 메모리 에러가 발생했습니다. 이미 지워진 메모리에 접근하려는 시도로 인해 발생한 문제로, Enemy끼리 겹치는지 체크하는 부분을 수정하여 해결했습니다.
7.  **QuadTree 관련 오류:**
    -   QuadTree.h에 Actor를 전방 선언하는 대신 #include "Actor"를 사용하여 해결했습니다.
    -   GameLevel.h에서 using namespace Wanted;를 사용하지 않아 발생한 ambiguous 오류를 해결했습니다.
    -   AABB에서 QuadTree로 전환 후 delete array 에러가 발생했습니다. 죽은 Enemy까지 코드를 실행시켜 발생한 문제로, actor->IsActive()로 살아있는 객체만 QuadTree에 추가하도록 수정했습니다.
8.  **어이없는 오류:**
    -   전방 선언 시 QuadTree를 Quadtree로 잘못 입력하여 발생한 문제를 해결했습니다.
    -   if 문 끝에 세미콜론을 잘못 사용하여 발생한 문제를 해결했습니다.

### 개선된 코드 제공 (예시)

```cpp
// 기존 코드
for (int i = 0; i < objects.size(); ++i) {
    if (objects[i]->IsDead()) {
        delete objects[i];
        objects.erase(objects.begin() + i); // O(N)
    }
}

// 개선된 코드 (스왑-팝)
for (int i = 0; i < objects.size();) {
    if (objects[i]->IsDead()) {
        delete objects[i];
        objects[i] = objects.back();
        objects.pop_back(); // O(1)
    } else {
        ++i;
    }
}
```

### 성능 최적화 포인트

-   **Memory:**
    -   오브젝트 풀링을 통해 객체 생성 및 소멸 비용을 줄입니다.
    -   QuadTree를 통해 충돌 검사 대상 객체 수를 줄여 메모리 접근을 최적화합니다.
-   **CPU:**
    -   불필요한 연산을 줄이고, 알고리즘 효율성을 높입니다. (예: O(N)에서 O(1)으로 변경)
    -   병렬 처리를 통해 CPU 활용률을 높입니다.

### 면접 예상 질문 및 답변

**질문:** QuadTree를 구현하면서 raw 포인터를 사용했는데, 스마트 포인터를 사용하지 않은 이유는 무엇이며, raw 포인터를 사용할 때 주의해야 할 점은 무엇인가요?

**답변:** 스마트 포인터를 사용하면 메모리 관리를 자동으로 해 주지만, QuadTree의 노드가 자식 노드를 소유하는 구조에서 스마트 포인터를 사용하면 순환 참조 문제가 발생할 수 있습니다. 따라서 raw 포인터를 사용하여 메모리 관리를 직접 수행했습니다. raw 포인터를 사용할 때는 다음과 같은 점에 주의해야 합니다.

-   메모리 누수가 발생하지 않도록 delete를 통해 메모리를 해제해야 합니다.
-   댕글링 포인터가 발생하지 않도록 주의해야 합니다.
-   이중 해제가 발생하지 않도록 주의해야 합니다.
