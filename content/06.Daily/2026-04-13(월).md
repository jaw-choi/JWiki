==Tarray== : vector와 거의 유사함.
	Push_back : Add,Emplace 인자를 하나 뒤에 붙이고 싶을때
	AddUnique: 중복없이 추가하고싶을떄
	Append : 덩어리를 뒤에 붙이고 싶을때.
	Insert : 특정 Index에 추가하고싶을때 나머지 뒤로 밀림
	
- **TArray 요소 추가 방식 정리**
    - `Add` : 기본 추가, **복사 방식**
    - `Emplace` : **이동/직접 생성**을 더 명시적으로 하고 싶을 때 사용
    - `Push` : `Add`와 기능이 거의 같음
    - `Append` : 다른 배열이나 메모리 덩어리를 **뒤에 한꺼번에 이어 붙일 때** 사용
    - 중복 없이 넣고 싶으면 `AddUnique` 사용
    - `Insert`는 특정 인덱스 위치에 요소를 넣는 함수
    - `SetNum`은 배열 **크기를 늘리거나 줄일 때** 사용
- **순회 방식**
    - 범위 기반 `for` 사용 가능
    - 인덱스 기반 반복문도 가능
    - 일반 이터레이터, `const` 이터레이터도 제공함
- **정렬**
    - `Sort` 제공
    - 원하는 기준으로 정렬하고 싶으면 **람다**를 넘겨서 오름차순/내림차순 등 직접 기준 지정 가능
    - 힙 관련 정렬/처리도 지원함
- **자주 쓰는 기능**
    - `Num()` : 현재 저장된 요소 개수 확인
    - `GetData()` : 내부 원시 배열 포인터 접근
    - `Find` 계열 함수도 제공
- **슬랙(Slack) 개념**
    - 슬랙은 배열이 미리 확보해 둔 **여유 공간**
    - 이 여유 공간이 있으면 요소 추가 시 매번 재할당하지 않아도 돼서 성능에 유리함
    - 공간이 다 차면 다시 재할당이 일어남
- **언리얼 TArray 특징**
    - 언리얼은 생성 자체를 빠르게 하려고 **초기 슬랙이 0인 경우가 많음**
    - 즉, 처음 만들 때 미리 넉넉히 공간을 잡아두기보다 필요할 때 늘리는 쪽에 가깝게 설계됨
- **핵심 정리**
    - `TArray`는 기본적으로 **동적 배열**
    - 뒤에 추가하는 작업에 강하고
    - 중간 삽입/삭제는 가능하지만 비용이 더 큼
    - 중복 방지, 정렬, 탐색, 원시 메모리 접근까지 다양한 기능을 기본 제공함

## 📌 전체 주제

이 텍스트는 **언리얼 C++ 컨테이너 라이브러리** 중  
**`TArray`와 `TSet`의 차이, 내부 구조, 사용 상황, 디버깅 포인트**를 설명한 내용이에요.

---

## 1. `TArray` 핵심

- 가장 기본적으로 많이 쓰는 **동적 배열**
- **순서가 보장**됨
- 인덱스로 접근하기 편함
- 메모리에 비교적 **연속적으로 저장**됨
- 중간 삽입/삭제 시 뒤 요소들을 밀거나 당겨야 해서 비용이 큼

### 관련 예시

- `RemoveAll`로 조건에 맞는 요소 삭제
- 뒤에 다시 값 추가 가능
- `GetData()`로 C 배열처럼 메모리 복사 가능
- 배열 비교 시 **개수 + 값 + 순서**까지 같아야 같다고 봄
- 합계 계산은 직접 순회하거나 알고리즘 함수로 처리 가능

---

## 2. `TSet` 핵심

- **중복 없는 데이터 집합** 저장용
- **순서는 보장되지 않음**
- 값 자체를 **키처럼 사용**
- 해시 기반이라 **검색이 빠름**
- “순서보다 검색 성능, 고유값 유지”가 중요할 때 적합함

### 특징

- 같은 값 추가해도 중복 저장 안 됨
- `Contains`로 포함 여부 확인 가능
- 삭제는 보통 **인덱스보다 값 기반 제거**를 권장
- 반복은 범위 기반 for, iterator 둘 다 가능

---

## 3. `TSet` 내부 구조 핵심

`TSet`은 단순한 “정렬된 set”이라기보다,  
언리얼에서는 **해시 + 희소 배열(Sparse Array)** 구조에 가까운 방식으로 설명되고 있어요.

### 희소 배열 의미

- 요소를 삭제해도 뒤 데이터를 바로 당기지 않음
- 빈 자리를 **invalid 상태**로 남겨둠
- 나중에 새 요소가 들어오면 그 빈칸을 재활용함
- 그래서 삭제/삽입이 비교적 빠름
- 대신 **메모리 공간이 깔끔하게 연속적이지 않을 수 있음**

### 중요한 결과

- 사용자가 보는 인덱스/순서와
- 실제 메모리에 저장된 위치가  
    **같지 않을 수 있음**

---

## 4. `STL set`과 `언리얼 TSet` 비교

텍스트에서는 둘을 비교하면서 설명해요.

### STL `set`

- 보통 **레드블랙트리**
- 정렬 유지
- 탐색은 빠르지만
- 순회/재구성 비용, 메모리 접근 측면에서 부담이 있을 수 있음

### Unreal `TSet`

- 해시 기반
- 정렬보다는 **빠른 검색, 빠른 추가/삭제**에 초점
- 순서 안정성은 떨어짐
- 중복 허용 안 함

---

## 5. 언제 무엇을 쓰면 되는가

### `TArray` 추천 상황

- 순서가 중요할 때
- 인덱스 접근이 중요할 때
- 일반적인 저장/순회가 많을 때
- 가장 범용적으로 쓸 때

### `TSet` 추천 상황

- 중복을 막고 싶을 때
- 특정 값이 있는지 **자주 검색**할 때
- 순서는 중요하지 않을 때
- 성능상 검색/삭제가 중요할 때

---

## 6. 디버깅 포인트

- `TArray`는 비교적 구조 확인이 쉬움
- `TSet`은 내부가 희소 배열 기반이라 빈칸, invalid 상태 등을 같이 봐야 이해가 쉬움
- 디버깅 시 **Development Editor보다 DebugGame** 쪽이 구조 파악에 유리하다는 내용도 들어 있어요.

---

## 7. 한 줄 결론

**`TArray` = 순서 있는 기본 동적 배열**  
**`TSet` = 순서 없는 중복 제거용 고속 검색 컨테이너**  
그리고 `TSet`은 내부적으로 **빈 공간을 남기며 관리하는 희소 배열 구조**를 활용해서 성능을 챙긴다는 점이 핵심이에요.
