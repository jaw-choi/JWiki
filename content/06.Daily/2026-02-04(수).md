## 메모

- **힙 메모리와 전역 메모리**:
    
    - 힙에 할당된 메모리는 동적으로 관리되며, 전역(static) 변수는 프로그램이 시작될 때 데이터 영역에 고정된 값으로 존재합니다.        
    - 전역 공간에 많은 데이터를 올리지 않는 이유는 메모리 효율성과 관리 편의성 때문이며, 주로 대용량 데이터는 힙에 할당되어 사용됩니다.
        
- **싱글톤 패턴**:
    
    - 싱글톤은 애플리케이션에서 하나의 인스턴스를 공유하는 방식으로, 자주 쓰이는 기법이지만 여러 객체가 필요한 경우에는 다른 구조체나 클래스를 통해 관리할 수 있습니다.
        
    - '구조체'를 묶는 방법에 대해서도 논의되었으며, 일반적으로 구조체를 묶는 것은 편의성과 코드 관리 측면에서 유용하지만, 지나치게 복잡한 구조는 피해야 한다고 강조되었습니다.
        
- **템플릿과 친구 클래스**:
    
    - 템플릿에서 세이프 딜리트를 사용할 때 문제가 발생할 수 있다는 점도 언급되었습니다. 템플릿 함수는 친구(friend) 클래스나 함수와 달리 인스턴스화가 되어야만 사용할 수 있기 때문에 친구 등록이 중요합니다.
        
- **게임 엔진 설계 및 코드 최적화**:
    
    - 엔진의 설계에서는 코드 간의 의존성을 줄이고, 가독성을 높이기 위해 헤더 파일을 잘 관리하는 것이 중요하다고 설명하였습니다.
        
    - 이와 함께, 엔진 클래스나 게임 객체에 대한 메모리 관리를 효율적으로 하기 위한 여러 기법들이 논의되었습니다.
        
- **게임 프로젝트 개발**:
    
    - 게임 레벨을 구현하고, 플레이어 액터와 총알 발사 등의 기초적인 게임 로직을 추가하는 과정도 다루었습니다. 이를 위해 클래스와 헤더 파일을 잘 관리하고, 게임 오브젝트를 구현하여 레벨에서 액터가 잘 동작하도록 했습니다.
        
    - 프레임 단위로 동작하는 게임 시스템에서는 이동 속도를 계산할 때 '델타 타임(delta time)'을 사용하여 프레임 시간에 관계없이 동일한 결과를 얻을 수 있도록 했습니다.

이 내용은 게임 개발에서 타이머를 구현하는 과정과 관련된 설명입니다. 핵심적으로 다룬 부분은 타이머 클래스를 만들어서 경과 시간을 추적하고 이를 활용하는 방법입니다. 구체적으로 설명한 내용은 다음과 같습니다:

1. **타이머 클래스 구현**:
    
    - `타이머` 클래스에서 경과 시간을 추적하고, `target time`을 설정하여 목표 시간이 되었는지 비교합니다.
        
    - `경과 시간 초기화`와 같은 기능을 제공하며, 게임 로직에서 시간 관리를 더 효율적으로 할 수 있습니다.
        
2. **타이머 업데이트**:
    
    - 타이머를 업데이트할 때 델타 타임을 클램프하여 오버플로우를 방지하고, 경과 시간이 목표 시간보다 많이 흘렀는지 확인합니다.
        
    - 업데이트 함수, 리셋 함수 등 필요한 기능들을 클래스에 구현하여, 여러 곳에서 사용 가능합니다.
        
3. **타이머 클래스 확장**:
    
    - 반복적인 타이머 작업을 위해 콜백 함수 기능을 추가하고, 타이머를 업데이트하는 작업을 반복적으로 처리할 수 있도록 합니다.
        
    - 이런 기능을 이용해 게임 내 여러 이벤트나 반복 작업을 타이머 기반으로 쉽게 관리할 수 있습니다.
        
4. **게임 로직 구현**:
    
    - 타이머 기능을 활용하여 발사 타이머, 적 스폰 타이머 등을 구현하며, 이벤트가 발생한 후 타이머를 리셋하거나 업데이트하는 방식으로 게임 로직을 전개합니다.
        
5. **추가적인 사항**:
    
    - 코드를 작성하면서 코딩 스타일, 객체 지향 설계, 그리고 다른 개발 도구들에 대한 얘기도 다룹니다.
