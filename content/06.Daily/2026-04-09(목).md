### 1. UObject는 일반 C++ 객체처럼 만들면 안 됨

언리얼에서 객체를 제대로 사용하려면 일반적인 방식이 아니라 **언리얼이 제공하는 특별한 생성 방식**을 써야 합니다.  
그래야 엔진이 그 객체를 추적하고, 타입 정보나 메모리 관리 같은 기능을 제대로 지원할 수 있습니다.

### 2. 타입 정보는 리플렉션 시스템으로 가져옴

언리얼은 클래스와 객체의 정보를 **리플렉션 시스템**으로 관리합니다.

- 실제 생성된 인스턴스에서 클래스 정보를 가져올 수 있음
- 클래스 타입 자체에서도 정보를 가져올 수 있음
- 런타임과 클래스 타입 양쪽에서 타입 정보를 확인할 수 있음

즉, **“이 객체가 어떤 클래스인지”, “이 클래스가 어떤 속성을 갖는지”**를 엔진이 알 수 있게 해주는 구조입니다.

### 3. CDO(Class Default Object)란?

각 언리얼 클래스에는 **기본값을 담아두는 특별한 객체**가 하나씩 존재하는데, 이것을 **CDO**라고 합니다.

- CDO는 해당 클래스의 기본 프로퍼티 값을 보관함
- 새로운 객체를 만들 때 이 CDO의 값을 기준으로 초기화됨
- 같은 클래스에서 여러 인스턴스를 많이 만들 때 매우 유용함

예를 들어, 타워디펜스에서 같은 적 몬스터를 여러 마리 생성할 때  
매번 일일이 값을 넣는 것이 아니라 **기본값은 CDO에서 가져와 빠르게 생성**하는 방식입니다.

### 4. CDO의 특징

- 엔진 초기화 과정에서 생성됨
- 콘텐츠 제작자는 CDO가 준비되어 있는 상태를 신뢰하고 사용 가능
- `GetDefaultObject()` 같은 함수로 가져올 수 있음
- 단, **처음 생성된 뒤에는 에디터/엔진을 다시 시작하지 않으면 변경사항이 즉시 반영되지 않을 수 있음**

이 부분이 중요합니다.  
즉, **기본값을 바꿨는데 CDO가 예전 값을 계속 들고 있는 경우**가 생길 수 있어서, 재실행이 필요할 수 있습니다.

### 5. UCLASS / UPROPERTY / UFUNCTION 매크로 역할

언리얼에서는 클래스, 프로퍼티, 함수에 매크로를 붙이면  
리플렉션 시스템이 이를 인식해서 자동으로 관리합니다.

예를 들면:

- 프로퍼티 자동 초기화
- 에디터 노출
- 직렬화 지원
- 가비지 컬렉션 추적
- 블루프린트 연동

기본 초기화도 자동으로 이뤄져서

- 객체 포인터는 `nullptr`
- 숫자형은 `0`  
    등으로 채워집니다.

### 6. 메모리 관리와 레퍼런스 추적

리플렉션 시스템에 등록된 객체는 언리얼이 참조 관계를 추적할 수 있어서  
**가비지 컬렉션(GC)** 과 **댕글링 포인터 예방**에 도움이 됩니다.

예를 들어:

- 액터나 컴포넌트가 제거되면
- 더 이상 유효하지 않은 참조를 엔진이 파악해서
- 잘못된 접근 위험을 줄여줌

즉, **실제 객체는 사라졌는데 포인터만 남아 있는 문제**를 줄이기 위한 구조입니다.

### 7. 직렬화 지원

언리얼 객체와 프로퍼티는 **직렬화**도 지원합니다.  
그래서 저장, 로드, 복제, 에디터 데이터 처리 등에 활용됩니다.

### 8. 객체 생성 시 실제로 일어나는 일

새 객체를 만들면 보통

1. 클래스 정보를 확인하고
2. 해당 클래스의 CDO를 참고해서
3. 기본값을 복사한 뒤
4. 필요한 추가 초기화를 진행합니다.

즉, **CDO는 객체 생성의 기준 템플릿 같은 역할**을 합니다.

### 9. 코드에서 자주 보는 개념

설명 중 언급된 것들:

- `Super` : 부모 클래스 접근
- `Cast<>` : 언리얼 방식의 형변환
- `GetDefaultObject()` : CDO 접근
- `StaticClass()` : 클래스 타입 정보 얻기

이런 것들은 언리얼 C++에서 매우 자주 쓰입니다.

## 한 줄 핵심 정리

**언리얼은 UObject + 리플렉션 시스템을 기반으로 타입 정보, 기본값(CDO), 메모리 관리, 직렬화, 에디터 연동을 통합해서 관리하며, 새 객체는 보통 CDO의 기본값을 바탕으로 생성된다**는 내용입니다.
