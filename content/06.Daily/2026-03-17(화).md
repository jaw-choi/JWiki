유한 스테이트 머신 (유한 상태 기계)
FSM - Finite State Machine

상태(State) 기반으로 기능을 구현하는 방법(모델).

용어
상태(State)
 - 시작(Start)
 - 틱(Update, Tick)
 - 끝(End)
 - 예: A상태 B상태로 전환 발생된 경우-> A.End 이벤트 호출 -> B.Start 이벤트 호출 -> B.Update 이벤트 반복 호출

트랜지션(전환, Transition)
 - 특정 조건을 만족 했을 때 한 상태에서 다른 상태로 변경을 가능하게 함.
 - 상태의 전환은 연결된 상태끼리만 가능

조건(Condition)/트랜지션 조건(Transition Condition)
 - 전환을 발생하게하는 조건
[FSM 관련 자료](https://gameprogrammingpatterns.com/state.html)

# 1. 언리얼에서 컨트롤러의 역할

언리얼 구조에서 **PlayerController는 사용자를 대표하는 객체**

구조 흐름

사용자 입력  
   ↓  
PlayerController  
   ↓  
Pawn (Character)  
   ↓  
Animation / Movement

컨트롤러의 주요 역할

1. **입력 처리**

- Input Mapping Context 사용
    
- 어떤 입력 시스템을 사용할지 지정
    
- 입력 이벤트를 받아 캐릭터에 전달
    

예

마우스 이동 → 카메라 회전  
키보드 입력 → 이동  
마우스 클릭 → 공격

2. **카메라 관리**

컨트롤러는 **Camera Manager를 통해 카메라를 제어**

구조

Controller  
   ↓  
PlayerCameraManager  
   ↓  
Camera Component

즉

**컨트롤러 → 카메라 매니저 → 실제 카메라**

---

# 2. 카메라 각도 제한 (Camera Manager)

카메라 회전 제한은 **PlayerCameraManager에서 설정**

주요 옵션

|값|의미|
|---|---|
|Pitch|위/아래 회전|
|Yaw|좌우 회전|
|Roll|기울기|

예시

Pitch Min : -45  
Pitch Max : 45

효과

- 위/아래 회전 제한
    
- 캐릭터가 과도하게 위나 아래를 보지 않도록 제한
    

Yaw는 보통

-360 ~ 360

→ 자유 회전

---

Input Action  
   ↓

# 5. 애니메이션 시스템 구조

언리얼 애니메이션은 **FSM 기반**

FSM = Finite State Machine

구성 요소

|요소|의미|
|---|---|
|State|상태|
|Transition|상태 전환|
|Condition|전환 조건|

예

Locomotion (이동)  
    ↓  
Battle (전투)

# 8. 애니메이션 몽타주 (Animation Montage)

몽타주는 **특수한 애니메이션 실행 시스템**

일반 애니메이션

State Machine이 자동 실행

몽타주

로직에서 직접 실행

즉

블루프린트 → 애니메이션 강제 실행

예

공격  
피격  
스킬

---

### 몽타주 특징

1. 로직에서 직접 실행 가능

Play Montage

2. 현재 애니메이션을 중단하고 실행

현재 애니메이션 Stop  
→ Montage 실행

3. 콤보 구현 가능

Attack1  
Attack2  
Attack3  
Attack4

4. 이벤트 트리거 가능

예

타격 판정  
사운드  
이펙트

---

# 9. 몽타주 사용 이유

State Machine만 사용하면

문제

입력 기반 애니메이션 제어 어려움

그래서

로직 → 애니메이션 직접 제어

용도로 몽타주 사용
