 핵심 목표: 총알과 같은 빈번하게 생성/소멸되는 객체들을 효율적으로 관리하기 위한 오브젝트 풀링 시스템을 구축한다. 플레이어의 총알 발사 로직을 오브젝트
     풀에 통합한다.
   * 구현 내용:
       1. `ObjectPool` 템플릿 클래스 구현:
           * Engine/Util 또는 Engine/Common에 ObjectPool.h/ObjectPool.cpp 파일을 생성하고 template <typename T>를 사용하는 제네릭 ObjectPool 클래스를
             구현합니다.
           * std::vector를 사용하여 객체들을 저장하고, Get() (활성화) 및 Return() (비활성화) 메서드를 가집니다.
       2. `PlayerBullet` 오브젝트 풀 적용:
           * GameLevel 또는 Player 클래스에 ObjectPool<PlayerBullet> 인스턴스를 생성합니다.
           * 게임 시작 시 풀을 미리 초기화하여 일정 개수의 PlayerBullet 객체를 생성해 둡니다.
           * Player가 총알을 발사할 때 new PlayerBullet() 대신 pool.Get()을 호출하여 총알을 가져옵니다.
           * 총알이 화면 밖으로 나가거나 적과 충돌하여 비활성화될 때 delete bullet 대신 pool.Return(bullet)을 호출합니다.
       3. 기본 적 스폰 및 이동:
           * GameLevel에 간단한 EnemySpawner 로직을 추가하여 일정 시간마다 화면 밖에 Enemy를 생성하고, Enemy는 플레이어를 향해 단순하게 이동하도록
             구현합니다. (A*는 아직 적용하지 않습니다.)
   * 테스트:
       * 플레이어가 총알을 무한정 발사해도 프레임 드랍이 없는지 확인.
       * 디버그 메시지를 통해 총알 객체가 new/delete 대신 풀에서 재활용되는지 확인.
       * 적이 제대로 스폰되고 플레이어를 향해 이동하는지 확인.
   * 위기와 해결:
       * 위기(Problem): ObjectPool에서 객체를 가져올 때 초기화 로직을 누락하여 이전에 사용된 객체의 잔여 데이터가 남아 의도치 않은 동작을 하거나,
         Get()/Return() 호출이 누락되어 메모리 누수가 발생한다.
       * 해결(Solution): ObjectPool::Get()에서 객체를 활성화할 때 Reset() 또는 Init() 메서드를 호출하여 필요한 모든 상태 변수를 명확하게 초기화하도록
         합니다. 또한, 객체가 비활성화될 모든 조건(화면 밖, 충돌 등)에서 pool.Return()이 호출되도록 철저히 검토합니다.
