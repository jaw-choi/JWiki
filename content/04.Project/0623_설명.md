크립라운드 전투 시작 시 태그 처리 흐름
  
  1. 태그 구조
  Champion_State_Player1_Field  → Player1 필드 기물
  Champion_State_Player1_Bench  → Player1 대기석 기물
  각 플레이어마다 인덱스별로 존재하고, PlayerState::BeginPlay()에서 배열로 초기화됩니다.

  2. 왜 Unit->Team 대신 태그를 쓰나

  Unit->Team은 OnRep_OwnerPlayerIndex()에서 GetFirstPlayerController()(항상 Player1 기준)로 설정됩니다. 서버에서 Player2,
  3의 챔피언은 모두 Enemy로 판별 → CombatManager에 Ally/Enemy가 섞이는 버그 발생.

  태그는 명시적으로 AddLooseGameplayTag로 부착되므로 뷰어 기준이 아닌 소유권 기준으로 신뢰할 수 있습니다.

  3. StartCreepCombat() 흐름
  FGameplayTag FieldTag = GetFieldTag(); // Champion_State_PlayerX_Field

  // 필드 태그 보유 챔피언만 → Ally
  for (Champion : OwnedChampions)
      if (ChampASC->HasMatchingGameplayTag(FieldTag))
          CombatManager->RegisterAlly(Champion);  // 명시적 Ally

  // 크립은 항상 → Enemy
  for (Creep : ActiveCreeps)
      CombatManager->RegisterEnemy(Creep);  // 명시적 Enemy

  결과적으로:
  - 필드/대기석 구분: FieldTag 필터로 대기석 기물 자동 제외
  - 팀 구분: RegisterAlly/RegisterEnemy로 Unit->Team 의존성 제거
  - 보드 간 격리: 각 PlayerState의 CombatManager가 독립적으로 관리
