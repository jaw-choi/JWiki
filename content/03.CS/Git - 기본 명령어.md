## 1. 한 줄 요약

Git은 분산 버전 관리 시스템으로, 코드 변경 사항을 추적하고 협업을 용이하게 한다.

## 2. 왜 필요한가? (Why)

- 코드 변경 사항 추적
- 협업 용이성 증대
- 이전 버전 복구
- 브랜치 관리

## 3. 핵심 개념 (What)

- 저장소 (Repository): 코드와 변경 이력을 저장하는 공간
- 커밋 (Commit): 변경 사항을 저장소에 기록하는 작업
- 푸시 (Push): 로컬 저장소의 변경 사항을 원격 저장소에 업로드
- 풀 (Pull): 원격 저장소의 변경 사항을 로컬 저장소에 다운로드
- 브랜치 (Branch): 독립적인 개발 라인

## 4. 동작 과정 (How)

1. `git init`: 로컬 저장소 초기화
2. `git config`: Git 설정
3. `git status`: 저장소 상태 확인
4. `git add`: 변경 사항을 스테이징 영역에 추가
5. `git commit`: 스테이징 영역의 변경 사항을 저장소에 기록
6. `git remote add`: 원격 저장소 연결
7. `git branch`: 브랜치 생성 및 관리
8. `git push`: 로컬 저장소의 변경 사항을 원격 저장소에 업로드
9. `git pull`: 원격 저장소의 변경 사항을 로컬 저장소에 다운로드

## 5. 장단점 / 트레이드오프

- 장점:
    - 코드 변경 사항 추적 용이
    - 협업 용이성 증대
    - 이전 버전 복구 가능
- 단점:
    - 학습 곡선 존재
    - 복잡한 워크플로우

## 6. 자주 나오는 질문 / 오해

- Q: Git은 왜 무료인가?
- A: 오픈 소스 프로젝트이며, GitHub 등의 플랫폼은 Git을 기반으로 수익을 창출

## 7. 프로젝트에서 어디에 쓰일 수 있는가

- 모든 소프트웨어 개발 프로젝트
- 코드 관리 및 협업
