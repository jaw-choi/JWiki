# 언리얼 네트워크 요약 정리

## 1. 서버-클라이언트 구조의 핵심

언리얼 멀티플레이에서는 **서버가 진짜 세계**입니다.

클라이언트는 서버가 보내준 데이터를 기반으로 화면에서 시뮬레이션하는 구조입니다.

즉,

**서버 = 권한이 있는 실제 게임 세계**  
**클라이언트 = 서버 데이터를 받아 보여주는 복제 세계**

라고 이해하면 됩니다.

클라이언트끼리는 직접 통신하지 않습니다.  
클라이언트 A가 클라이언트 B에게 무언가를 전달하려면 반드시 서버를 거쳐야 합니다.

```
클라이언트 A → 서버 → 클라이언트 B
```

---

## 2. Authority 개념

언리얼 네트워크에서 **Authority**는 “이 액터에 대한 진짜 권한을 누가 가지고 있느냐”를 의미합니다.

대부분의 멀티플레이 상황에서는 서버가 Authority를 가집니다.

```
HasAuthority()
```

이 함수로 현재 액터가 서버 권한을 가지고 있는지 확인할 수 있습니다.

정리하면:

|구분|의미|
|---|---|
|Authority|서버 권한, 진짜 액터|
|Proxy|클라이언트에 복제된 가짜 액터|
|Server|게임 로직의 기준|
|Client|입력과 시각적 표현 중심|

---

## 3. RPC와 Replication

언리얼에서 네트워크 통신은 크게 두 가지 방식으로 이루어집니다.

## Replication

**서버의 값을 클라이언트에 복제하는 방식**입니다.

예를 들어 서버에서 캐릭터 위치, 체력, 상태 값이 바뀌면 그 값이 클라이언트에 전달됩니다.

Replication은 지속적으로 상태를 맞추는 데 적합합니다.

```
서버의 변수 값 변경 → 클라이언트로 복제
```

---

## RPC

RPC는 함수를 네트워크를 통해 호출하는 방식입니다.

클라이언트가 서버에게 요청할 때 주로 사용합니다.

예를 들어 클라이언트가 공격 버튼을 눌렀다면,

```
클라이언트 입력 발생→ Server RPC 호출→ 서버에서 공격 처리→ 결과를 클라이언트에 복제
```

이 흐름이 됩니다.

단, RPC는 모든 값을 계속 전달하는 용도로 쓰기보다는 **즉각적인 이벤트 처리**에 적합합니다.

---

## 4. PlayerController, Pawn, Ownership

멀티플레이에서 중요한 개념은 **소유권 Ownership**입니다.

플레이어가 게임에 접속하면 서버는 해당 플레이어를 대표하는 **PlayerController**를 생성합니다.

그 PlayerController가 Pawn 또는 Character를 Possess하면, 그 캐릭터는 해당 플레이어가 조종하는 캐릭터가 됩니다.

```
Connection→ PlayerController→ Pawn / Character→ Weapon 또는 소유 액터
```

이렇게 소유권이 이어집니다.

중요한 점은, 클라이언트가 서버 RPC를 호출하려면 해당 액터가 클라이언트와 연결된 소유권 체인 안에 있어야 합니다.

예를 들어:

```
PlayerController가 Character를 소유Character가 Weapon을 소유
```

이 구조라면 Weapon도 PlayerController의 연결 정보를 따라 RPC 통신이 가능해질 수 있습니다.

---

## 5. Connection 개념

언리얼 네트워크에서 **Connection**은 서버와 클라이언트 사이의 연결 정보를 의미합니다.

클라이언트 입장에서는 서버와 연결되는 하나의 Server Connection이 있습니다.

서버 입장에서는 여러 클라이언트를 관리해야 하므로 Client Connection 배열을 가집니다.

```
클라이언트:Server Connection 1개서버:Client Connection 여러 개
```

---

## 6. NetDriver, Connection, Channel

언리얼 내부 네트워크 구조는 대략 이렇게 이해하면 됩니다.

```
NetDriver→ Connection→ Channel
```

## NetDriver

여러 네트워크 연결을 관리하는 주체입니다.

게임에서는 주로 **GameNetDriver**가 사용됩니다.

## Connection

서버와 클라이언트 간의 연결 정보입니다.

## Channel

실제 데이터를 주고받는 통로입니다.

대표적인 채널은 다음과 같습니다.

|채널|역할|
|---|---|
|Control Channel|접속, 로그인, 맵 이동 등 제어 메시지|
|Actor Channel|액터 Replication 처리|
|Voice Channel|음성 채팅 데이터 처리|

액터가 Replication 대상이 되면 해당 액터마다 Actor Channel이 생성되어 데이터를 주고받습니다.

---

## 7. Role 개념

언리얼 액터에는 역할 Role 개념이 있습니다.

크게 보면 다음과 같습니다.

|Role|의미|
|---|---|
|Authority|서버에 있는 진짜 액터|
|Autonomous Proxy|내가 조종하는 클라이언트의 복제 액터|
|Simulated Proxy|다른 플레이어를 보여주는 복제 액터|

예를 들어 내 캐릭터는 내 클라이언트에서 **Autonomous Proxy**입니다.  
입력 처리를 할 수 있기 때문입니다.

반면 다른 플레이어 캐릭터는 내 클라이언트에서 **Simulated Proxy**입니다.  
내가 직접 조종하지 않고 서버에서 받은 데이터만 보고 시뮬레이션합니다.

---

## 8. Local Role과 Remote Role

언리얼에서는 액터가 자기 기준에서 보는 역할과 상대 기준에서 보는 역할을 구분합니다.

|개념|의미|
|---|---|
|Local Role|현재 실행 중인 쪽에서의 내 역할|
|Remote Role|반대편에서 바라보는 역할|

서버 기준과 클라이언트 기준에 따라 값이 달라질 수 있으므로, 네트워크 로직을 작성할 때는 지금 코드가 **서버에서 실행 중인지, 클라이언트에서 실행 중인지**를 구분해야 합니다.

---

## 9. 클라이언트 접속 후 게임 시작 흐름

클라이언트가 서버에 접속하면 바로 게임 플레이가 시작되는 것이 아니라, 내부적으로 여러 준비 과정이 진행됩니다.

흐름은 대략 다음과 같습니다.

```
클라이언트가 서버 URL로 접속→ 서버와 Connection 생성→ 서버가 접속 허용→ 클라이언트에게 맵 로드 지시→ 클라이언트가 같은 맵을 로컬에서 로드→ 서버가 PlayerController 생성→ Login / PostLogin 처리→ Pawn 또는 Character Possess→ 게임 시작 준비 완료
```

여기서 중요한 점은 서버가 맵 데이터를 통째로 클라이언트에게 보내는 것이 아니라, **클라이언트에게 어떤 맵을 로드하라고 알려준다**는 것입니다.

클라이언트는 이미 가지고 있는 맵 파일을 로컬에서 로드합니다.

---

## 10. Listen Server 개념

Listen Server는 서버이면서 동시에 플레이어 역할도 하는 구조입니다.

즉, 한 사람이 방장이 되어 서버를 열고, 그 사람도 게임에 참여하는 방식입니다.

```
Listen Server = 서버 역할 + 클라이언트 플레이어 역할
```

반대로 Dedicated Server는 플레이어로 참여하지 않고 서버 역할만 수행합니다.

# 핵심만 다시 정리

## 가장 중요한 흐름

```
서버가 진짜다.클라이언트는 가짜 복제본이다.클라이언트 입력은 Server RPC로 서버에 보낸다.서버가 처리한 결과는 Replication으로 클라이언트에 전달된다.
```

## Ownership 흐름

```
Connection→ PlayerController→ Character / Pawn→ Weapon / Owned Actor
```

## 네트워크 내부 구조

```
NetDriver→ Connection→ Channel→ Actor Replication / RPC / Control Message
```

## Role 구분

```
Authority = 서버의 진짜 액터Autonomous Proxy = 내가 조종하는 클라이언트 액터Simulated Proxy = 남의 캐릭터를 보여주는 액터
```

# 한 줄 결론

언리얼 멀티플레이는 **서버가 모든 진짜 게임 상태를 관리하고, 클라이언트는 입력을 서버에 보내며, 서버 결과를 Replication으로 받아 화면에 재현하는 구조**입니다.
