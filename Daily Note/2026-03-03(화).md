## 1) 쿼드트리 핵심 한 줄

**2D 공간을 4등분하면서 “안 봐도 되는 애들”을 먼저 걸러서(필터링) 연산을 줄이는 구조.**

---

## 2) 언제 이득이 커지나 (성공 조건)

쿼드트리는 “전수검사(모두 vs 모두)”가 비싸질 때 빛남.

- **오브젝트가 넓게 퍼져있다** → 각 노드에 적당히 분산됨 → 후보군이 확 줄어듦
    
- **충돌/탐색/렌더 호출이 많다** → “안 할 연산”을 많이 만들 수 있음
    
- **카메라/영역 기반 쿼리**가 자주 발생한다 (근처 적 찾기, 화면 안만 렌더링 등)
    

---

## 3) 언제 망하나 (실패 조건)

이 경우엔 “나눴는데도 결국 다 봄”이 되어버려서 손해가 날 수 있음.

- **한 곳에 오밀조밀 몰림(불균형)**
    
    - 나머지 영역은 비어 있고 한 노드만 계속 터짐 → 필터링 의미 감소
        
- **트리 깊이(Depth)가 너무 깊어짐**
    
    - 노드 수 폭증 → 메모리/포인터 관리/재귀 비용 증가
        
- **삽입/삭제가 너무 빈번**하고 객체가 자주 이동
    
    - 매 프레임 재배치하면 “최적화하려다 최적화 비용이 더 큼”
        

결론: **“분산 + 쿼리 많음”이면 강추, “몰림 + 이동 많음”이면 신중.**

## 5) 단점 요약

## 6) 구현에서 제일 중요한 설계 기준 3개

### (1) 분할 기준(언제 Divide?)

보통 둘 중 하나(혹은 둘 다)로 간다:

- **노드 안의 포인트 수가 capacity 초과하면 분할**
    
- **maxDepth 미만이고, 객체가 사분면에 ‘깔끔히’ 들어갈 때(경계 부분과 겹치지 않고 완전히 포함되는 경우)만 분할**
    

### (2) 객체가 “경계를 걸치면” 어디에 넣을지

우리 수업에서는 아래처럼 열거형을 두고 여러개 걸치면 Straddling 반환함
또, 나머지 각 상황에 맞는 index 값을 반환함.
```c++
// 영역 구분을 위한 열거형.
enum class NodeIndex
{
    // 완전히 포함되는 4가지.
    TopLeft,
    TopRight,
    BottomLeft,
    BottomRight,
    // 경계선에 걸침.
    Straddling,
    // 영역을 벗어난 경우.
    OutOfArea
};
```

## 7) Insert 흐름(정리한 로직의 골자)

1. 들어온 바운즈가 **현재 노드 영역과 겹치는지** 확인
    
2. 겹치면 `GetQuads()`로 **어느 사분면에 해당하는지 목록** 얻음
    
3. 결과가
    
    - **여러 개면(걸침)** → 현재 노드 points에 저장
        
    - **정확히 1개면** → 필요 시 divide 후 해당 자식으로 내려보냄
        
    - **없으면(out of area)** → 삽입 실패/무시(정책)
        

---

## 8) Query 흐름(후보군 반환)

1. 현재 노드 points를 결과 리스트에 합침
    
2. 분할 안 됐으면 끝
    
3. 분할 됐으면, `GetQuads()`로 겹치는 자식들만 골라서
    
4. 그 자식들에게 재귀 Query
