## 1) 힙(Heap) 핵심 요약

### 힙의 목적

- **정렬 자체가 목적이 아님**
    
- 딱 하나를 빠르게 보장:
    
    - **최대 힙(Max-Heap)**: `루트(0번)`가 **가장 큰 값**
        
    - **최소 힙(Min-Heap)**: `루트(0번)`가 **가장 작은 값**
        
- 나머지 노드들의 “정렬된 순서”는 중요하지 않음  
    → 대신 **부모-자식 관계 조건**은 반드시 유지해야 함.
    

### 힙의 조건(정의가 진짜 핵심)

- 최대 힙: **부모 ≥ 자식**
    
- 최소 힙: **부모 ≤ 자식**
    
- 그래서 “루트만 최대/최소면 끝”이 아니라,  
    **이 조건이 깨지면 다음 루트 추출 때 최대/최소 보장이 무너져서** 아래까지 고쳐야 함.
    

---

## 2) 힙을 배열로 표현하는 규칙

힙은 트리를 직접 연결리스트처럼 구현하지 않고, **배열**로 구현함.

- 루트: `0번`
    
- 어떤 노드가 `i`에 있을 때
    
    - 왼쪽 자식: `2*i + 1`
        
    - 오른쪽 자식: `2*i + 2`
        
    - 부모: `(i - 1) / 2` (정수 나눗셈)
        

그리고 힙은 **완전 이진 트리**라서:

- **왼쪽 자식이 없으면 오른쪽 자식도 없음**
    
- 다만 “완전 이진 트리”는 “마지막 레벨이 꽉 찬다”가 아니라  
    **마지막 레벨은 왼쪽부터 채운다**라서
    
    - 어떤 노드는 **왼쪽만 있고 오른쪽이 없을 수 있음**(이론적으로 가능)
        
    - 그래서 실제 구현은 보통 `left < length`, `right < length` 둘 다 체크함

## 3) Heapify(힙 구성)와 Heap Sort(힙 정렬) 흐름

### (1) Heapify(힙 성질 맞추기)

- 어떤 인덱스 `i`를 기준으로
    
    - 자식들과 비교해서 “최대/최소가 되어야 할 자리”로 내려보내며 정리
        
- 핵심: `i`가 바뀌면 그 내려간 위치에서 **반복**(while/재귀)
    

### (2) Heap Sort 절차

1. **배열 전체를 힙으로 만든다**(최대 힙이면 루트가 최댓값)
    
2. 루트(최댓값) ↔ 배열의 마지막 원소 교환
    
3. “정렬 완료 영역”을 하나 늘리고(마지막은 확정)
    
4. 줄어든 길이에 대해 다시 heapify(루트부터)
    
5. 끝까지 반복
    

### 복잡도/특징

- 시간: **O(n log n)**
    
- 추가 메모리: **거의 없음(O(1))** ← 배열 안에서 처리
    
- 구현 난이도는 heapify 때문에 체감상 높은 편

## 4) A\*에서 힙이 유용한 이유

A\*은 “다음에 갈 후보들 중에서 비용이 가장 작은 것”을 반복해서 선택함.

- 후보들을 매번 전부 탐색해서 최소 비용 찾으면 느림
    
- **최소 힙(min-heap)**에 후보 비용을 넣어두면
    
    - 루트에서 **항상 최소 비용 후보를 O(1)에 확인**
        
    - 꺼내고(push/pop) 유지 비용이 **O(log n)**
        

즉 A*의 “가장 싼 후보를 계속 뽑는 구조”랑 **힙이 구조적으로 딱 맞음**.

## 5) DFS/BFS 복습 포인트(짧게)

- DFS: 스택(또는 재귀) 기반, 깊게 파고듦
    
    - 단점: 깊으면 스택오버플로우/무한루프 위험
        
- BFS: 큐 기반, 가까운 곳부터 넓게
    
    - 보통 최단거리(간선 가중치 동일)에서 강함

## 6) 레드블랙 트리 요약

### 왜 필요한가

- BST는 삽입 순서에 따라 **한쪽으로 쏠리면 링크드리스트처럼 되어** 성능이 망가짐
    
- 레드블랙트리는 **자가 균형 BST**라서 높이를 제한해줌(검색 성능 유지)
    

### 5가지 규칙(핵심만)

1. 노드는 빨강/검정
    
2. 루트는 검정
    
3. 모든 NIL(리프 대체 노드)은 검정
    
4. 빨강 노드의 자식은 반드시 검정 (빨강-빨강 금지)
    
5. 어떤 노드에서든 NIL까지 가는 모든 경로의 **검정 노드 수가 동일**
    

### 회전(Rotation)

- 균형 맞추려면 “부모-자식 위치 교환”이 필요
    
- 좌회전/우회전으로 구조를 바꾸며 규칙을 만족시킴
    

### 삽입/삭제 난이도

- 삽입: 주로 “빨강-빨강 위반” 해결이 핵심(케이스 1/2/3)
    
- 삭제: **더블 블랙** 같은 케이스 때문에 훨씬 어렵고 분기 많음  
    → 실전 구현도 어려워서 보통 면접은 “규칙/개념” 위주로 묻는 편
