### 면접 준비

## 메모


#### 오전 

BST 구현
1. 이진 트리 / 이진 탐색 트리 차이    

- 이진 트리: 자식이 최대 2개
    
- 이진 탐색 트리 BST: 추가로 정렬 규칙이 있음
    
    - 왼쪽은 부모보다 작은 값
        
    - 오른쪽은 부모보다 큰 값
        

2. BST를 쓰는 이유
    

- 탐색할 때 전체를 다 보지 않고 비교하면서 왼쪽/오른쪽으로 내려감
    
- 그래서 검색 효율이 좋음
    

3. BST 구현 핵심 기능, 삽입 규칙, 삭제 시 주의 할점
4. 삭제 시 대체 노드 찾은 후 삭제할 것
	1. 대체 노드 찾는 법
		1. 왼쪽트리의 가장 큰 값의 노드
		2. 오른쪽트리의 가장 작은 값의 노드
		3. ==위 노드로 대체 할 시 BST 유지되기 때문에 위 노드랑 교체하는 거임==

- BST는 작은 값 왼쪽, 큰 값 오른쪽 규칙으로 저장해서 검색/삽입/삭제를 빠르게 처리하는 트리 구조입니다.

#### 오후

BST 파괴함수 구현
- 메모리 릭 추적  
    디버그 모드에서 누수 리포트가 파일명과 라인 번호를 찍어줘서 어디서 new 했는지 찾는다. 해제는 시스템이 안 해주니, 소멸자나 Destroy 같은 정리 지점을 설계해서 직접 넣고 재실행으로 0 릭 확인한다. 디버그 전용 코드로 #ifdef로 감싸고 릴리즈에서는 비활성화한다. -> ==Google에 MSDN 치면 됨==
    
- BST 순회 핵심  
    전위: ==부모==→왼쪽→오른쪽  
    중위: 왼쪽→==부모==→오른쪽 이게 BST에서는 정렬된 순서로 나온다  
    후위: 왼쪽→오른쪽→==부모==  
    재귀는 node가 null이면 즉시 return이 종료 조건.
    
- STL 컨테이너 선택 기준  
    unordered_map 정렬 없음 해시 기반 빠른 탐색 목적  
    map 키 정렬됨 보통 레드블랙 트리 같은 균형 BST 기반
    
- 성능 분석 핵심  
    빅오는 정확 측정이 아니라 성장률 추정. 상수/계수/낮은 차수는 버리고 최고차항만 본다. 실제 최적화는 반드시 측정으로 판단.
